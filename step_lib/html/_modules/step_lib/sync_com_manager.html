   1"""Synchronous MQTT Communication Manager Module.
   2
   3This module provides a thread-safe interface for MQTT communication with automatic reconnection
   4and message queueing capabilities. It wraps asynchronous MQTT operations in a synchronous
   5interface making it easier to use in traditional threaded applications: subscribing and
   6receiving run on a background thread's asyncio loop, while publishing is handed off to a
   7pool of publish worker processes (PublishWorkerPool).
   8
   9Key Features:
  10
  11    - Thread-safe MQTT operations
  12    - Automatic reconnection handling
  13    - A desired-state subscription, kept on the broker by the background loop
  14      (re-applied after every reconnect), and a queue of received messages (to
  15      the caller)
  16    - Support for QoS levels
  17    - Configurable connection parameters
  18    - Context manager support
  19    - Proper cleanup of resources
  20
  21Example:
  22    >>> with SyncComManager(params, logger=logger) as manager:  # doctest: +SKIP
  23    ...     manager.subscribe(["topic1"], MqttQoS.QOS_1)
  24    ...     manager.publish_its_message(
  25    ...         message=some_message,
  26    ...         address=address,
  27    ...         current_position=current_position,
  28    ...         is_station_mobile=True,
  29    ...     )
  30    ...     received = manager.get_its_message_received()
  31
  32Complexity:
  33    - Time: O(1) for construction; O(w), where w is publish_worker_count,
  34      for start/stop (spawning/tearing down the publish worker pool); O(k)
  35      for subscribe and for each subscription reconciliation, where k is the
  36      number of requested topics; O(n) for publish_its_message and per
  37      message processed by the background thread's internal coroutines
  38      (_message_receive_thread), where n is the number of fields in the
  39      facility message being sent or received.
  40    - Space: O(1) for construction; O(w) for start/stop, for the publish
  41      worker pool's per-worker bookkeeping; O(k) for subscribe; O(n) for
  42      publish_its_message and per message processed by the background
  43      thread's coroutines, mirroring the time complexity.
  44
  45Classes:
  46    - ConnectionStatus: Enumeration of the manager's connection states.
  47      Complexity: time O(1), space O(1).
  48    - _SystemStatus: Internal start()/stop() lifecycle states of

  51      QoS) kept as the desired and applied subscription state. Complexity: time
  52      O(k), space O(k), where k is the number of topics.

  54      and PublishWorkerPool for MQTT publish/subscribe. Complexity: time
  55      O(w) for start/stop (w = publish_worker_count) or O(n) for

 189class SyncComManager:
 190    """Synchronous Communication Manager for MQTT messaging.
 191
 192    This class provides a thread-safe interface for MQTT communication,
 193    managing operations through queues, a background asyncio thread
 194    (subscribe/receive), a health-check thread, and a publish worker process
 195    pool (publish).
 196
 197    The manager handles:
 198
 199        - MQTT message publishing and subscribing
 200        - Automatic reconnection on connection loss
 201        - Thread-safe message queuing
 202        - Exception handling and logging
 203
 204    The manager can be started and stopped repeatedly: every ``start()``
 205    builds fresh background and health-check threads (see
 206    ``_create_runtime()``), and every event loop the background thread runs
 207    gets its own incoming command queue.
 208
 209    Note:
 210        A single internal ``_cond`` (``Condition`` wrapping an ``RLock``) guards the connection
 211        status, the transitions of the background event loop/thread state
 212        (``_async_loop``), and the ``start()``/``stop()`` lifecycle state
 213        (``_system_status``) used by the subscribe/receive path.
 214
 215        ``_system_status`` is a 4-state lifecycle (``STOPPED`` ->
 216        ``STARTING`` -> ``STARTED`` -> ``STOPPING`` -> ``STOPPED``) written
 217        only through ``_set_status()`` with ``_cond`` held. ``STARTED`` and
 218        ``STOPPED`` are the stable states; ``STARTING`` and ``STOPPING`` are
 219        transitional, entered by exactly one thread (the one executing
 220        ``start()``/``stop()``) while every other caller waits in
 221        ``_wait_settled()``. ``start()`` and ``stop()`` are symmetric and
 222        idempotent: after the wait they return if the manager is already in
 223        the requested state, otherwise they claim the transitional state
 224        atomically with that check and do the slow work with no lock held.
 225        The actual teardown lives in the internal, unguarded ``_stop()``,
 226        called both by the public ``stop()`` and by ``start()``'s own
 227        failure-unwind path; it always leaves ``_system_status == STOPPED``
 228        and calls ``notify_all()`` before returning or raising - including
 229        when the background thread dies before ever publishing
 230        ``_async_loop``. An error raised while starting reaches only the
 231        thread that executed that ``start()``; waiting callers see
 232        ``STOPPED`` and retry on their own.
 233
 234        Every write of ``_async_loop`` (and of the ``_incoming_queue`` and
 235        ``_subscription_wakeup`` published together with it) goes through
 236        ``_set_async_loop()``, and every read happens under ``_cond``
 237        (``_is_async_loop_ready()``, ``_stop()``, ``subscribe()``), so no
 238        method can accidentally read or write it outside ``_cond``. It does
 239        not serialize the blocking calls made through a captured loop
 240        reference (those stay outside the lock so I/O is not serialized).
 241        The desired subscription (``_desired_subscription``) is also
 242        guarded by ``_cond``: ``subscribe()`` writes it and the background
 243        loop's reconciler reads it. ``publish_its_message()`` and
 244        ``check_health()`` do not use ``_cond`` at all: they send
 245        directly to the publish worker pool (``_worker_pool``), which is
 246        safe to call concurrently from multiple threads because it
 247        serializes access to its own state internally.
 248
 249    Attributes:
 250        its_messages_received (Generator[FacilityMessage]): Property yielding every
 251            message currently available in the receive queue.
 252        is_running (bool): Property returning whether the manager is running (from
 253            start() until stop() begins), unaffected by MQTT reconnections.
 254        connection_status (ConnectionStatus): Property returning the current MQTT
 255            connection status.
 256
 257    The class can be used either with context manager (recommended) or manual start/stop:
 258
 259    Example:
 260        >>> with SyncComManager(params, logger=logger) as manager:  # doctest: +SKIP
 261        ...     manager.subscribe(["topic1", "topic2"], MqttQoS.QOS_1)
 262        ...     manager.publish_its_message(
 263        ...         message=message,
 264        ...         address=address,
 265        ...         current_position=current_position,
 266        ...         is_station_mobile=True,
 267        ...     )
 268
 269    Or manually:
 270
 271    Example:
 272        >>> manager = SyncComManager(params, logger=logger)  # doctest: +SKIP
 273        >>> manager.start()  # doctest: +SKIP
 274        >>> manager.subscribe(["topic1"], MqttQoS.QOS_0)  # doctest: +SKIP
 275        >>> manager.stop()  # doctest: +SKIP
 276
 277    Complexity:
 278        - Time: O(1) for construction; O(k) for subscribe (k topics); O(w), where w is
 279          publish_worker_count, for start/stop; O(n) for publish_its_message and
 280          the background thread's message handling, where n is the number of
 281          fields in the facility message being sent or received.
 282        - Space: O(1) for the manager's own queues and state (bounded by the
 283          configured queue capacities); O(w) for the publish worker pool's
 284          per-worker bookkeeping; O(n) per message held in a queue or published.
 285    """

 510    def _settle_budget(self) -> float:
 511        """How long a caller waits for a transitional status to settle.
 512
 513        The caller cannot know whether the transition in progress is a start or
 514        a stop (or one right after the other), so it waits for both worst cases
 515        back to back: the publish worker pool's own start and close budgets (each
 516        already including the pool's TIMEOUT_MARGIN), plus the four
 517        ``params.timeout``-bounded waits of stop(), each with its
 518        ENQUEUE_RESULT_MARGIN.
 519
 520        Returns:
 521            float: The worst-case duration, in seconds, of a start or a stop.
 522
 523        Complexity:
 524            - Time: O(1), a fixed arithmetic expression.
 525            - Space: O(1), no additional storage is required.
 526        """
 527        return (
 528            self._worker_pool.start_budget()
 529            + self._worker_pool.close_budget()
 530            + 4 * (self._params.timeout + self.ENQUEUE_RESULT_MARGIN)
 531        )

 652    async def _apply_subscription(
 653        self, client: AsyncComManager, desired: _Subscription
 654    ) -> None:
 655        """Replace the subscription applied on the broker with the desired one.
 656
 657        Unsubscribes the topics of the applied subscription (if any), then
 658        subscribes to the desired topics, logging every SUBACK result with
 659        ``_log_suback_result``.
 660
 661        Args:
 662            client (AsyncComManager): The connected MQTT client.
 663            desired (_Subscription): The subscription to apply.
 664
 665        Returns:
 666            None: The broker subscription and ``_applied_subscription`` are updated
 667            as a side effect.
 668
 669        Note:
 670            - ``_applied_subscription`` is set to ``desired`` even when the
 671              connection fails meanwhile: an ``MqttError`` (including
 672              ``MqttCodeError``) is not caught, since it may be transient (e.g.
 673              MQTT_ERR_NO_CONN, a timeout), so it propagates to trigger the
 674              reconnect, whose first reconciler pass unsubscribes and subscribes
 675              it again.
 676            - A ``ValueError`` from ``client.subscribe`` (invalid topic filter or
 677              options, rejected by paho's validation) is permanent: it is logged
 678              at ERROR, the request is recorded as ``_rejected_subscription`` (so
 679              it is not retried until a different one is requested), and nothing
 680              is left applied.
 681            - Subscription options are set to:
 682
 683                - noLocal=False (required by shared subscriptions, ``$share/...``;
 684                  echo filtering relies on station_id instead)
 685                - retainAsPublished=False
 686                - retainHandling=RETAIN_DO_NOT_SEND
 687
 688        Complexity:
 689            - Time: O(k), where k is the number of applied plus desired topics, to
 690              unsubscribe and subscribe them and log each result.
 691            - Space: O(k), for the subscription option tuples and results built
 692              during the call.
 693        """
 694        applied = self._applied_subscription
 695        self._applied_subscription = None
 696        rejected = False
 697        try:
 698            if self._logger.isEnabledFor(level=logging.DEBUG):
 699                self._logger.debug(msg=f"Applying subscription {desired}")
 700            if applied is not None and len(applied.topics) > 0:
 701                await client.unsubscribe(topic=list(applied.topics))
 702                if self._logger.isEnabledFor(level=logging.INFO):
 703                    for topic in applied.topics:
 704                        self._logger.info(msg=f"Unsubscribed to {topic}")
 705            if len(desired.topics) > 0:
 706                try:
 707                    sub_results: Sequence[int | ReasonCode] = await client.subscribe(
 708                        topic=[
 709                            (
 710                                topic,
 711                                SubscribeOptions(
 712                                    qos=desired.max_qos,
 713                                    # Always False: required by shared subscriptions
 714                                    # ($share/...); echo filtering relies on station_id
 715                                    noLocal=False,
 716                                    retainAsPublished=False,
 717                                    retainHandling=SubscribeOptions.RETAIN_DO_NOT_SEND,
 718                                ),
 719                            )
 720                            for topic in desired.topics
 721                        ]
 722                    )
 723                except ValueError:
 724                    # Permanent error (rejected by paho's validation): the same
 725                    # request would fail again after every reconnect, so it is
 726                    # not retried until a different one is requested, and the
 727                    # connection is kept
 728                    rejected = True
 729                    self._rejected_subscription = desired
 730                    if self._logger.isEnabledFor(level=logging.ERROR):
 731                        self._logger.exception(
 732                            msg=f"Invalid subscription dropped: {list(desired.topics)}"
 733                        )
 734                    return
 735                for topic, result in zip(desired.topics, sub_results, strict=True):
 736                    self._log_suback_result(
 737                        topic=topic, result=result, max_qos=desired.max_qos
 738                    )
 739        finally:
 740            if not rejected:
 741                self._applied_subscription = desired

 743    async def _subscription_reconciler(
 744        self, client: AsyncComManager, wakeup: AsyncioEvent
 745    ) -> None:
 746        """Keep the broker subscription equal to the desired one.
 747
 748        Runs as a task for the lifetime of one MQTT connection. The first pass
 749        applies the desired subscription even if it equals the applied one, since
 750        a new connection may have lost it (or, with a persistent session, still
 751        hold the previously applied topics, which are unsubscribed first); later
 752        passes run when ``subscribe()`` signals a change through ``wakeup`` and
 753        apply the desired subscription only if it differs from the applied one.
 754        A desired subscription equal to the last rejected one is not retried.
 755
 756        The event is cleared before the desired subscription is read: a request
 757        written during a pass (its ``wakeup.set()`` runs on this loop after the
 758        write) leaves the event set, so the next wait returns at once and the new
 759        request is applied by another pass.
 760
 761        Args:
 762            client (AsyncComManager): The connected MQTT client.
 763            wakeup (AsyncioEvent): The event ``subscribe()`` sets, through
 764                ``call_soon_threadsafe``, after recording a new desired
 765                subscription.
 766
 767        Returns:
 768            None: The coroutine runs until cancelled (by ``_exit_threads()`` or
 769            the connection's task group).
 770
 771        Complexity:
 772            - Time: O(k) per pass, where k is the number of topics, to compare and
 773              apply the subscription; the coroutine runs until cancelled.
 774            - Space: O(k), for the subscription being applied.
 775        """
 776        new_connection = True
 777        while True:
 778            wakeup.clear()
 779            with self._cond:
 780                desired = self._desired_subscription
 781            if (
 782                desired is not None
 783                and desired != self._rejected_subscription
 784                and (new_connection or desired != self._applied_subscription)
 785            ):
 786                await self._apply_subscription(client=client, desired=desired)
 787            new_connection = False
 788            await wakeup.wait()

 790    def _log_suback_result(
 791        self, topic: str, result: int | ReasonCode, max_qos: MqttQoS
 792    ) -> None:
 793        """Log one SUBACK result: granted, granted with a lower QoS, or refused.
 794
 795        Args:
 796            topic (str): The subscribed topic filter.
 797            result (int | ReasonCode): The SUBACK reason code, one element of what
 798                ``aiomqtt.Client.subscribe`` returns (``tuple[int, ...]`` with MQTT
 799                v3.1.1, ``list[ReasonCode]`` with MQTT v5).
 800            max_qos (MqttQoS): The QoS requested for the subscription.
 801
 802        Returns:
 803            None: The result is logged as a side effect: INFO when the requested
 804            QoS was granted, WARNING when a lower QoS was granted, ERROR (with the
 805            reason name) when the subscription was refused (code >= 0x80).
 806
 807        Complexity:
 808            - Time: O(1), a fixed number of comparisons and one log call.
 809            - Space: O(1), no additional storage is required.
 810        """
 811        code = result.value if isinstance(result, ReasonCode) else int(result)
 812        if code == max_qos:
 813            if self._logger.isEnabledFor(level=logging.INFO):
 814                self._logger.info(msg=f"Subscribed to {topic}: QoS {code}")
 815        elif code < self.SUBACK_FAILURE_MIN:
 816            if self._logger.isEnabledFor(level=logging.WARNING):
 817                self._logger.warning(
 818                    msg=f"Subscribed to {topic} with granted QoS {code} "
 819                    f"lower than requested {int(max_qos)}"
 820                )
 821        elif self._logger.isEnabledFor(level=logging.ERROR):
 822            reason = getattr(result, "getName", lambda: hex(code))()
 823            self._logger.error(
 824                msg=f"Subscription to {topic} refused: {reason} ({code:#04x})"
 825            )

 827    async def _incoming_command_thread(
 828        self, incoming_queue: AsyncioQueue[Command]
 829    ) -> None:
 830        """Handle commands drained from the incoming queue.
 831
 832        This coroutine (run as a task on the background thread's event loop)
 833        continuously monitors the incoming queue and handles the exit command
 834        enqueued by ``stop()``. Neither publishing (``publish_its_message`` sends
 835        directly to the publish worker pool) nor subscribing (kept on the broker by
 836        ``_subscription_reconciler``) runs through this queue.
 837
 838        Args:
 839            incoming_queue (AsyncioQueue[SyncComManager.Command]): The command queue of the
 840                event loop this coroutine runs on.
 841
 842        Returns:
 843            None: The method runs until an ExitThreadsCommand is received.
 844
 845        Note:
 846            The thread runs continuously until an ExitThreadsCommand is received,
 847            which cancels the other connection tasks; any other command is logged at
 848            WARNING and ignored.
 849
 850        Complexity:
 851            - Time: O(1) per dispatch step (queue get and match); the loop itself runs
 852              until an ExitThreadsCommand is received.
 853            - Space: O(1), no additional storage is required.
 854        """
 855        loop_continue = True
 856        while loop_continue:
 857            # Wait for a message
 858            msg = await incoming_queue.get()
 859            # Process the message
 860            try:
 861                match msg:
 862                    case SyncComManager.ExitThreadsCommand():
 863                        await self._exit_threads()
 864                        loop_continue = False
 865                    case _:
 866                        if self._logger.isEnabledFor(level=logging.WARNING):
 867                            self._logger.warning(
 868                                msg=f"Invalid message type: {type(msg)}"
 869                            )
 870            finally:
 871                incoming_queue.task_done()

 873    async def _async_wait_while_enabled(self, delay: float) -> None:
 874        """Sleep on the event loop for up to ``delay`` seconds, returning early once
 875        the manager is told to stop.
 876
 877        Polls ``_is_thread_enabled()`` every ``STOP_POLL_INTERVAL`` seconds, so a
 878        reconnect wait never delays ``stop()`` by more than that.
 879
 880        Args:
 881            delay (float): The longest time to wait, in seconds.
 882
 883        Returns:
 884            None: Returns after ``delay`` seconds, or within ``STOP_POLL_INTERVAL``
 885            of a ``stop()``.
 886
 887        Complexity:
 888            - Time: O(delay / STOP_POLL_INTERVAL) polls in the worst case.
 889            - Space: O(1), no additional storage is required.
 890        """
 891        deadline = monotonic() + delay
 892        while self._is_thread_enabled():
 893            remaining = deadline - monotonic()
 894            if remaining <= 0:
 895                return
 896            await asyncio_sleep(delay=min(remaining, self.STOP_POLL_INTERVAL))

 945    async def _connection_attempt(
 946        self, incoming_queue: AsyncioQueue[Command], subscription_wakeup: AsyncioEvent
 947    ) -> None:
 948        """Run one connect-and-serve cycle.
 949
 950        Connects to the broker, then runs the connection's tasks in a task group
 951        until the incoming-command task exits (on the ``ExitThreadsCommand`` of
 952        ``stop()``, which cancels the others): the message receive task (only if
 953        ``max_outgoing_queue_rooms > 0``), the incoming-command task and the
 954        subscription reconciler.
 955
 956        Args:
 957            incoming_queue (AsyncioQueue[SyncComManager.Command]): The command queue
 958                of the event loop this coroutine runs on.
 959            subscription_wakeup (AsyncioEvent): The reconciler's wake-up event,
 960                created for the same event loop.
 961
 962        Returns:
 963            None: Returns once the connection's tasks have all finished.
 964
 965        Raises:
 966            Exception: Any connection or task failure (e.g. an ``MqttError``),
 967                handled by ``_async_run``'s retry loop.
 968
 969        Complexity:
 970            - Time: O(1) to connect and create the (at most three) tasks; the tasks
 971              then run until the connection ends, their per-message cost being
 972              documented on _message_receive_thread/_subscription_reconciler.
 973            - Space: O(1) for the connection's own state.
 974        """
 975        async with AsyncComManager(params=self._params, logger=self._logger) as client:
 976            self._set_connection_status(status=ConnectionStatus.CONNECTED)
 977            async with AsyncioTaskGroup() as group:
 978                if self._params.max_outgoing_queue_rooms > 0:
 979                    # Create mqtt receive thread
 980                    self._async_threads.append(
 981                        group.create_task(
 982                            coro=self._message_receive_thread(client=client),
 983                            name="message_receive_thread",
 984                        )
 985                    )
 986                # Create incoming-command thread
 987                self._async_threads.append(
 988                    group.create_task(
 989                        coro=self._incoming_command_thread(
 990                            incoming_queue=incoming_queue
 991                        ),
 992                        name="incoming_command_thread",
 993                    )
 994                )
 995                # Keep the broker subscription equal to the desired one
 996                self._async_threads.append(
 997                    group.create_task(
 998                        coro=self._subscription_reconciler(
 999                            client=client, wakeup=subscription_wakeup
1000                        ),
1001                        name="subscription_reconciler",
1002                    )
1003                )

1007    ) -> bool:
1008        """Run one connection attempt, aborting it if ``stop()`` arrives before the
1009        manager is connected.
1010
1011        A connection attempt can last up to paho's 5 s socket connect timeout plus
1012        ``params.timeout`` (the CONNACK wait): while it is in flight nothing drains
1013        the incoming queue, so without an abort ``stop()`` would wait that long. The
1014        attempt runs in its own task, polled every ``STOP_POLL_INTERVAL``; once the
1015        manager is told to stop and is not connected, the attempt is cancelled.
1016        While connected, the graceful path is kept: the ``ExitThreadsCommand`` of
1017        ``stop()`` ends the attempt.
1018
1019        Args:
1020            incoming_queue (AsyncioQueue[SyncComManager.Command]): The command queue
1021                of the event loop this coroutine runs on.
1022            subscription_wakeup (AsyncioEvent): The reconciler's wake-up event.
1023
1024        Returns:
1025            bool: True if the attempt was aborted by ``stop()``, False if it ended
1026            on its own.
1027
1028        Raises:
1029            Exception: Re-raised from an attempt that failed on its own.
1030            CancelledError: If this coroutine is cancelled; the attempt is
1031                cancelled too.
1032
1033        Note:
1034            Cancelling an attempt during its TCP/TLS connect cannot stop paho's
1035            executor thread, which finishes within its 5 s socket timeout
1036            (``Runner.close()`` waits for it); cancelling it during the CONNACK
1037            wait leaves the half-open socket to the garbage collector. A DNS
1038            resolution that hangs is not bounded by paho at all.
1039
1040        Complexity:
1041            - Time: O(1) per poll; the attempt runs as documented on
1042              _connection_attempt.
1043            - Space: O(1), one task.
1044        """
1045        attempt = asyncio_create_task(
1046            coro=self._connection_attempt(
1047                incoming_queue=incoming_queue, subscription_wakeup=subscription_wakeup
1048            ),
1049            name="connection_attempt",
1050        )
1051        try:
1052            while True:
1053                done, _ = await asyncio_wait({attempt}, timeout=self.STOP_POLL_INTERVAL)
1054                if done:
1055                    attempt.result()
1056                    return False
1057                if (
1058                    not self._is_thread_enabled()
1059                    and self.connection_status is not ConnectionStatus.CONNECTED
1060                ):
1061                    attempt.cancel()
1062                    await asyncio_wait({attempt})
1063                    if not attempt.cancelled():
1064                        # It finished on its own meanwhile: retrieve its outcome
1065                        # so asyncio does not report it as never retrieved
1066                        attempt.exception()
1067                    return True
1068        except CancelledError:
1069            # External cancellation: never leave the attempt running
1070            attempt.cancel()
1071            raise

1073    async def _async_run(
1074        self, incoming_queue: AsyncioQueue[Command], subscription_wakeup: AsyncioEvent
1075    ) -> None:
1076        """Run asynchronous communication manager.
1077
1078        This method runs connection attempts (see ``_connection_attempt``) until
1079        one ends normally or the manager's lifecycle status is no longer
1080        STARTING/STARTED (see ``_is_thread_enabled()``). On an exception, it
1081        reconnects after the configured reconnect interval; both that wait and an
1082        attempt still connecting are cut short by ``stop()`` (see
1083        ``_async_wait_while_enabled`` and ``_run_abortable_attempt``).
1084
1085        Args:
1086            incoming_queue (AsyncioQueue[SyncComManager.Command]): The command queue
1087                created for the event loop this coroutine runs on, handed to every
1088                incoming-command task it starts.
1089            subscription_wakeup (AsyncioEvent): The subscription reconciler's
1090                wake-up event, created for the same event loop.
1091
1092        Note:
1093            Before returning, any commands still sitting in ``incoming_queue``
1094            (e.g. an ``ExitThreadsCommand`` enqueued by ``stop()`` while this
1095            manager was disconnected or mid-reconnect, when no
1096            ``_incoming_command_thread`` was running to drain it) are drained and
1097            marked done, so a caller blocked in ``stop()``'s
1098            ``_incoming_queue.join()`` observes a clean completion instead of a
1099            cancellation from the event loop tearing down.
1100
1101        Returns:
1102            None: The coroutine runs until the manager is disabled,
1103            reconnecting on failure as a side effect.
1104
1105        Raises:
1106            CancelledError: If the coroutine is cancelled; a cancellation is never
1107                retried as a connection failure (the command queue is still
1108                drained first).
1109
1110        Complexity:
1111            - Time: O(1) per connection attempt, plus the attempt itself (see
1112              _connection_attempt) and the bounded reconnect wait.
1113            - Space: O(1) for the manager's own state per connection attempt.
1114        """
1115        self._set_connection_status(status=ConnectionStatus.DISCONNECTED)
1116        loop_continue = True
1117        try:
1118            while loop_continue and self._is_thread_enabled():
1119                try:
1120                    aborted = await self._run_abortable_attempt(
1121                        incoming_queue=incoming_queue,
1122                        subscription_wakeup=subscription_wakeup,
1123                    )
1124                    if aborted and self._logger.isEnabledFor(level=logging.INFO):
1125                        self._logger.info(msg="Connection attempt aborted by stop()")
1126                    self._set_connection_status(status=ConnectionStatus.DISCONNECTED)
1127                    loop_continue = False
1128                except CancelledError:
1129                    # A cancellation must propagate: never retry through it
1130                    self._set_connection_status(status=ConnectionStatus.DISCONNECTED)
1131                    raise
1132                except Exception:
1133                    self._set_connection_status(status=ConnectionStatus.DISCONNECTED)
1134                    if self._logger.isEnabledFor(level=logging.ERROR):
1135                        self._logger.exception(msg="Exception happened")
1136                    if self._logger.isEnabledFor(level=logging.INFO):
1137                        self._logger.info(
1138                            msg="All threads stopped and connection dropped"
1139                        )
1140                    await self._wait_before_reconnect()
1141                finally:
1142                    self._async_threads.clear()
1143        finally:
1144            # Once the loop above has exited, no incoming_command_thread will run
1145            # again to call task_done() on commands already queued (e.g. by stop()
1146            # while this was disconnected/reconnecting). Drain them here, even on
1147            # cancellation, so a pending _incoming_queue.join() (as awaited by
1148            # stop()) can complete normally instead of being cancelled when the
1149            # Runner tears this loop down.
1150            while not incoming_queue.empty():
1151                incoming_queue.get_nowait()
1152                incoming_queue.task_done()
1153            # Retire the loop: a caller still waiting for a command it dispatched
1154            # here (stop()) sees the queue was drained, even if the loop closes
1155            # before running that caller's task (see _wait_loop_result)
1156            self._set_async_loop(loop=None)
1157        if self._logger.isEnabledFor(level=logging.INFO):
1158            self._logger.info(msg="Thread async execution end")
1159
1160    def _run(self) -> None:
1161        """Executes the main asynchronous loop for the communication manager.
1162
1163        This method initializes and runs the asynchronous event loop, using the
1164        event loop factory of ``_loop_utils.loop_factory`` (a SelectorEventLoop on
1165        Windows). _async_run already retries internally on any exception raised
1166        inside its connection loop, but anything that still escapes it -- e.g. a
1167        failure outside that loop -- is caught here. In that case the whole event
1168        loop is torn down and rebuilt from scratch after a reconnect delay (cut
1169        short by ``stop()``), so the background thread keeps trying to serve the
1170        manager instead of dying silently. Every loop gets a freshly created
1171        incoming command queue and subscription wake-up event (an
1172        ``asyncio.Queue``/``asyncio.Event`` binds to the first loop that waits on
1173        it, so reusing the previous loop's would fail), published together with the
1174        loop through ``_set_async_loop()``; commands still queued on a crashed loop
1175        are lost, while the desired subscription is applied again on the next
1176        connection.
1177
1178        Retries are unbounded: there is no maximum retry count or backoff cap, so
1179        the thread keeps restarting the event loop, forever, at a fixed
1180        reconnect_interval cadence, for as long as the manager is enabled. As soon
1181        as an attempt fails, ``_async_loop`` is reset to ``None`` and the
1182        connection status is republished (DISCONNECTED, then RECONNECTING once the
1183        retry delay has elapsed). Both resets of ``_async_loop`` go through
1184        ``_set_async_loop()`` (backed by ``_cond``); likewise, every read of the
1185        manager's enabled state here goes through ``_is_thread_enabled()`` rather
1186        than reading ``_system_status`` directly. The thread only stops retrying,
1187        and releases its state via ``finally``, once ``stop()`` (or ``start()``'s
1188        own failure-unwind path) has moved ``_system_status`` out of
1189        ``STARTING``/``STARTED``. A ``BaseException`` that is not an ``Exception``
1190        (e.g. ``SystemExit``) is not retried: it ends the thread.
1191
1192        Returns:
1193            None: The method runs for the background thread lifetime,
1194            restarting the event loop on failure as a side effect.
1195
1196        Complexity:
1197            - Time: O(1) to select the loop factory and start each runner attempt;
1198              the runner then blocks for the lifetime of _async_run, and the whole
1199              cycle repeats on failure, without limit, while the thread stays
1200              enabled.
1201            - Space: O(1), no additional storage is required.
1202        """
1203        if self._logger.isEnabledFor(level=logging.INFO):
1204            self._logger.info(msg="Thread async start execution")
1205        try:
1206            while self._is_thread_enabled():
1207                try:
1208                    with Runner(loop_factory=loop_factory()) as runner:
1209                        loop = runner.get_loop()
1210                        loop.set_exception_handler(
1211                            handler=lambda _, context: log_loop_exception(
1212                                logger=self._logger, context=context
1213                            )
1214                        )
1215                        # An asyncio.Queue/Event binds to the first loop that waits
1216                        # on it, so every (re)built loop needs its own
1217                        incoming_queue: AsyncioQueue[SyncComManager.Command] = (
1218                            AsyncioQueue(maxsize=self._params.max_incoming_queue_rooms)
1219                        )
1220                        subscription_wakeup = AsyncioEvent()
1221                        self._set_async_loop(
1222                            loop=loop,
1223                            incoming_queue=incoming_queue,
1224                            subscription_wakeup=subscription_wakeup,
1225                        )
1226                        runner.run(
1227                            coro=self._async_run(
1228                                incoming_queue=incoming_queue,
1229                                subscription_wakeup=subscription_wakeup,
1230                            )
1231                        )
1232                        # Forced to remove all lingering resources
1233                        # before closing the event loop
1234                        gc.collect()
1235                except Exception:
1236                    self._set_async_loop(loop=None)
1237                    self._set_connection_status(status=ConnectionStatus.DISCONNECTED)
1238                    if self._logger.isEnabledFor(level=logging.ERROR):
1239                        self._logger.exception(
1240                            msg="Unhandled exception escaped the async event loop"
1241                        )
1242                    self._wait_while_enabled(delay=self._params.reconnect_interval)
1243                    if not self._is_thread_enabled():
1244                        break
1245                    if self._logger.isEnabledFor(level=logging.INFO):
1246                        self._logger.info(
1247                            msg=f"Restarting async event loop after {self._params.reconnect_interval}"
1248                        )
1249                    self._set_connection_status(status=ConnectionStatus.RECONNECTING)
1250                    continue
1251                break
1252        finally:
1253            self._set_async_loop(loop=None)
1254            self._set_connection_status(status=ConnectionStatus.DISCONNECTED)
1255            if self._logger.isEnabledFor(level=logging.INFO):
1256                self._logger.info(msg="Thread async execution end")

1258    def _set_async_loop(
1259        self,
1260        loop: AbstractEventLoop | None,
1261        incoming_queue: AsyncioQueue[Command] | None = None,
1262        subscription_wakeup: AsyncioEvent | None = None,
1263    ) -> None:
1264        """Set the shared ``_async_loop``, ``_incoming_queue`` and
1265        ``_subscription_wakeup`` references under ``_cond``.
1266
1267        This is the sole writer of those three attributes, so no other method
1268        assigns to them directly; centralizing the write here guarantees every
1269        transition is observed atomically, loop, queue and event together, by
1270        readers such as ``subscribe()`` and ``_is_async_loop_ready()``.
1271
1272        Args:
1273            loop (AbstractEventLoop | None): The event loop now running in the
1274                background thread, or ``None`` once it has stopped or crashed.
1275            incoming_queue (AsyncioQueue[SyncComManager.Command] | None): The command
1276                queue created for ``loop``, or ``None`` (the default) when clearing.
1277            subscription_wakeup (AsyncioEvent | None): The subscription
1278                reconciler's wake-up event created for ``loop``, or ``None`` (the
1279                default) when clearing.
1280
1281        Returns:
1282            None: The shared references are updated as a side effect.
1283
1284        Complexity:
1285            - Time: O(1), acquires a lock and assigns three attributes.
1286            - Space: O(1), no additional storage is required.
1287        """
1288        with self._cond:
1289            self._async_loop = loop
1290            self._incoming_queue = incoming_queue if loop is not None else None
1291            self._subscription_wakeup = (
1292                subscription_wakeup if loop is not None else None
1293            )

1298        Returns:
1299            bool: True if ``_async_loop`` is currently set, False otherwise.
1300
1301        Complexity:
1302            - Time: O(1), acquires a lock and reads a single attribute.

1308    def _wait_for_async_loop_ready(self) -> None:
1309        """Poll until the background thread publishes its event loop.
1310
1311        Polls via ``_is_async_loop_ready()`` (re-acquiring ``_cond``
1312        briefly on each iteration) rather than blocking on one long wait,
1313        so it cannot block the background thread from publishing the loop.
1314        Extracted from ``start()`` into its own method (rather than a
1315        ``raise`` inline inside ``start()``'s outer ``try``) to keep the
1316        raise out of that broader try/except's control flow.
1317
1318        Returns:
1319            None: Returns once ``_async_loop`` has been published.
1320
1321        Raises:
1322            StepLibError: If the background thread dies before publishing
1323                the loop.
1324
1325        Complexity:
1326            - Time: O(1) amortized, bounded by how long the background
1327              thread takes to publish its loop.
1328            - Space: O(1), no additional storage is required.
1329        """
1330        while not self._is_async_loop_ready():
1331            if not self._async_thread.is_alive():
1332                raise StepLibError("Async thread died before event loop was ready")
1333            time_sleep(0.1)

1374    def _wait_loop_result(
1375        self, loop: AbstractEventLoop, future: Future[Any], description: str
1376    ) -> tuple[bool, Any]:
1377        """Wait for a future dispatched to ``loop``, tolerating the loop's end.
1378
1379        Waits in slices of ``STOP_POLL_INTERVAL``, up to ``params.timeout`` plus
1380        ``ENQUEUE_RESULT_MARGIN``. ``stop()`` aborts a connection attempt in
1381        flight almost at once, so the loop can end (draining its queue) and close
1382        before it runs the task behind ``future``: that task is then cancelled by
1383        ``Runner.close()``, or never runs at all. Once the loop is retired the
1384        command is therefore treated as processed instead of as a timeout.
1385
1386        Args:
1387            loop (AbstractEventLoop): The loop the future was dispatched to.
1388            future (Future[Any]): The future returned by
1389                ``run_coroutine_threadsafe``.
1390            description (str): The command's name used in error messages.
1391
1392        Returns:
1393            tuple[bool, Any]: ``(True, result)`` when the future completed, or
1394            ``(False, None)`` when the loop was retired first (its queue drained).
1395
1396        Raises:
1397            StepLibError: If the future does not complete within the budget, or
1398                is cancelled, while ``loop`` is still the published loop.
1399
1400        Complexity:
1401            - Time: O(t / STOP_POLL_INTERVAL) wake-ups, t being the wait.
1402            - Space: O(1), no additional storage is required.
1403        """
1404        deadline = monotonic() + self._params.timeout + self.ENQUEUE_RESULT_MARGIN
1405        while True:
1406            remaining = deadline - monotonic()
1407            try:
1408                return True, future.result(
1409                    timeout=max(0.0, min(remaining, self.STOP_POLL_INTERVAL))
1410                )
1411            except TimeoutError as error:
1412                if self._is_loop_retired(loop=loop):
1413                    future.cancel()
1414                    return False, None
1415                if remaining <= self.STOP_POLL_INTERVAL:
1416                    future.cancel()
1417                    raise StepLibError(
1418                        "Timed out waiting for the async loop to process the "
1419                        f"{description} command"
1420                    ) from error
1421            except FutureCancelledError as error:
1422                if self._is_loop_retired(loop=loop):
1423                    return False, None
1424                raise StepLibError(
1425                    f"Async loop was torn down while processing the {description} "
1426                    "command"
1427                ) from error

1429    @staticmethod
1430    async def _put_before(
1431        incoming_queue: AsyncioQueue[Command], command: Command, deadline: float
1432    ) -> bool:
1433        """Enqueue a command only if that can be done before an absolute deadline.
1434
1435        Runs on the async loop. Starting after the deadline (e.g. because the loop
1436        was busy) or still waiting for room in a full queue when it expires, it
1437        gives up without enqueueing, so a command whose caller already timed out
1438        is never applied later.
1439
1440        Args:
1441            incoming_queue (AsyncioQueue[Command]): The loop's incoming command queue.
1442            command (Command): The command to enqueue.
1443            deadline (float): The ``time.monotonic()`` instant after which the
1444                command must not be enqueued.
1445
1446        Returns:
1447            bool: True if the command was enqueued, False if the deadline passed first.
1448
1449        Complexity:
1450            - Time: O(1), a single queue insertion (plus the bounded wait for room).
1451            - Space: O(1), no additional storage is required.
1452        """
1453        remaining = deadline - monotonic()
1454        if remaining <= 0:
1455            return False
1456        try:
1457            async with asyncio_timeout(remaining):
1458                await incoming_queue.put(item=command)
1459        except TimeoutError:
1460            return False
1461        return True

1463    def _enqueue_command(
1464        self,
1465        loop: AbstractEventLoop,
1466        incoming_queue: AsyncioQueue[Command],
1467        command: Command,
1468        description: str,
1469    ) -> None:
1470        """Enqueue a command on the async loop, bounded by ``params.timeout``.
1471
1472        The deadline is enforced on the loop side by ``_put_before``, which never
1473        enqueues past it; the caller waits ``ENQUEUE_RESULT_MARGIN`` past the
1474        deadline for the loop to report the outcome. Only ``stop()`` enqueues
1475        commands (its ``ExitThreadsCommand``), and a stop must be applied even if
1476        its caller timed out, so no withdrawal is needed.
1477
1478        Args:
1479            loop (AbstractEventLoop): The running async loop.
1480            incoming_queue (AsyncioQueue[Command]): The loop's incoming command queue.
1481            command (Command): The command to enqueue.
1482            description (str): The command's name used in error messages
1483                (e.g. ``"stop"``).
1484
1485        Returns:
1486            None: The command is enqueued as a side effect.
1487
1488        Raises:
1489            StepLibError: If the loop is closed concurrently while dispatching
1490                without having been retired (a loop that already ended is left
1491                alone), if the command could not be enqueued before the deadline, or if
1492                the loop was torn down (cancelling the enqueue) meanwhile.
1493
1494        Complexity:
1495            - Time: O(1), plus the bounded wait for the loop.
1496            - Space: O(1), no additional storage is required.
1497        """
1498        deadline = monotonic() + self._params.timeout
1499        coro = self._put_before(
1500            incoming_queue=incoming_queue, command=command, deadline=deadline
1501        )
1502        try:
1503            future = asyncio_run_coroutine_threadsafe(coro=coro, loop=loop)
1504        except RuntimeError as error:
1505            # coro is a coroutine object: pylint infers its type from the
1506            # coroutine function's "-> bool" return annotation instead
1507            coro.close()  # pylint: disable=no-member
1508            # stop() aborts a connection attempt in flight by itself, so the loop
1509            # may have ended and closed before this dispatch: a retired loop has
1510            # already drained its queue, so there is nothing left to stop
1511            if self._is_loop_retired(loop=loop):
1512                return
1513            raise StepLibError(
1514                f"Async loop was closed concurrently while dispatching {description}"
1515            ) from error
1516        completed, enqueued = self._wait_loop_result(
1517            loop=loop, future=future, description=description
1518        )
1519        # A retired loop has already ended: there is nothing left to stop
1520        if completed and not enqueued:
1521            raise StepLibError(
1522                "Timed out waiting for the async loop to process the "
1523                f"{description} command"
1524            )

1526    def _wait_queue_drained(
1527        self, loop: AbstractEventLoop, incoming_queue: AsyncioQueue[Command]
1528    ) -> None:
1529        """Wait until every command already queued on the async loop is processed.
1530
1531        Args:
1532            loop (AbstractEventLoop): The running async loop.
1533            incoming_queue (AsyncioQueue[Command]): The loop's incoming command queue.
1534
1535        Returns:
1536            None: Returns once the queue is drained.
1537
1538        Raises:
1539            StepLibError: If the loop is closed concurrently while dispatching
1540                without having been retired (a loop that ended after processing the
1541                exit command is treated as drained), if
1542                the queue is not drained within ``params.timeout`` plus
1543                ``ENQUEUE_RESULT_MARGIN`` (the waiting task is then cancelled so it
1544                does not linger on the loop), or if the loop was torn down
1545                (cancelling the wait) meanwhile.
1546
1547        Note:
1548            A connection attempt in flight is aborted by ``stop()`` within
1549            ``STOP_POLL_INTERVAL`` (see ``_run_abortable_attempt``) and the reconnect
1550            wait is cut short the same way, so the queue is drained well within
1551            the budget even while the broker is unreachable.
1552
1553        Complexity:
1554            - Time: O(1) here, plus the bounded wait for the loop.
1555            - Space: O(1), no additional storage is required.
1556        """
1557        coro = incoming_queue.join()
1558        try:
1559            future = asyncio_run_coroutine_threadsafe(coro=coro, loop=loop)
1560        except RuntimeError as error:
1561            coro.close()
1562            # The loop may have processed the exit command and closed between the
1563            # enqueue and this dispatch: a retired loop has already drained its
1564            # queue, so there is nothing left to wait for
1565            if self._is_loop_retired(loop=loop):
1566                return
1567            raise StepLibError(
1568                "Async loop was closed concurrently while dispatching stop"
1569            ) from error
1570        self._wait_loop_result(loop=loop, future=future, description="stop")

1572    def _stop(self) -> None:
1573        """Tear down the health-check thread, the background thread, and the
1574        publish worker pool - the actual teardown mechanism shared by the
1575        public ``stop()`` and by ``start()``'s own failure-unwind path.
1576
1577        Does not itself check or transition into ``STOPPING``/``STARTING``
1578        on entry - the caller (``stop()`` or ``start()``'s except-block) is
1579        responsible for having already claimed one of those via
1580        ``stop()``/``start()``. Because of that, this method
1581        can only ever be reached from one of those two states, and can
1582        never have two simultaneous callers (see the class-level Note).
1583
1584        Always leaves ``_system_status == STOPPED`` before returning or
1585        raising, even if a wait times out, the publish worker pool close
1586        raises (even a ``BaseException``), or the background thread never
1587        published a loop (e.g. it died before becoming ready) - so a
1588        failed/partial start-then-stop cycle never permanently wedges the
1589        manager. Every wait is bounded by ``self._params.timeout``, including
1590        the join of the background thread: a thread still alive after it is
1591        reported, and ``start()`` then refuses to run until it has exited.
1592
1593        Returns:
1594            None: The background thread and publish worker pool are
1595            stopped as a side effect before this returns.
1596
1597        Raises:
1598            StepLibError: If the health-check thread does not stop within
1599                ``self._params.timeout``, if the async loop is closed
1600                concurrently while the stop command is dispatched or does not
1601                process it within that same timeout, or if the
1602                background thread is still alive after its bounded join. In
1603                every case the rest of teardown (the publish worker pool close
1604                and the final STOPPED transition) still runs first.
1605
1606        Complexity:
1607            - Time: O(w + q), where w is ``publish_worker_count`` (publish worker pool
1608              close) and q is the number of commands already queued in
1609              _incoming_queue at the time this is called (bounded by
1610              max_incoming_queue_rooms), to drain them before the exit command is
1611              processed; the thread joins then block for bounded shutdown delays.
1612            - Space: O(w), for the pool's snapshot of worker processes.
1613        """
1614        self._health_check_stop_event.set()
1615        health_check_timeout_error: StepLibError | None = None
1616        if self._health_check_thread.ident is not None:
1617            self._health_check_thread.join(timeout=self._params.timeout)
1618            if self._health_check_thread.is_alive():
1619                health_check_timeout_error = StepLibError(
1620                    "Timed out waiting for the health-check thread to stop"
1621                )
1622        async_thread_error: StepLibError | None = None
1623        try:
1624            with self._cond:
1625                loop = self._async_loop
1626                incoming_queue = self._incoming_queue
1627            if loop is not None and incoming_queue is not None:
1628                try:
1629                    self._enqueue_command(
1630                        loop=loop,
1631                        incoming_queue=incoming_queue,
1632                        command=SyncComManager.ExitThreadsCommand(),
1633                        description="stop",
1634                    )
1635                    self._wait_queue_drained(loop=loop, incoming_queue=incoming_queue)
1636                except StepLibError as error:
1637                    async_thread_error = error
1638            if self._async_thread.ident is not None:
1639                self._async_thread.join(timeout=self._params.timeout)
1640            if self._async_thread.is_alive():
1641                thread_alive_error = StepLibError(
1642                    "Background thread did not stop in time"
1643                )
1644                # Keep the dispatch failure that likely caused it, if any
1645                thread_alive_error.__cause__ = async_thread_error
1646                async_thread_error = thread_alive_error
1647            else:
1648                self._set_async_loop(loop=None)
1649        finally:
1650            try:
1651                self._worker_pool.close()
1652            finally:
1653                with self._cond:
1654                    self._set_status(new_status=_SystemStatus.STOPPED)
1655                    self._cond.notify_all()
1656        for stop_error in (health_check_timeout_error, async_thread_error):
1657            if stop_error is not None:
1658                raise stop_error

1660    def _health_check_loop(self, stop_event: Event) -> None:
1661        """Periodically check the publish worker pool's health, restarting any dead/blocked worker.
1662
1663        Runs on its own dedicated OS thread (``_health_check_thread``),
1664        separate from the subscribe/receive background thread -
1665        ``PublishWorkerPool.check_health()``'s restart path can involve a
1666        genuinely blocking wait for a replacement worker to become ready
1667        (bounded by ``publish_worker_startup_timeout``); running it as a
1668        coroutine sharing the subscribe/receive event loop would stall
1669        inbound MQTT message delivery for that whole duration every time a
1670        restart happens. A dedicated thread sidesteps this, since blocking
1671        calls here don't affect anything else - including ``send()``, since
1672        the pool's own internal ``_cond`` is held only for brief state reads
1673        and socket calls, not across the spawn/readiness-wait.
1674
1675        Args:
1676            stop_event (Event): The stop event created together with this thread by
1677                ``_create_runtime()``; passed explicitly (rather than read from the
1678                attribute) so a thread from a previous run always watches its own event.
1679
1680        Returns:
1681            None: The loop runs until ``stop_event`` is set, restarting unhealthy
1682            workers as a side effect.
1683
1684        Note:
1685            Any exception raised by a health-check pass is logged and the loop
1686            continues with the next pass, so an unexpected failure (e.g. an
1687            ``OSError`` while spawning a replacement worker) never kills this thread
1688            - which would otherwise leave every later dead/blocked worker
1689            unrestarted. The first failure of a run of failures is logged at ERROR
1690            with its traceback, the following ones at WARNING on one line, and the
1691            first successful pass afterwards at INFO, so a persistent failure does
1692            not flood the log with a traceback every interval.
1693
1694        Complexity:
1695            - Time: O(1) per interruptible sleep; O(w), where w is
1696              ``publish_worker_count``, per health-check pass.
1697            - Space: O(1), no additional storage is required.
1698        """
1699        failing = False
1700        while not stop_event.wait(timeout=self._params.publish_health_check_interval):
1701            try:
1702                self._worker_pool.check_health(auto_restart=True)
1703            except Exception as error:
1704                if not failing:
1705                    if self._logger.isEnabledFor(level=logging.ERROR):
1706                        self._logger.exception(msg="Publish worker health check failed")
1707                elif self._logger.isEnabledFor(level=logging.WARNING):
1708                    self._logger.warning(
1709                        msg=f"Publish worker health check still failing: {error!r}"
1710                    )
1711                failing = True
1712            else:
1713                if failing and self._logger.isEnabledFor(level=logging.INFO):
1714                    self._logger.info(msg="Publish worker health check recovered")
1715                failing = False

1717    def start(self) -> None:
1718        """Start the background thread, the publish worker pool, and the health check.
1719
1720        Starts the asynchronous thread and waits for its event loop to be published,
1721        then starts the publish worker pool and the health-check thread. The method
1722        ensures that only one thread and loop are running at a time. The manager can be
1723        restarted after stop(): once ``STARTING`` is claimed, ``_create_runtime()``
1724        builds fresh background and health-check threads and clears the previous
1725        subscription, so subscribe() must be called again after every start().
1726
1727        Note:
1728            The initial "not already running" check is performed atomically by
1729            claiming ``STARTING`` under ``_cond`` (concurrent ``start()``/``stop()``
1730            calls wait for the transition in progress and an already ``STARTED``
1731            manager makes ``start()`` a no-op) to avoid racing
1732            or with the background thread publishing ``_async_loop``. The subsequent
1733            readiness poll goes through ``_is_async_loop_ready()``, which re-acquires
1734            the lock briefly on each iteration instead of holding it for the whole
1735            wait, so it cannot block the background thread from publishing the loop.
1736            Before the background thread is started, when ``cache_dir`` is set,
1737            ``FacilitySerializer.get_asn_context`` loads the ASN.1 grammar once,
1738            filling both ``cache_dir`` (from which every publish worker process
1739            loads it instead of compiling it concurrently - a worker compiling it
1740            would stall its event loop and heartbeat for seconds) and this
1741            process's memo (reused by the background thread's serializers).
1742            Once the subscribe/receive loop is ready, the publish worker pool is
1743            started and, once that succeeds, the dedicated health-check thread is
1744            started. The *entire* startup sequence after claiming ``STARTING`` -
1745            including the readiness-wait's own failure branch - runs inside one
1746            ``try`` whose ``except`` - on any ``BaseException``, including a
1747            ``KeyboardInterrupt``/``SystemExit`` - always attempts the internal
1748            ``_stop()`` best-effort (logging, not raising, if the unwind itself
1749            fails) before re-raising the original error, so no orphaned thread
1750            survives a failed ``start()``, the manager never stays in STARTING,
1751            and the caller always sees the real cause of the failure, never a
1752            masking exception from the unwind. ``start()`` is refused while the
1753            background thread of a previous run is still alive (its ``stop()``
1754            timed out).
1755
1756        Returns:
1757            None: The background thread, publish worker pool, and
1758            health-check thread are all running when this returns without
1759            raising.
1760
1761        Raises:
1762            StepLibError: If a start/stop in progress does not settle in time, if
1763                the previous background thread is still running, if the background
1764                thread dies before the event loop becomes ready, or if the publish
1765                worker pool fails to start (a worker did not become ready or did
1766                not complete the ZMQ handshake in time, or the ZMQ socket could not
1767                be bound).
1768            Exception: Any error raised by asn1tools/diskcache while warming the
1769                ASN.1 cache (e.g. an unwritable ``cache_dir``), after the unwind.
1770
1771        Complexity:
1772            - Time: O(f) for the ASN.1 cache warm-up when ``cache_dir`` is set, where
1773              f is the total size of the bundled grammar files (a full compilation
1774              only while the cache is empty); O(1) amortized for the
1775              subscribe/receive thread startup; O(w), where w is
1776              ``publish_worker_count``, for starting the publish worker pool.
1777            - Space: O(f) for the compiled ASN.1 context, memoized for the process
1778              (and reused by the background thread); O(w), for the publish worker
1779              pool's per-worker bookkeeping.
1780        """
1781        with self._cond:
1782            self._wait_settled()
1783            if self._system_status is _SystemStatus.STARTED:
1784                return
1785            if self._async_thread.is_alive():
1786                raise StepLibError(
1787                    "The previous background thread is still running; "
1788                    "stop() did not complete"
1789                )
1790            self._set_status(new_status=_SystemStatus.STARTING)
1791            self._create_runtime()
1792        try:
1793            if self._params.cache_dir is not None:
1794                # Fill the on-disk ASN.1 cache before the publish workers start, so
1795                # they load the grammar instead of compiling it concurrently; the
1796                # same call fills this process's memo, reused by the background
1797                # thread's serializers (the returned context is kept there)
1798                if self._logger.isEnabledFor(level=logging.DEBUG):
1799                    self._logger.debug(
1800                        msg=f"Warming the ASN.1 cache in {self._params.cache_dir}"
1801                    )
1802                FacilitySerializer.get_asn_context(cache_dir=self._params.cache_dir)
1803            self._async_thread.start()
1804            self._wait_for_async_loop_ready()
1805            self._worker_pool.start()
1806            self._health_check_thread.start()
1807        except BaseException:
1808            # Unwind on any interruption too (KeyboardInterrupt, SystemExit), so the
1809            # manager never stays in STARTING with a live background thread
1810            try:
1811                self._stop()
1812            except Exception:
1813                if self._logger.isEnabledFor(level=logging.ERROR):
1814                    self._logger.exception(
1815                        msg="Failed to unwind the background thread after a failed start()"
1816                    )
1817            raise
1818        with self._cond:
1819            self._set_status(new_status=_SystemStatus.STARTED)
1820            self._cond.notify_all()

1822    def stop(self) -> None:
1823        """Stop the background thread, the health check, and the publish worker pool.
1824
1825        Stops the running asynchronous thread by claiming the STOPPING lifecycle state
1826        and sending an exit command through the queue. Waits for every already-queued command (including the exit
1827        command) to be fully processed, then waits for thread completion before
1828        clearing the async loop reference.
1829
1830        Note:
1831            The initial "is it actually running" check and the claim of the STOPPING
1832            state are performed atomically under ``_cond`` (after waiting for any transition in
1833            progress; a manager already ``STOPPED`` makes ``stop()`` a no-op), so a
1834            concurrent ``stop()`` call never races through duplicate teardown. The actual
1835            teardown work is delegated to the internal ``_stop()``, shared with
1836            ``start()``'s own failure-unwind path - see its docstring for the full
1837            sequence and its bounded-wait/error-handling behavior (the health-check
1838            thread join and the async-loop dispatch calls are each bounded by
1839            ``self._params.timeout``; the publish worker pool is always closed, and
1840            ``_system_status`` always ends at STOPPED, even if either wait times out).
1841
1842        Raises:
1843            StepLibError: If a start/stop in progress does not settle in time; if the
1844                health-check thread or the async loop do not respond within
1845                ``self._params.timeout`` seconds (or the loop is torn down while
1846                processing the stop command); or if the background thread is still
1847                alive after its bounded join ("Background thread did not stop in
1848                time", chaining the dispatch failure that likely caused it).
1849            Exception: Any error raised by ``PublishWorkerPool.close()``, after the
1850                manager has been moved to STOPPED.
1851
1852        Returns:
1853            None: The background thread and publish worker pool are
1854            stopped as a side effect before this returns.
1855
1856        Complexity:
1857            - Time: O(w + q), where w is ``publish_worker_count`` (publish worker pool
1858              teardown) and q is the number of commands already queued in
1859              _incoming_queue at the time stop() is called (bounded by
1860              max_incoming_queue_rooms), to drain them before the exit command is
1861              processed; the thread joins then block for bounded shutdown delays.
1862            - Space: O(w), for the pool's snapshot of worker processes.
1863        """

1865            self._wait_settled()

1867                return
1868            self._set_status(new_status=_SystemStatus.STOPPING)
1869        if self._logger.isEnabledFor(level=logging.INFO):
1870            self._logger.info(msg="Command: thread async stop execution")

1934    def subscribe(self, topics: list[str], max_qos: MqttQoS) -> None:
1935        """Set the MQTT subscription this manager keeps on the broker.
1936
1937        The request replaces any previous one and is applied asynchronously by the
1938        background loop's subscription reconciler, which first unsubscribes the
1939        previously applied topics: as soon as the manager is connected, and again
1940        after every reconnect. The call never waits for the background loop or the
1941        broker - the outcome (SUBACK) is logged - so it cannot time out, and it is
1942        accepted while the background loop is being rebuilt or reconnecting.
1943        Repeating the same request sends nothing to the broker. Like every
1944        subscription, it is cleared by ``start()``: call ``subscribe()`` again
1945        after each ``start()``.
1946
1947        Args:
1948            topics (list[str]): List of MQTT topic strings to subscribe to. The list
1949                is copied: changing it afterwards does not alter the request.
1950            max_qos (MqttQoS): Maximum Quality of Service level for the subscriptions.
1951
1952        Note:
1953            The subscriptions always use ``noLocal=False``, which MQTT v5 requires
1954            for shared subscriptions (``$share/<group>/<filter>``, passed through
1955            unchanged). The messages this manager publishes on a subscribed topic
1956            are therefore received back unless ``station_id`` is set, which makes
1957            the receiver drop them as echoes; with ``station_id=None`` an INFO
1958            record says so.
1959
1960            The background loop is woken through ``call_soon_threadsafe``, which
1961            only appends a callback to the loop's (unbounded) ready queue: it never
1962            blocks. If that loop is closed concurrently (``RuntimeError``), the
1963            request is still recorded and the next loop applies it when it
1964            connects.
1965
1966        Raises:
1967            StepLibValueError: If any topic is not a valid MQTT topic filter. The
1968                check runs synchronously, before the request is recorded.
1969            StepLibError: If the manager is not running (not started, or being
1970                stopped).
1971
1972        Returns:
1973            None: The desired subscription is recorded and the background loop
1974            woken; this does not wait for the broker's SUBACK.
1975
1976        Example:
1977            >>> com_manager.subscribe(
1978            ...     topics=["home/sensors/#"], max_qos=MqttQoS.QOS_1
1979            ... )  # doctest: +SKIP
1980
1981        Complexity:
1982            - Time: O(k), where k is the number of topics, to validate and copy them.
1983            - Space: O(k), where k is the number of topics, for the recorded request.
1984        """
1985        try:
1986            for topic in topics:
1987                Wildcard(value=topic)
1988        except (TypeError, ValueError) as error:
1989            raise StepLibValueError(f"Invalid subscribe topic: {error}") from error
1990        request = _Subscription(topics=tuple(topics), max_qos=max_qos)
1991        with self._cond:
1992            if not self._is_thread_enabled():
1993                raise StepLibError("Manager is not running")
1994            self._desired_subscription = request
1995            loop = self._async_loop
1996            wakeup = self._subscription_wakeup
1997        if self._params.station_id is None and self._logger.isEnabledFor(
1998            level=logging.INFO
1999        ):
2000            self._logger.info(
2001                msg="station_id is None: messages this manager publishes on subscribed "
2002                "topics will be received back"
2003            )
2004        if self._logger.isEnabledFor(level=logging.DEBUG):
2005            self._logger.debug(msg=f"Command: subscribe {topics}, max_qos {max_qos}")
2006        if loop is not None and wakeup is not None:
2007            # A loop closed concurrently is harmless: the request is recorded, and
2008            # the next loop's reconciler applies it when it connects
2009            with suppress(RuntimeError):
2010                loop.call_soon_threadsafe(wakeup.set)

2092    def check_health(self, auto_restart: bool = True) -> None:
2093        """Run an immediate, out-of-cadence publish worker health check.
2094
2095        An escape hatch for callers who want to check/restart dead or
2096        blocked publish workers immediately, in addition to the periodic
2097        check already run by the dedicated health-check thread. Delegates
2098        straight to the publish worker pool: the check-and-mark step of a
2099        restart is serialized against a concurrent restart of the same

2101        manual call here) via the pool's own internal locking - no locking
2102        is needed at this level. The restart itself still runs unlocked so
2103        ``send()``/``publish_its_message()`` stay available throughout.
2104
2105        Args:
2106            auto_restart (bool): If True (the default), restart every
2107                dead/blocked worker found. If False, only log what was
2108                found.
2109
2110        Returns:
2111            None: Unhealthy publish workers are logged and, if
2112            auto_restart is True, restarted in place as a side effect.
2113
2114        Complexity:
2115            - Time: O(w), where w is ``publish_worker_count``, for
2116              detection, plus the cost of restarting any unhealthy worker
2117              found.

2123        self, signals: Sequence[int] = (signal.SIGTERM,)
2124    ) -> None:
2125        """Install signal handlers that stop the manager.
2126
2127        This is the parent-side counterpart to the worker-side SIGTERM bridge.
2128
2129        Opt-in: never wired into ``start()``/``stop()`` automatically. Must
2130        be called from the main thread of the main interpreter -
2131        ``signal.signal()``'s own hard requirement, enforced by the stdlib
2132        itself, not by step_lib. The installed handler never runs ``stop()``
2133        itself: it would interrupt the main thread at an arbitrary point and could
2134        re-enter a ``start()``/``stop()`` already running on that same thread.
2135        It starts a non-daemon ``signal-stop`` thread that calls ``self.stop()``
2136        (``stop()`` is idempotent, so repeated signals stop the manager once);
2137        it does not call ``sys.exit()`` or otherwise
2138        terminate the process, since presuming the whole application should
2139        exit is too strong an assumption for a library method to make on
2140        the caller's behalf - the caller remains responsible for noticing
2141        the manager has stopped (e.g. ``while manager.is_running: ...``) and
2142        exiting its own main loop if that is the desired behavior. Do not use
2143        ``connection_status`` for that: it is also DISCONNECTED during every
2144        transient MQTT reconnection.
2145
2146        The default ``signals`` tuple contains only ``SIGTERM``, not
2147        ``SIGINT``: Python already installs its own default ``SIGINT``
2148        handler (raising ``KeyboardInterrupt``), which already propagates
2149        cleanly through a ``with SyncComManager(...):`` block via ordinary
2150        exception unwinding, so overriding it by default would silently
2151        change already-working behavior.
2152
2153        The installed handler holds the manager only through a weak reference,
2154        so it never keeps the manager alive. The handler each signal had before
2155        the first install is remembered: ``restore_signal_handlers()`` puts it
2156        back, and a signal received after the manager was garbage-collected
2157        restores it and passes the signal on to it, so the signal is never
2158        silently swallowed.
2159

2161            signals (Sequence[int]): The signals to install the handler
2162                for. Defaults to ``(signal.SIGTERM,)``.
2163
2164        Returns:
2165            None: The signal handlers are installed as a side effect;
2166            nothing is returned.
2167
2168        Raises:
2169            ValueError: If called from any thread other than the main
2170                thread of the main interpreter (raised by ``signal.signal()``
2171                itself).
2172
2173        Complexity:
2174            - Time: O(len(signals)), one ``signal.signal()`` call per
2175              signal.
2176            - Space: O(len(signals)), one remembered previous handler per
2177              signal.
2178        """
2179        handler = SyncComManager._make_signal_handler(
2180            stop_ref=weakref.WeakMethod(self._start_stop_from_signal),
2181            previous_handlers=self._previous_signal_handlers,
2182        )
2183        for one_signal in signals:
2184            previous_handler = signal.signal(one_signal, handler)
2185            # A repeated install must keep the original handler, not ours; None
2186            # (a handler not installed from Python) cannot be reinstalled

2189                signal.SIG_DFL if previous_handler is None else previous_handler,

2218    def _make_signal_handler(
2219        stop_ref: "weakref.WeakMethod[Callable[[], None]]",
2220        previous_handlers: dict[int, Any],
2221    ) -> Callable[[int, FrameType | None], None]:
2222        """Build a signal handler that stops the manager without referencing it.
2223
2224        The handler holds only stop_ref and previous_handlers (the manager's
2225        own dict, which does not reference the manager), so it never keeps the
2226        manager alive. If the manager is gone when a signal arrives, the
2227        handler reinstalls the previous handler for that signal and passes the
2228        signal on to it: a callable is called, ``SIG_DFL`` is re-raised so the
2229        default action (e.g. terminating on ``SIGTERM``) takes place, and
2230        ``SIG_IGN`` (or an unknown handler) ignores it.
2231
2232        Args:
2233            stop_ref (weakref.WeakMethod[Callable[[], None]]): Weak reference to
2234                the manager's ``_start_stop_from_signal`` bound method.
2235            previous_handlers (dict[int, Any]): The handler each signal had
2236                before the install, keyed by signal number.
2237
2238        Returns:
2239            Callable[[int, FrameType | None], None]: The signal handler.
2240
2241        Complexity:
2242            - Time: O(1), builds one closure.
2243            - Space: O(1), the closure holds two references.
2244        """
2245
2246        def handler(signum: int, frame: FrameType | None) -> None:
2247            """Stop the manager, or forward the signal if it no longer exists.
2248
2249            Args:
2250                signum (int): The received signal number.
2251                frame (FrameType | None): The interrupted stack frame.
2252
2253            Returns:
2254                None: The manager is stopped, or the signal forwarded, as a
2255                side effect.
2256
2257            Complexity:
2258                - Time: O(1), one thread start or one signal forward.
2259                - Space: O(1), no additional storage is required.
2260            """
2261            start_stop = stop_ref()
2262            if start_stop is not None:
2263                start_stop()
2264                return
2265            previous_handler = previous_handlers.pop(signum, signal.SIG_DFL)
2266            signal.signal(signum, previous_handler)
2267            if callable(previous_handler):
2268                previous_handler(signum, frame)
2269            elif previous_handler == signal.SIG_DFL:
2270                signal.raise_signal(signum)
2271
2272        return handler

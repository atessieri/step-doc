 117class SyncComManager:
 118    """Synchronous Communication Manager for MQTT messaging.
 119
 120    This class provides a thread-safe interface for MQTT communication,
 121    managing operations through queues and background threads.
 122
 123    The manager handles:
 124
 125        - MQTT message publishing and subscribing
 126        - Automatic reconnection on connection loss
 127        - Thread-safe message queuing
 128        - BaseException handling and logging
 129
 130    Note:
 131        A single internal ``_state_lock`` (``RLock``) guards both the connection
 132        status and the transitions of the background event loop/thread state
 133        (``_async_loop``, ``_async_thread_enable``) used by the subscribe/receive
 134        path. It makes the "is the loop running" check-and-capture atomic across
 135        threads calling start()/stop()/subscribe()/get_its_message_received()
 136        concurrently with the background thread. It does not serialize the
 137        blocking calls made through the captured loop reference (those stay
 138        outside the lock so I/O is not serialized). Every read or write of
 139        ``_async_loop``/``_async_thread_enable`` is funneled through a small set
 140        of private accessor methods (``_set_async_loop()``,
 141        ``_is_async_loop_ready()``, ``_is_thread_enabled()``, ``_get_active_loop()``,
 142        ``_begin_start()``, ``_begin_stop()``) rather than touching the attributes
 143        directly, so no method can accidentally read or write them outside
 144        ``_state_lock``. ``publish_its_message()`` and ``check_health()`` do not
 145        use ``_state_lock`` at all: they send directly to the publish worker pool
 146        (``_worker_pool``), which is safe to call concurrently from multiple
 147        threads because it serializes access to its own ZMQ socket internally.
 148
 149    Attributes:
 150        params (SyncComManagerParams): Configuration parameters for the communication manager,
 151            including queue sizes and other settings.
 152        logger (Logger): Logger instance for the manager.
 153
 154    The class can be used either with context manager (recommended) or manual start/stop:
 155
 156    Example:
 157        >>> with SyncComManager(params) as manager:
 158        ...     manager.subscribe(["topic1", "topic2"], MqttQoS.QOS_1)
 159        ...     manager.publish_its_message(
 160        ...         message=message,
 161        ...         address=address,
 162        ...         current_position=current_position,
 163        ...         is_station_mobile=True,
 164        ...     )
 165
 166    Or manually:
 167
 168    Example:
 169        >>> manager = SyncComManager(params)
 170        ... manager.start()
 171        ... manager.subscribe(["topic1"], MqttQoS.QOS_0)
 172        ... manager.stop()

 174    Complexity:
 175        - Time: O(1) for construction and subscribe dispatch; O(w), where w is
 176          publish_worker_count, for start/stop; O(n) for publish_its_message and

 353        processes them and puts them into the outgoing queue. It logs the received messages
 354        along with their QoS level and topic.

 358            from.

 524        """Executes an asynchronous thread that handles commands drained from the
 525        incoming queue.
 526
 527        This thread manages subscribing to topics and handling exit commands (the
 528        publish path no longer runs through this thread - see
 529        ``publish_its_message``, which sends directly to the publish worker pool). It
 530        continuously monitors an incoming queue for commands and processes them
 531        accordingly.
 532
 533        Args:
 534            client (AsyncComManager): The asynchronous communication manager client instance.
 535
 536        Returns:
 537            None: The method runs until an ExitThreadsCommand is received.
 538
 539        Note:
 540            The thread runs continuously until an ExitThreadsCommand is received.
 541            Supported commands are:
 542
 543                - ExitThreadsCommand: Terminates the thread
 544                - SubscribeCommand: Subscribes to specified topics
 545
 546        Complexity:
 547            - Time: O(1) per dispatch step (queue get and match), plus the complexity of
 548              the delegated command handler, which is O(k) for a SubscribeCommand (k
 549              topics); the loop itself runs until an ExitThreadsCommand is received.
 550            - Space: O(1) for the loop's own state; bounded by the complexity of the
 551              delegated command handler for each iteration.

 554            await self._subscribe_command_exec(
 555                client=client, subscribe_params=self._subscribe_topics
 556            )

 605        This method initializes and manages asynchronous communication threads for message
 606        receiving and incoming-command handling. It handles connection retries and
 607        exceptions during execution.
 608
 609        The method sets up an event loop with a custom exception handler and creates tasks for:
 610
 611            - Message receiving (if max_outgoing_queue_rooms > 0)
 612            - Incoming-command handling (subscribe/exit commands)
 613
 614        The execution continues until either loop_continue is False or _async_thread_enable is
 615        False. On exceptions, it will attempt to reconnect after the configured reconnect interval.
 616
 617        Note:
 618            Before returning, any commands still sitting in ``_incoming_queue``
 619            (e.g. an ``ExitThreadsCommand`` enqueued by ``stop()`` while this
 620            manager was disconnected or mid-reconnect, when no
 621            ``_incoming_command_thread`` was running to drain it) are drained and
 622            marked done, so a caller blocked in ``stop()``'s
 623            ``_incoming_queue.join()`` observes a clean completion instead of a
 624            cancellation from the event loop tearing down.
 625
 626        Returns:
 627            None: The coroutine runs until the manager is disabled,
 628            reconnecting on failure as a side effect.
 629
 630        Complexity:
 631            - Time: O(1) per connection attempt to set up the event loop, exception
 632              handler, and the (at most two) receive/incoming-command tasks; the tasks
 633              themselves run until cancelled and their per-message cost is documented on
 634              _message_receive_thread/_incoming_command_thread.
 635            - Space: O(1) for the manager's own state per connection attempt.
 636        """
 637        self._set_connection_status(status=ConnectionStatus.DISCONNECTED)
 638        loop = get_running_loop()
 639        loop.set_exception_handler(
 640            handler=lambda _, context: self._exception_handler(context=context)
 641        )
 642        self._set_async_loop(loop)
 643        loop_continue = True
 644        while loop_continue and self._is_thread_enabled():
 645            try:
 646                async with AsyncComManager(
 647                    params=self._params, logger=self._logger
 648                ) as client:
 649                    self._set_connection_status(status=ConnectionStatus.CONNECTED)
 650                    async with AsyncioTaskGroup() as group:
 651                        if self._params.max_outgoing_queue_rooms > 0:
 652                            # Create mqtt receive thread
 653                            self._async_threads.append(
 654                                group.create_task(
 655                                    coro=self._message_receive_thread(client=client),
 656                                    name="message_receive_thread",
 657                                )
 658                            )
 659                        # Create incoming-command thread
 660                        self._async_threads.append(
 661                            group.create_task(
 662                                coro=self._incoming_command_thread(client=client),
 663                                name="incoming_command_thread",
 664                            )
 665                        )
 666                self._set_connection_status(status=ConnectionStatus.DISCONNECTED)
 667                loop_continue = False
 668            except BaseException:
 669                self._set_connection_status(status=ConnectionStatus.DISCONNECTED)
 670                if self._logger.isEnabledFor(level=logging.ERROR):
 671                    self._logger.exception(msg="Exception happened")
 672                if self._logger.isEnabledFor(level=logging.INFO):
 673                    self._logger.info(msg="All threads stopped and connection dropped")
 674                await asyncio_sleep(delay=self._params.reconnect_interval)
 675                if self._logger.isEnabledFor(level=logging.INFO):
 676                    self._logger.info(
 677                        msg=f"Connection retry after {self._params.reconnect_interval}"
 678                    )
 679                self._set_connection_status(status=ConnectionStatus.RECONNECTING)
 680            finally:
 681                self._async_threads.clear()
 682        # Once the loop above has exited, no incoming_command_thread will run again
 683        # to call task_done() on commands already queued (e.g. by stop() while this
 684        # was disconnected/reconnecting). Drain them here so a pending
 685        # _incoming_queue.join() (as awaited by stop()) can complete normally
 686        # instead of being cancelled when the Runner tears this loop down.
 687        while not self._incoming_queue.empty():
 688            self._incoming_queue.get_nowait()
 689            self._incoming_queue.task_done()
 690        if self._logger.isEnabledFor(level=logging.INFO):
 691            self._logger.info(msg="Thread async execution end")

 693    def _run(self) -> None:
 694        """Executes the main asynchronous loop for the communication manager.
 695
 696        This method initializes and runs the asynchronous event loop, handling Windows-specific
 697        event loop policy if needed. _async_run already retries on connection failures
 698        (Exception) internally, but anything that escapes that inner retry loop -- a
 699        BaseException such as a CancelledError/BaseExceptionGroup surfaced by the TaskGroup,
 700        or a failure before the inner loop even starts -- is caught here. In that case the
 701        whole event loop is torn down and rebuilt from scratch after a reconnect delay, so the
 702        background thread keeps trying to serve the manager instead of dying silently.
 703
 704        Retries are unbounded: there is no maximum retry count or backoff cap, so the thread
 705        keeps restarting the event loop, forever, at a fixed reconnect_interval cadence, for as
 706        long as the manager is enabled. As soon as an attempt fails, ``_async_loop`` is reset
 707        to ``None`` and the connection status is republished (DISCONNECTED, then RECONNECTING
 708        once the retry delay has elapsed) so that other threads calling start()/stop()/
 709        subscribe()/publish_its_message()/get_its_message_received() during the retry window
 710        see "loop not running" immediately, rather than a stale reference to the event loop
 711        that just crashed. Both resets of ``_async_loop`` go through ``_set_async_loop()``
 712        (backed by ``_state_lock``) so that callers on other threads observe the ``None``
 713        transition atomically together with the ``_async_thread.is_alive()`` check they
 714        perform alongside it; likewise, every read of ``_async_thread_enable`` here goes
 715        through ``_is_thread_enabled()`` rather than reading the attribute directly. The
 716        thread only stops retrying, and releases its state via ``finally``, once ``stop()``
 717        has cleared ``_async_thread_enable`` (via ``_begin_stop()``).
 718
 719        Returns:
 720            None: The method runs for the background thread lifetime,
 721            restarting the event loop on failure as a side effect.
 722
 723        Complexity:
 724            - Time: O(1) to select the loop factory and start each runner attempt; the
 725              runner then blocks for the lifetime of _async_run, and the whole cycle repeats
 726              on failure, without limit, while the thread stays enabled.
 727            - Space: O(1), no additional storage is required.
 728        """
 729        if self._logger.isEnabledFor(level=logging.INFO):
 730            self._logger.info(msg="Thread async start execution")
 731        loop_factory = (
 732            asyncio.SelectorEventLoop
 733            if (sys.platform == "win32") or (os.name.lower() == "nt")
 734            else None
 735        )
 736        try:
 737            while self._is_thread_enabled():
 738                try:
 739                    with Runner(loop_factory=loop_factory) as runner:
 740                        runner.run(coro=self._async_run())
 741                except BaseException:
 742                    self._set_async_loop(None)
 743                    self._set_connection_status(status=ConnectionStatus.DISCONNECTED)
 744                    if self._logger.isEnabledFor(level=logging.ERROR):
 745                        self._logger.exception(
 746                            msg="Unhandled exception escaped the async event loop"
 747                        )
 748                    if not self._is_thread_enabled():
 749                        break
 750                    time_sleep(self._params.reconnect_interval)
 751                    if self._logger.isEnabledFor(level=logging.INFO):
 752                        self._logger.info(
 753                            msg=f"Restarting async event loop after {self._params.reconnect_interval}"
 754                        )
 755                    self._set_connection_status(status=ConnectionStatus.RECONNECTING)
 756                    continue
 757                break
 758        finally:
 759            self._set_async_loop(None)
 760            self._set_connection_status(status=ConnectionStatus.DISCONNECTED)
 761            if self._logger.isEnabledFor(level=logging.INFO):
 762                self._logger.info(msg="Thread async execution end")

 816    def _get_active_loop(self) -> AbstractEventLoop:
 817        """Atomically snapshot and validate the running event loop.
 818
 819        Reads ``_async_loop`` and ``_async_thread.is_alive()`` together under
 820        ``_state_lock`` so the two checks reflect a single consistent instant,

 826        Returns:
 827            AbstractEventLoop: The currently running background event loop.

 831                is not alive.

 834            - Time: O(1), a single lock-protected read of two attributes.
 835            - Space: O(1), no additional storage is required.

 838            loop = self._async_loop
 839            thread_alive = self._async_thread.is_alive()

 841            raise StepLibError("Async loop is not running")
 842        if not thread_alive:

 902    def start(self) -> None:
 903        """Start the async thread and wait for the async loop. Start the asynchronous
 904        thread and wait for initialization of the event loop. The method ensures that
 905        only one thread and loop are running at a time.
 906
 907        Note:
 908            The initial "not already running" check is performed atomically by
 909            ``_begin_start()`` (backed by ``_state_lock``) to avoid racing with a
 910            concurrent stop() or with the background thread publishing
 911            ``_async_loop``. The subsequent readiness poll goes through
 912            ``_is_async_loop_ready()``, which re-acquires the lock briefly on each
 913            iteration instead of holding it for the whole wait, so it cannot block
 914            the background thread from publishing the loop.
 915            Once the subscribe/receive loop is ready, the publish worker pool is
 916            started and, once that succeeds, the dedicated health-check thread is
 917            started. If the pool fails to start, the already-started background
 918            thread is unwound via ``stop()`` before the error is re-raised, so no
 919            orphaned thread survives a failed ``start()``.
 920
 921        Returns:
 922            None: The background thread, publish worker pool, and
 923            health-check thread are all running when this returns without
 924            raising.
 925
 926        Raises:
 927            StepLibError: If async loop is already running or async thread is already
 928                alive, or if the publish worker pool fails to start (a worker did not
 929                become ready in time, or no free port could be found).
 930
 931        Complexity:
 932            - Time: O(1) amortized for the subscribe/receive thread startup; O(w),
 933              where w is ``publish_worker_count``, for starting the publish worker
 934              pool.
 935            - Space: O(w), for the publish worker pool's per-worker bookkeeping.
 936        """
 937        self._begin_start()
 938        self._async_thread.start()
 939        while not self._is_async_loop_ready():
 940            if not self._async_thread.is_alive():
 941                raise StepLibError("Async thread died before event loop was ready")
 942            time_sleep(0.1)
 943        try:
 944            self._worker_pool.start()
 945        except Exception:
 946            # Unwind the already-started background thread so no orphaned thread
 947            # survives a failed start(); self._health_check_thread is only started
 948            # below, once the pool itself is confirmed up, so stop() finds it never
 949            # started and safely skips joining it.
 950            self.stop()
 951            raise
 952        self._health_check_thread.start()

 954    def stop(self) -> None:
 955        """Stop the asynchronous communication thread. Stops the running asynchronous
 956        thread by setting the enable flag to False and sending an exit command through
 957        the queue. Waits for every already-queued command (including the exit command)
 958        to be fully processed, then waits for thread completion before clearing the
 959        async loop reference.
 960
 961        Note:
 962            The loop/thread-alive check, the capture of the loop reference used
 963            for dispatch, and the ``_async_thread_enable`` write are performed
 964            atomically by ``_begin_stop()`` (backed by ``_state_lock``), so a
 965            concurrent crash cannot leave this method holding a half-updated
 966            reference. The lock is released before the blocking
 967            ``run_coroutine_threadsafe(...).result()`` calls and the thread join, so
 968            those I/O waits are not serialized against other lock users. Each
 969            ``.result()`` call is bounded by ``self._params.timeout`` as a
 970            defense-in-depth safeguard: ``_async_run`` already drains any
 971            leftover queue items before returning so these calls should
 972            complete promptly on their own, but the timeout ensures ``stop()``
 973            fails loudly rather than blocking forever if some other, unforeseen
 974            interleaving still leaves them pending.
 975            The health-check thread is stopped and joined first, before any of the
 976            above, so no further ``check_health()`` call can race with the teardown
 977            that follows; the publish worker pool is always closed in a ``finally``
 978            block, so it is torn down even if the subscribe/receive shutdown sequence
 979            above raises.
 980
 981        Raises:
 982            StepLibError: If async loop is not running or async thread is not alive,
 983                or if the async loop does not process the stop command within
 984                ``self._params.timeout`` seconds.
 985
 986        Returns:
 987            None: The background thread and publish worker pool are
 988            stopped as a side effect before this returns.
 989
 990        Complexity:
 991            - Time: O(q), where q is the number of commands already queued in
 992              _incoming_queue at the time stop() is called (bounded by
 993              max_incoming_queue_rooms), to drain them before the exit command is
 994              processed; the subsequent thread join then blocks for a bounded shutdown
 995              delay.
 996            - Space: O(1), no additional storage is required.
 997        """
 998        loop = self._begin_stop()
 999        if self._logger.isEnabledFor(level=logging.INFO):
1000            self._logger.info(msg="Command: thread async stop execution")
1001        self._health_check_stop_event.set()
1002        if self._health_check_thread.ident is not None:
1003            self._health_check_thread.join()
1004        try:
1005            try:
1006                asyncio_run_coroutine_threadsafe(
1007                    coro=self._incoming_queue.put(
1008                        item=SyncComManager.ExitThreadsCommand()
1009                    ),
1010                    loop=loop,
1011                ).result(timeout=self._params.timeout)
1012                asyncio_run_coroutine_threadsafe(
1013                    coro=self._incoming_queue.join(), loop=loop
1014                ).result(timeout=self._params.timeout)
1015            except TimeoutError as error:
1016                raise StepLibError(
1017                    "Timed out waiting for the async loop to process the stop command"
1018                ) from error
1019            self._async_thread.join()
1020            self._set_async_loop(None)
1021        finally:
1022            self._worker_pool.close()

1025        """Periodically check the publish worker pool's health, restarting any

1027
1028        Runs on its own dedicated OS thread (``_health_check_thread``),

1176        """Publishes an ITS message to the network.
1177
1178        This method is fully synchronous: it builds a ``PublishEnvelope`` from the
1179        given domain objects and sends it directly to the publish worker pool's ZMQ
1180        ``PUSH`` socket on the caller's own thread (no dispatch through the
1181        subscribe/receive event loop). The pool's own internal locking makes this
1182        safe to call concurrently from multiple threads, and from the periodic
1183        health-check thread's restarts, without any locking needed at this level.
1184
1185        Args:
1186            message (FacilityMessage): The ITS message to be published.
1187            address (GeoNetworkAddress): The network address for the message.
1188            current_position (GpsLocation): The current GPS position of the sender.
1189            is_station_mobile (bool, optional): Indicates if the station is mobile.
1190            Defaults to True.
1191
1192        Raises:
1193            StepLibError: If the publish worker pool is not running, or the message
1194                is not one of the supported FacilityMessage subclasses.
1195            StepLibBackpressureError: If every worker's send pipe has reached its
1196                configured high-water mark (``publish_hwm``).
1197
1198        Returns:
1199            None: The envelope is sent to the publish worker pool as a
1200            side effect; nothing is returned to the caller.
1201
1202        Complexity:
1203            - Time: O(n), where n is the number of fields in the message, to build
1204              and JSON-encode the envelope; the socket send itself is O(1).
1205            - Space: O(n), where n is the number of fields in the message, for the
1206              envelope and its encoded JSON payload.
1207        """
1208        if not self._worker_pool.is_running:
1209            raise StepLibError("Publish worker pool is not running")
1210        envelope = PublishEnvelope.from_domain_objects(
1211            message=message,
1212            address=address,
1213            current_position=current_position,
1214            is_station_mobile=is_station_mobile,
1215        )
1216        if self._logger.isEnabledFor(level=logging.DEBUG):
1217            self._logger.debug(msg=f"Command: publish {message}")
1218        try:
1219            self._worker_pool.send(envelope=envelope)
1220        except zmq.Again as error:
1221            raise StepLibBackpressureError(
1222                "Every publish worker's send pipe is full"
1223            ) from error
1224        if self._logger.isEnabledFor(level=logging.DEBUG):
1225            self._logger.debug(msg=f"Message {message.its_time} published")

1254    def install_default_signal_handlers(
1255        self, signals: Sequence[int] = (signal.SIGTERM,)
1256    ) -> None:
1257        """Install signal handlers that call ``self.stop()``, the parent-side
1258        counterpart to the worker-side SIGTERM bridge.
1259
1260        Opt-in: never wired into ``start()``/``stop()`` automatically. Must
1261        be called from the main thread of the main interpreter -
1262        ``signal.signal()``'s own hard requirement, enforced by the stdlib
1263        itself, not by step_lib. The installed handler only calls
1264        ``self.stop()``; it does not call ``sys.exit()`` or otherwise
1265        terminate the process, since presuming the whole application should
1266        exit is too strong an assumption for a library method to make on
1267        the caller's behalf - the caller remains responsible for noticing
1268        the manager has stopped (e.g. via ``connection_status``) and
1269        exiting its own main loop if that is the desired behavior.
1270
1271        The default ``signals`` tuple contains only ``SIGTERM``, not
1272        ``SIGINT``: Python already installs its own default ``SIGINT``
1273        handler (raising ``KeyboardInterrupt``), which already propagates
1274        cleanly through a ``with SyncComManager(...):`` block via ordinary
1275        exception unwinding, so overriding it by default would silently
1276        change already-working behavior.
1277
1278        Args:
1279            signals (Sequence[int]): The signals to install the handler
1280                for. Defaults to ``(signal.SIGTERM,)``.
1281
1282        Returns:
1283            None: The signal handlers are installed as a side effect;
1284            nothing is returned.
1285
1286        Raises:
1287            ValueError: If called from any thread other than the main
1288                thread of the main interpreter (raised by ``signal.signal()``
1289                itself).
1290
1291        Complexity:
1292            - Time: O(len(signals)), one ``signal.signal()`` call per
1293              signal.
1294            - Space: O(1), no additional storage is required.
1295        """
1296        for one_signal in signals:
1297            signal.signal(one_signal, lambda *_args: self.stop())

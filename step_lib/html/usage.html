STEP Connection Guide

This guide explain how to use the STEP Library to communicate to STEP broker using both asynchronous (Coroutine) and synchronous (Non-blocking) approaches.

Prerequisites

Before using STEP Library, ensure you have:

  • Python 3.11 or higher

  • STEP Library installed

  • Valid STEP broker credentials

Basic Concepts

The main features of the STEP Library include:

  1. Publish ITS Etsi messages to the broker (STEP).

  2. Subscribe to the specific topics in order to receive ITS Etsi messages.

The library supports CAM, CPM and DENM messages.

The library provides two main approaches for MQTT communication:

  1. Synchronous (Non-blocking) using SyncComManager

  2. Asynchronous (Coroutine) using AsyncComManager

It is recommended to provide a cache folder during the initialization of the library for performance reason. This folder is used to store the ASN.1 information used during the parsing of the messages. No any part of the message is stored in the cache folder.

The information in the message is encapsulated and passed to the library using:

  1. The class

  2. A dictionary

  3. A JSON string

The communication session is managed with or without the context manager.

Note

The station_id field can be None if the library is able to send messages created by different stations. If station_id is None, it isn’t used; otherwise, the library discards received messages carrying station_id (the client’s own echoes) and replaces the station id of the published messages with it. The override is performed by AsyncComManager.publish_its_message (called by the publish worker of SyncComManager), before serialization and before the position data topic is built; FacilitySerializer encodes the message’s station id as is.

Note

The GenericMessageType.POSITION_DATA entry of publish_topics_params is optional and enables the STEP position data feed: every published CAM is also projected onto a PositionDataV1 record and published as JSON on <header_topic>/<station_id>, with no geohash levels (geohash_precision is ignored for this entry). Without the entry, the CAM is published alone. See Position Data MQTT Topic.

Note

SyncComManager publishes through a pool of worker processes rather than on the calling thread. The publish_worker_* and publish_* fields tune that pool:

  • publish_worker_count: number of publish worker processes to spawn.

  • publish_worker_startup_timeout: seconds to wait for a spawned worker to signal readiness before treating it as failed.

  • publish_hwm: high-water mark for the worker pool’s ZMQ PUSH socket.

  • publish_health_check_interval: seconds between periodic worker health checks.

  • publish_heartbeat_interval: seconds between worker heartbeat refreshes.

  • publish_heartbeat_timeout: seconds of heartbeat staleness after which a worker is considered blocked; keep it well above the time a worker needs to compile the ASN.1 grammar on its first connect.

  • publish_parent_watchdog_interval: seconds between a worker’s checks that its parent process is still alive.

  • publish_graceful_shutdown_timeout: bound of each of the two phases of a graceful stop: handing the queued messages to the workers, then letting every worker publish the messages it already received (drain) before exiting. stop() can therefore wait about twice this value before escalating to a forceful termination. If this manager runs inside a container/service manager, keep that (plus publish_forceful_join_timeout) safely below the manager’s own outer shutdown grace period.

  • publish_forceful_join_timeout: seconds to wait for a forcefully-terminated worker to exit before escalating further.

  • publish_max_connect_attempts: consecutive failed MQTT connect attempts a worker tolerates before giving up and exiting, to be picked up and restarted by the pool’s health check, rather than retrying forever. A worker whose restart fails is retried after 1 s, then after 2, 4, … seconds, up to 60 s between attempts.

  • leap_seconds_source, leap_seconds_urls, leap_seconds_allow_download: configuration of the LeapSeconds singleton of each publish worker process (see Time scale and leap seconds).

Every field must be picklable, since the parameters are sent to the worker processes: an unpicklable value (e.g. a queue_type defined inside a function) raises ValueError naming the field.

Time scale and leap seconds

Since step_cloud_schemas 3.0.0 every ITS timestamp on the wire is TAI (5 seconds ahead of UTC since the ITS epoch), while the ISO strings of the models stay UTC. Every station of a deployment must therefore move to step_cloud_schemas 3.0.0 and step_lib 3.0.0 together: a mixed deployment reads each other’s times 5 s apart.

The leap-second table is a LeapSeconds singleton per process. The application configures the singleton of its own process (the one running SyncComManager or AsyncComManager) before any ItsTime use, e.g.:

from step_cloud_schemas import LeapSeconds

LeapSeconds(allow_download=False)

The publish worker processes do not inherit it: each one creates its own from the leap_seconds_source, leap_seconds_urls and leap_seconds_allow_download parameters, as the very first thing it does.

Delivery and time notes

  • At-least-once publishing: a message whose publish fails with an MQTT transport error is published again after the worker reconnects, up to 3 attempts, so a subscriber can receive it twice. The pending message lives only in the worker’s memory.

  • Graceful stop: stop() publishes every message already handed to publish_its_message() before returning, within the time budget above.

  • Sequence numbers: the GeoNetworking sequence number is assigned by the pool, so the worker processes never reuse one; it starts at a random value.

  • Times rebuilt on reception: a CAM carries only generationDeltaTime (TAI ms modulo 65536), and the GeoNetworking position vector TST (TAI ms modulo 2^32). Both are rebuilt against the time of decoding, so creationTime is only right when a CAM is decoded within +/-32.7 s of its generation (+/-24.8 days for TST); replaying an old capture shifts the times.

  • Standard CPM: only the custom CPM layout (CpmMessageV1 with is_custom=True, BTP port 1009) is supported. Publishing a standard CPM raises StepLibUnsupportedMessageError at once; a standard CPM received on port 2009 is dropped with an INFO record.

Note

Subscriptions always use noLocal=False, which MQTT v5 requires for shared subscriptions: a $share/<group>/<filter> topic is passed to the broker unchanged, and the broker then delivers each message to one member of the group. For example, several processes can split the CAM traffic between them with:

client.subscribe(topics=["$share/cam_readers/v2x/cam/#"], max_qos=MqttQoS.QOS_1)

The messages a manager publishes on a topic it is subscribed to are received back, unless station_id is set: the receiver then drops them as echoes. With station_id=None subscribe() logs this at INFO.

subscribe() returns once the command is queued; the SUBACK is logged later by the background thread: INFO when the requested QoS was granted, WARNING when the broker granted a lower QoS (the subscription works, with weaker delivery guarantees), ERROR with the reason (e.g. Not authorized) when it was refused.

def _async_com_manager_create(
    instance_name: str,
    station_id: int | None,
    config: StepBrokerConfig,
    mqtt_credential: MqttCredential,
    logger: Logger,
) -> AsyncComManager:
    """Create and configure an AsyncComManager instance for MQTT communication.

    This function initializes an AsyncComManager with all necessary parameters derived from
    a StepBrokerConfig object, including TLS settings, connection parameters, and publish topics.

    Args:
        instance_name (str): Unique identifier for this communication manager instance.
        station_id (int | None): Optional station identifier for the communication instance.
        config (StepBrokerConfig): Configuration object containing MQTT client, protocol, and
            cache settings.
        mqtt_credential (MqttCredential): The MQTT credential containing connection details for the broker.
        logger (Logger): Logger instance for logging communication events and errors.

    Returns:
        AsyncComManager: A configured AsyncComManager instance ready for MQTT communication.

    Note:
        - TLS parameters are only configured if ``config.mqttClient.sslEnable`` is True.
        - The function uses TLSv1.2 protocol when SSL is enabled.
        - Certificate verification mode depends on ``config.mqttClient.sslVerifyServerCert``.
        - Publish topics are converted from config format to PublishTopicParams if provided.

    Complexity:
        - Time: O(p), where p is the number of entries in
          config.mqttProtocol.publishTopics (O(1) when publishTopics is None).
        - Space: O(p), for the list of PublishTopicParams built from the configuration.
    """
    tls_params: TLSParameters | None = None
    if config.mqttClient.sslEnable:
        tls_params = TLSParameters(
            ca_certs=config.mqttClient.sslCaCertsFile,
            certfile=config.mqttClient.sslClientCertFile,
            keyfile=config.mqttClient.sslClientKeyFile,
            cert_reqs=(
                VerifyMode.CERT_REQUIRED
                if config.mqttClient.sslVerifyServerCert
                else VerifyMode.CERT_NONE
            ),
            tls_version=ssl.PROTOCOL_TLSv1_2,
            ciphers=None,
            keyfile_password=config.mqttClient.sslClientKeyFilePassword,
        )
    async_com_manager_params = AsyncComManagerParams(
        instance_name=instance_name,
        host=mqtt_credential.url,
        port=mqtt_credential.port,
        username=mqtt_credential.username or "",
        password=mqtt_credential.password or "",
        timeout=config.mqttProtocol.timeout,
        station_id=station_id,
        keepalive=config.mqttProtocol.keepalive,
        bind_address="",
        bind_port=0,
        clean_start=config.mqttProtocol.cleanStart,
        queue_type=None,
        max_queued_incoming_messages=config.mqttProtocol.maxQueuedIncomingMessages,
        max_queued_outgoing_messages=config.mqttProtocol.maxQueuedOutgoingMessages,
        max_inflight_messages=config.mqttProtocol.maxInflightMessages,
        max_concurrent_outgoing_calls=config.mqttProtocol.maxConcurrentOutgoingCalls,
        tls_params=tls_params,
        proxy=None,
        socket_options=None,
        session_expiry=config.mqttProtocol.sessionExpiry,
        receive_maximum=config.mqttProtocol.receiveMaximum,
        maximum_packet_size=config.mqttProtocol.maximumPacketSize,
        topic_alias_maximum=0,
        publish_topics_params=(
            [
                PublishTopicParams(
                    message_type=MessageType.orm_to_enum(
                        message_type=topic.messageType
                    ),
                    header_topic=topic.headerTopic,
                    geohash_precision=topic.geohashPrecision,
                    qos=MqttQoS(topic.qos),
                )
                for topic in config.mqttProtocol.publishTopics
            ]
            if config.mqttProtocol.publishTopics is not None
            else None
        ),
        cache_dir=config.cacheDir,
    )
    return AsyncComManager(params=async_com_manager_params, logger=logger)

async def _receive_messages(client: AsyncComManager, logger: Logger) -> None:
    """Asynchronously receives and logs messages from a communication manager.

    This function continuously listens for incoming messages from the provided
    AsyncComManager client and logs them with their QoS level, topic, and payload content.

    Args:
        client (AsyncComManager): The asynchronous communication manager client
            used to receive messages.
        logger (Logger): The logger instance used to log received messages.

    Returns:
        None: This function does not return any value.

    Note:
        This is a long-running coroutine that will continue processing messages
        until canceled or until the client stops yielding messages.

    Complexity:
        - Time: O(k), where k is the number of messages received before the
          coroutine is canceled or the client stops yielding messages.
        - Space: O(1), each message is logged as it arrives and not retained.
    """
    async for message in client.its_messages:
        if logger.isEnabledFor(level=logging.INFO):
            logger.info(
                msg=f"Message(qos:{message.qos},topic:{message.topic}): {message.its_payload}"
            )


async def _subscribe_execution(
    client: AsyncComManager, config: MqttProtocolConfig, logger: Logger
) -> None:
    """Subscribe to a list of topics with specified MQTT options.

    This method subscribes to a list of topics specified in the configuration
    with the following MQTT options:

        - QoS level from config
        - No local messages disabled (noLocal=False)
        - Do not retain as published (retainAsPublished=False)
        - Do not send retained messages (retainHandling=RETAIN_DO_NOT_SEND)

    Args:
        client (AsyncComManager): The asynchronous communication manager client
            used to perform the subscription.
        config (MqttProtocolConfig): Configuration object containing subscription topics
            and QoS settings.
        logger (Logger): The logger instance used for logging subscription results.

    Raises:
        StepLibError: If subscription fails or QoS level doesn't match the configured
            one.

    Returns:
        None: This function does not return a value.

    Complexity:
        - Time: O(t), where t is the number of entries in config.subscriptionTopics
          (O(1) when subscriptionTopics is None).
        - Space: O(t), for the list of subscription tuples built from the configuration.
    """
    if config.subscriptionTopics is not None:
        sub_results = await client.subscribe(
            topic=[
                (
                    topic_param.topic,
                    SubscribeOptions(
                        qos=config.maxSubscriptionQos,
                        noLocal=False,
                        retainAsPublished=False,
                        retainHandling=SubscribeOptions.RETAIN_DO_NOT_SEND,
                    ),
                )
                for topic_param in config.subscriptionTopics
            ]
        )
        if len(sub_results) != len(config.subscriptionTopics):
            raise StepLibError(
                f"Subscription results {len(sub_results)} do not match the number "
                f"of topics {len(config.subscriptionTopics)}."
            )
        for topic_param, result in zip(
            config.subscriptionTopics, sub_results, strict=True
        ):
            if result != config.maxSubscriptionQos:
                raise StepLibError(
                    f"Failed to subscribe to {topic_param.topic}: {result}"
                )
            if logger.isEnabledFor(level=logging.INFO):
                logger.info(msg=f"Subscribed to {topic_param.topic}: {result}")

def _subscribe_execution(client: SyncComManager, config: MqttProtocolConfig) -> None:
    """Subscribe to MQTT topics specified in the configuration.

    This function subscribes to all topics defined in the config.subscriptionTopics list
    with a single ``client.subscribe`` call, using the maximum QoS level specified in the
    configuration. Nothing is done when ``config.subscriptionTopics`` is None.

    Args:
        client (SyncComManager): The MQTT client manager used to subscribe to topics.
        config (MqttProtocolConfig): Configuration object containing subscription topics
            and maximum QoS level for subscriptions.

    Returns:
        None: This function does not return a value.

    Note:
        - Any validation of the subscription outcome, and any error raised on
          failure, is delegated to ``SyncComManager.subscribe``; this function
          neither raises nor logs by itself.
        - The MQTT subscription options are chosen internally by
          ``SyncComManager.subscribe``; only the topics and ``max_qos`` are
          passed from here.

    Complexity:
        - Time: O(t), where t is the number of entries in config.subscriptionTopics
          (O(1) when subscriptionTopics is None).
        - Space: O(t), for the list of topic strings built from the configuration.
    """
    if config.subscriptionTopics is not None:
        client.subscribe(
            topics=[topic_param.topic for topic_param in config.subscriptionTopics],
            max_qos=MqttQoS(config.maxSubscriptionQos),
        )


def _publish_message(
    *,
    client: SyncComManager,
    message: FacilityMessage,
    address: GeoNetworkAddress,
    current_position: GpsLocation,
    is_station_mobile: bool,
    logger: Logger,
    message_log: str,
) -> None:
    """Publish a single ITS message through the given client and log the action.

    A ``StepLibError`` raised by the publish call is caught and logged at WARNING
    level instead of being propagated.

    Args:
        client (SyncComManager): The MQTT client manager used to publish the message.
        message (FacilityMessage): The ITS message object to be published.
        address (GeoNetworkAddress): The GeoNetworking address used as the destination.
        current_position (GpsLocation): The current GPS location of the sending station.
        is_station_mobile (bool): Indicates if the sending station is mobile.
        logger (Logger): Logger instance used to record the message sent, at INFO level.
        message_log (str): A string describing the message for logging purposes.

    Returns:
        None: This function does not return a value.

    Complexity:
        - Time: O(1), dominated by the single delegated
          ``client.publish_its_message`` call for one message.
        - Space: O(1), no additional data structures are built beyond the
          message already provided.
    """
    try:
        client.publish_its_message(
            message=message,
            address=address,
            current_position=current_position,
            is_station_mobile=is_station_mobile,
        )
        if logger.isEnabledFor(level=logging.INFO):
            logger.info(msg=f"Message sent: {message_log}, {message}")
    except StepLibError as e:
        if logger.isEnabledFor(level=logging.WARNING):
            logger.warning(msg=f"Failed to send message: {e}")


def _publish_messages(
    client: SyncComManager,
    current_position: GpsLocation,
    address: GeoNetworkAddress,
    logger: Logger,
) -> None:
    """Build and publish a fixed set of demo ITS messages through the given client.

    This function publishes hard-coded ITS messages in sequence: a CAM message
    built from an ORM object, a CAM message built from a dictionary representation,
    100 CPM messages built from an ORM object (one every 0.1 s, simulating 10 Hz,
    so the call blocks for about 10 seconds), and finally a DENM message built from
    an ORM object. Each message is sent via ``_publish_message`` using the provided
    position and address; a failed send is logged as a warning and does not stop
    the sequence.

    Args:
        client (SyncComManager): The MQTT client manager used to publish the messages.
        current_position (GpsLocation): The current GPS location of the sending station,
            attached to each published message.
        address (GeoNetworkAddress): The GeoNetworking address used as the destination
            for each published message.
        logger (Logger): Logger instance used to record each message sent, at INFO level.

    Returns:
        None: This function does not return a value.

    Complexity:
        - Time: O(1), a fixed number (103) of hard-coded messages is built and
          published, including a fixed 100 iterations of 0.1 s sleep.
        - Space: O(1), each message object is a single fixed-size object graph.
    """
    # CAM message as ORM
    cam_message = _create_cam_data()
    _publish_message(
        client=client,
        message=CamMessageV1(message_param=cam_message),
        address=address,
        current_position=current_position,
        is_station_mobile=True,
        logger=logger,
        message_log="CAM message ORM",
    )
    # CAM message as DICT
    cam_message = CamDataV1(**_create_cam_dict_data())
    _publish_message(
        client=client,
        message=CamMessageV1(message_param=cam_message),
        address=address,
        current_position=current_position,
        is_station_mobile=True,
        logger=logger,
        message_log="CAM message DICT",
    )
    for _ in range(100):
        # CPM message as ORM
        cpm_message = _create_cpm_data()
        _publish_message(
            client=client,
            message=CpmMessageV1(message_param=cpm_message),
            address=address,
            current_position=current_position,
            is_station_mobile=True,
            logger=logger,
            message_log="CPM message ORM",
        )
        # Simulate 10 hz
        time_sleep(0.1)
    # DENM message as ORM
    denm_message = _create_denm_data()
    _publish_message(
        client=client,
        message=DenmMessageV1(message_param=denm_message),
        address=address,
        current_position=current_position,
        is_station_mobile=True,
        logger=logger,
        message_log="DENM message ORM",
    )

            3. 100 CPM messages as ORM objects (10 Hz)
            4. DENM message as ORM object

        - Logs all received ITS messages
        - Ensures proper cleanup by stopping the client in the finally block

    Complexity:
        - Time: O(p + t + r), where p is the number of publish topics and t the number
          of subscription topics in config (client setup), and r is the number of

        time=ItsTime(),

        longitude=sender_longitude,
        accuracy=None,

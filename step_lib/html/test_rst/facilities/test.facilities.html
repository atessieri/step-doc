test.facilities package

Test Suite for ITS Facility Layer Message Implementations.

This package contains comprehensive unit tests for Intelligent Transportation Systems (ITS) facility layer message implementations in the step_lib library. The tests verify proper handling, validation, and transformation of vehicular communication messages used in cooperative ITS applications.

Overview:

The facilities test suite validates message classes that implement ITS-G5 standards for vehicle-to-vehicle (V2V) and vehicle-to-infrastructure (V2I) communications. Each test module ensures reliable message processing across different data formats and operations.

Test Modules:
test_cam_message_v1.py:

Comprehensive test suite for Cooperative Awareness Message (CAM) version 1 implementation. CAM messages are periodically broadcasted by ITS stations to share position, motion state, and basic attributes.

Key test areas:

  • Message initialization and validation

  • Format conversions (ASN.1, ORM, dict, JSON)

  • Message properties and attributes access

  • Station ID modifications

  • Error handling for invalid inputs

  • Message source identification

  • Coordinate extraction from reference positions

  • Schema validation

test_denm_message_v1.py:

Complete test coverage for Decentralized Environmental Notification Message (DENM) version 1 implementation. DENM messages are event-triggered messages used to alert about road hazards, traffic conditions, and emergency situations.

Key test areas:

  • Message initialization with management containers

  • Data format conversions (ASN.1, ORM, Dictionary, JSON)

  • Message property access and manipulation

  • Station ID modifications and action ID handling

  • Error handling for invalid operations

  • Situation and location container validation

  • Pre-crash container processing

Message Format Support:
ASN.1 Format:

Binary representation following ETSI standards with proper encoding rules for over-the-air transmission.

ORM Format:

Object-Relational Mapping using Pydantic models from step_cloud_schemas for type-safe message handling and validation.

Dictionary Format:

Native Python dictionary representation for easy manipulation and serialization.

JSON Format:

JSON string serialization for web services, APIs, and human-readable storage.

Test Fixtures:

Each test module provides standardized fixtures for consistent testing:

message_asn:

ASN.1 structured dictionary with proper field encoding following ETSI specifications.

message_orm:

Fully populated ORM objects (CamDataV1, DenmDataV1) with valid test data.

message_dict:

Python dictionary representations with all required and optional fields.

message_json:

JSON string representations for serialization testing.

Test Coverage Areas:
Initialization:

  • Construction with None, empty, and fully populated messages

  • Proper ITS time extraction and validation

  • Station information handling

Conversions:

  • Bidirectional transformations between all supported formats

  • Data integrity preservation during conversions

  • Schema validation after transformations

Properties:

  • Message type identification (CAM_PDU, DENM_PDU)

  • Station ID extraction and modification

  • Reference position access and coordinate extraction

  • Schema identifier retrieval

Validation:

  • Invalid input rejection with proper exceptions

  • Missing data detection

  • Type checking and field validation

  • Schema compliance verification

Operations:

  • Station ID modification (change_station_id)

  • Message presence checking (is_message_present)

  • Equality comparison between messages

  • String representation generation

Testing Framework:
pytest:

Core testing framework with parameterized tests and fixtures.

pytest.fixtures:

Reusable test data across multiple test cases ensuring consistency.

pytest.mark.parametrize:

Testing multiple input scenarios with single test functions.

pytest.raises:

Exception handling validation for error cases.

Example

Run all facility layer tests:

pytest test/facilities/

Run CAM message tests only:

pytest test/facilities/test_cam_message_v1.py

Run DENM message tests with verbose output:

pytest -vv test/facilities/test_denm_message_v1.py

Run specific test class:

pytest test/facilities/test_cam_message_v1.py::TestCamMessageV1

Run with coverage for facilities module:

pytest --cov=step_lib.facilities test/facilities/

Note

These tests rely on the step_cloud_schemas package for ORM models and schema definitions. All tests follow strict type checking and validation to ensure message integrity throughout the system’s processing pipeline.

The test suite uses ruff for linting with specific ignores (S101 for assert statements, PLR2004 for magic values) as these are acceptable in test code.

Complexity:

  • - Time – O(1) per test, since each test constructs a fixed, small number of objects and performs a constant number of assertions.

  • - Space – O(1) per test, since only a fixed number of objects and fixtures are held.

========
Commands
========

The commands are available in the library to interact with the STEP MQTT broker using ITS 
packets and to decode or to encode the ITS packets. 

The following the complete list.

-------
Version
-------

The command is designed to print the version of the library.

.. code-block:: bash

   $step_lib -v

Example:

.. code-block:: bash

    $step_lib -v
    step_lib version: 1.7.8

---------------------------
Decode ITS facility packets
---------------------------

The command is designed to decode a complete ITS message (GeoNetworking + BTP + facility
layers) from its binary (hex format) representation and print the decoded message to the
console.

.. code-block:: bash

   $step_lib -d <hex_string>

The parameters are:

- <hex_string> is the ITS message in hex format.

.. note::
    <hex_string> is the only required parameter. The facility message type (CAM, CPM or
    DENM) does not need to be specified separately: it is determined automatically from
    the BTP destination port embedded in the message.

Example (the hex string below is the exact output of the ``-e`` example further down,
so decoding it reproduces the same JSON message that was encoded):

    and is not reproduced verbatim here.

---------------------------
Encode ITS facility packets
---------------------------

The command is designed to encode a JSON-formatted ITS message (matching the
``ItsMessageRoot`` schema) into its binary (hex format) representation, using a fixed
road-side-unit address for the GeoNetworking/BTP layers.

.. code-block:: bash

   $step_lib -e <json_message>

The parameters are:

- <json_message> is the ITS message as a JSON string.

Example:

.. code-block:: bash

    $step_lib -e '{"type": "DENM", "stationId": 19911991, "managementContainer": {"actionId": {"originatingStationId": 19911991, "sequenceNumber": 987}, "detectionTime": "2037-12-10T21:33:57.691Z", "referenceTime": "2037-12-10T21:33:57.691Z", "termination": null, "eventPosition": {"latitude": 41.9783821, "longitude": 12.4874982, "positionConfidence": {"semiMajorAxisLengthConfidence": 3.77, "semiMinorAxisLengthConfidence": 3.77, "semiMajorAxisOrientation": 0}, "altitude": {"value": 12.0, "confidence": 0.02}}, "awarenessDistance": 49, "trafficDirection": "allTrafficDirections", "validityDuration": 86400, "transmissionInterval": 500, "stationType": "moped", "referenceStationId": null, "referenceObjectId": null}, "situationContainer": {"informationQuality": 3, "eventType": "collisionRisk97"}, "locationContainer": {"eventSpeed": {"value": 130.0, "confidence": null}, "eventPositionHeading": {"value": 14.0, "confidence": null}, "roadType": null}, "preCrashContainer": null}'
    Encoded message (hex): 11004c0120400080003a010000000000bc000000075bcd156735d5341905648d077170e53fff0e111905648d077170e500c800000000000007d200000201012fd537c78097ea9b81ed9f2ce6ba8767cb39aea1dceaa4d8d72bb42e617917900018b5010546001f3030cc200d9647e08cfc00

-------------------
Set the log level
-------------------

The command is designed to control the verbosity of the logger used by the other
commands.

.. code-block:: bash

   $step_lib -l <log level> -d <hex_string>

The parameters are:

- <log level> is one of DEBUG, INFO, WARNING, ERROR, CRITICAL.

.. note::
    ``-l``/``--log-level`` only has an effect when combined with ``-d``/``--decode``
    or ``-e``/``--encode``, since those are the commands that use the logger. It
    cannot be combined with ``-v``/``--version``: argparse's ``version`` action
    prints the version and exits immediately, before the log level would ever be
    applied.

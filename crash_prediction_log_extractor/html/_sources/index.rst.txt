The **crash_prediction_log_extractor** package is a STEP utility that parses
``step_crash_prediction`` service logs and converts the scenario marker lines
they contain into structured JSON payloads, interactive HTML maps and
dashboards, and a GPX file.

Purpose
-------

The project provides a deterministic, file-based extraction workflow for
post-processing crash prediction runs. For every input log file it:

#. Reads the plain-text UTF-8 log file.
#. Parses every scenario block into one ``Session`` of a
   :ref:`CollectionSessions <collection_sessions_schema>` payload
   (``LogExtractor``).
#. Derives :ref:`CollectionActors <collection_actors_schema>`,
   :ref:`CollectionSequences <collection_sequences_schema>`, and
   :ref:`CollectionCheckpoints <collection_checkpoints_schema>` from the
   sessions (``DataRetriever``).
#. Writes the JSON payloads, the Folium maps (``InteractiveMap``), the Plotly
   dashboards (``InteractiveChart``), and the GPX tracks (``GpxBuilder``).

Key Features
------------

Marker-Based Parsing
~~~~~~~~~~~~~~~~~~~~

- **Scenario parsing**: Detects ``--Scenario start--`` / ``--Scenario end--``
  boundaries and the ``--Scenario t: <ISO8601>--`` time in mixed runtime log
  output, independently of the log level
- **Section parsing**: Parses the ``normalized real``, ``normalized
  forecasted``, and ``anomaly real`` section blocks
- **Crash parsing**: Extracts crash records with time, position, risk (1-7),
  and at least two distinct involved actors
- **Checkpoint parsing**: Collects ``--Checkpoint: <name>, timer: <ms>--``
  processing timings
- **Deterministic behavior**: Ignores non-marker lines and applies fixed
  finite-state parser transitions

Typed Data Model and Validation
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- **Strict payload models**: Frozen Pydantic models for sessions, actors,
  sequences, checkpoints, and the configuration, forbidding extra fields
- **Schema and example generation**: The CLI emits JSON schemas and example
  payloads of every model
- **Precision-aware serialization**: Coordinates are rounded to 7 decimals,
  speed, heading, and forecast errors to 2 decimals
- **Shared types**: ``TrafficParticipantType``, ``PositionType``, and
  ``LogConfig`` come from ``step_cloud_schemas``

Analysis Outputs
~~~~~~~~~~~~~~~~

- **Forecast sequences**: Each real position is paired with the positions
  forecasted for that instant by earlier sessions, with distance and heading
  errors
- **Interactive maps**: Folium maps of sessions and actors over the OSM road
  network, one selectable layer per road type
- **Dashboards**: Self-contained Plotly dashboards of forecast accuracy and of
  the elapsed time between processing checkpoints
- **GPX tracks**: One track per actor, compatible with step_publisher_pkl

Core Components
---------------

CLI Entry Point
~~~~~~~~~~~~~~~

The ``__main__.py`` module provides command parsing and execution routing. It
supports combined operations in a single run (schema generation, example
generation, and extraction), and returns explicit exit codes for success,
usage errors, unhandled exceptions, and user interruption.

Log Extractor
~~~~~~~~~~~~~

The ``LogExtractor`` class in ``log_extractor.py`` is the parser engine. It
uses regular expressions and the ``ParserScenarioState``,
``ParserSectionDataState``, and ``ParserCrashState`` finite-state machines to
build one ``Session`` per complete scenario with at least one actor.

Collection Models
~~~~~~~~~~~~~~~~~

The ``collection_sessions.py``, ``collection_actors.py``,
``collection_sequences.py``, and ``collection_checkpoints.py`` modules define
the versioned payloads and their JSON, schema, and example writers. The
``crash_prediction_log_extractor_config.py`` module defines the configuration
model and its schema/template writers.

Data Retriever
~~~~~~~~~~~~~~

The ``DataRetriever`` class in ``data_retriever.py`` regroups the sessions per
actor, builds the forecast sequences within the ``maxToleranceTime``
tolerance, and extracts the per-session checkpoints.

Renderers
~~~~~~~~~

- ``InteractiveMap`` (``interactive_map.py``): Folium maps of sessions and
  actors
- ``InteractiveChart`` (``interactive_chart.py``): Plotly distance/heading and
  performance dashboards
- ``GpxBuilder`` (``gpx_builder.py``): multi-track GPX file
- ``templates``: static HTML, CSS, and JavaScript assets of maps and
  dashboards

Dependencies
------------

Runtime Dependencies
~~~~~~~~~~~~~~~~~~~~

- ``pydantic`` for strict models and schema generation
- ``step_cloud_schemas`` for shared types, time/geodesic helpers, and logging
- ``osmnx`` and ``geopandas`` for OSM road networks
- ``folium`` and ``branca`` for interactive maps
- ``plotly`` for dashboards
- ``gpx`` for GPX output

Development Tooling
~~~~~~~~~~~~~~~~~~~

The project tooling includes ``pytest``, ``ruff``, ``mypy``, ``pyrefly``,
``pylint``, ``isort``, ``tox``, and Sphinx-based documentation generation.

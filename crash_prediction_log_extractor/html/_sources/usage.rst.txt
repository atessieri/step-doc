Crash Prediction Log Extractor Usage Guide
==========================================

Overview
--------

``crash_prediction_log_extractor`` is a command-line tool that parses
``step_crash_prediction`` log files and converts the scenario marker lines they
contain into:

* a :ref:`CollectionSessions <collection_sessions_schema>` payload, one session
  per scenario, with every actor's real and forecasted positions, the scenario
  crashes, and the processing checkpoints;
* the derived :ref:`CollectionActors <collection_actors_schema>`,
  :ref:`CollectionSequences <collection_sequences_schema>`, and
  :ref:`CollectionCheckpoints <collection_checkpoints_schema>` payloads;
* interactive Folium maps of sessions and actors over the OSM road network;
* Plotly dashboards of forecast accuracy and processing performance;
* a GPX file with one track per actor.

The executable command installed by the package is:

.. code-block:: bash

    crash_prediction_log_extractor


What the program does
---------------------

The extractor is marker-driven. It reads the log file line by line and reacts
only when one of the expected marker patterns is found anywhere in the line; it
is not filtered by log level, and non-marker lines are ignored. Each log line is
expected to look like::

    YYYY-MM-DD HH:MM:SS.mmm [LEVEL][pid=...][thread=...][module=...][function=...]: <marker>

A complete scenario block is expected in this order:

#. ``--Scenario start--``
#. ``--Scenario t: <ISO8601>--`` (scenario time, required)
#. three section data blocks, always in this order:

   * ``--Section normalized real start-- ... --Section normalized real end--``
   * ``--Section normalized forecasted start-- ... --Section normalized forecasted end--``
   * ``--Section anomaly real start-- ... --Section anomaly real end--``

#. crash section: ``--Section crash start-- ... --Section crash end--``
#. ``--Scenario end--``

``--Checkpoint: <name>, timer: <ms>--`` lines may be interleaved anywhere in the
scenario except inside individual crash records. Accepted names are the
``CheckpointType`` values (see the
:ref:`checkpoints schema <collection_checkpoints_schema>`); other names are
skipped with a warning.

Inside section data blocks, each actor line is followed by its points:

* Actor:
  ``--sid: <station_id>, oid: <object_id|None>, type: <TrafficParticipantType>, confidence: <0-100|None>--``
* Point:
  ``--t: <ISO8601>, p: (<lat>, <lon>), t: <PositionType>, s: <speed|None>, h: <heading|None>--``

Inside the crash section, each crash record is:

.. code-block:: text

    --Crash start--
    --Time: <ISO8601>, pos: (<lat>, <lon>), risk: <1-7>--
    --sid: ...--  (at least two distinct actors)
    --Crash end--

Full minimal scenario example::

    ... [INFO]...: --Scenario start--
    ... [INFO]...: --Scenario t: 2026-02-24T05:25:51.339Z--
    ... [INFO]...: --Checkpoint: scenario start, timer: 1000.000--
    ... [INFO]...: --Section normalized real start--
    ... [INFO]...: --sid: 37, oid: None, type: passengerCar, confidence: 90--
    ... [INFO]...: --t: 2026-02-24T05:25:51.339Z, p: (45.610087, 8.863476), t: GNSS, s: 0.00, h: 21.10--
    ... [INFO]...: --Section normalized real end--
    ... [INFO]...: --Section normalized forecasted start--
    ... [INFO]...: --Section normalized forecasted end--
    ... [INFO]...: --Section anomaly real start--
    ... [INFO]...: --Section anomaly real end--
    ... [INFO]...: --Section crash start--
    ... [INFO]...: --Crash start--
    ... [INFO]...: --Time: 2026-02-24T05:25:51.339Z, pos: (45.610087, 8.863476), risk: 5--
    ... [INFO]...: --sid: 36, oid: None, type: passengerCar, confidence: 90--
    ... [INFO]...: --sid: 37, oid: None, type: pedestrian, confidence: 80--
    ... [INFO]...: --Crash end--
    ... [INFO]...: --Section crash end--
    ... [INFO]...: --Checkpoint: scenario end, timer: 1002.000--
    ... [INFO]...: --Scenario end--

Every complete scenario with at least one actor becomes one ``Session``. For
each actor of a scenario the session data holds:

* ``dataType``: ``normalized`` when the actor has normalized real points,
  otherwise ``anomaly`` (anomaly real points are only a fallback; the two are
  never combined);
* ``realPositions`` and, for normalized data only, ``forecastedPositions``; a
  missing speed/heading is derived from the actor's previous point.

The scenario's ``crashesInfo`` and ``checkpoints`` are stored once per session;
``CollectionActors`` then keeps, per actor and session, only the crashes listing
that actor in ``actorsInvolved``.


CLI syntax
----------

.. code-block:: bash

    crash_prediction_log_extractor [options]

If run with no arguments, it prints help and exits with usage code ``1``.


Command-line options
--------------------

``-h``, ``--help``
    Show help and exit.

``-v``, ``--version``
    Show package version and exit.

``-s <schema folder>``, ``--schema <schema folder>``
    Write the JSON schemas of ``CollectionSessions``, ``CollectionActors``,
    ``CollectionSequences``, ``CollectionCheckpoints``, and
    :ref:`CrashPredictionLogExtractorConfig <crash_prediction_log_extractor_config_schema>`
    to the target directory.

``-e <example folder>``, ``--example <example folder>``
    Write example JSON payloads for the same models to the target directory.

``-c <config file>``, ``--config <config file>``
    Path to the JSON
    :ref:`configuration file <crash_prediction_log_extractor_config_schema>`
    listing the input log files, the OSM map files and road-type filters, the
    output folder, ``maxToleranceTime``, ``collisionRiskThreshold``,
    ``jsonIndentation``, and ``log``.

The output files written for each input log file are listed in
:doc:`commands`.


Examples
--------

Generate schema artifacts:

.. code-block:: bash

    crash_prediction_log_extractor -s ./schemas

Generate example JSON:

.. code-block:: bash

    crash_prediction_log_extractor -e ./examples

Run the bundled example (log file, maps, and configuration in ``doc/examples``):

.. code-block:: bash

    cd doc/examples
    crash_prediction_log_extractor -c ./config/config.json

Generate schemas and examples, then run extraction in one command:

.. code-block:: bash

    crash_prediction_log_extractor -s ./schemas -e ./examples -c ./config/config.json


Exit codes
----------

The program returns these exit codes:

* ``0`` (OK): successful execution.
* ``1`` (USAGE): no arguments provided.
* ``2`` (ERROR): unhandled exception.
* ``3`` (ABORTED): interrupted (for example, ``Ctrl+C``).

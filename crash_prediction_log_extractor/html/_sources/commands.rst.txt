======================
Command Line Interface
======================

Overview
========

The ``crash_prediction_log_extractor`` CLI parses ``step_crash_prediction`` log
files and writes, for every input file, the extracted scenario data as JSON
(:ref:`CollectionSessions <collection_sessions_schema>`,
:ref:`CollectionActors <collection_actors_schema>`,
:ref:`CollectionSequences <collection_sequences_schema>`,
:ref:`CollectionCheckpoints <collection_checkpoints_schema>`), together with
interactive HTML maps and dashboards and a GPX file.

It can also generate:

* JSON schema artifacts for the four payloads and for
  :ref:`CrashPredictionLogExtractorConfig <crash_prediction_log_extractor_config_schema>`
* JSON example artifacts for the same models (a configuration template for the
  config)


Basic usage
===========

.. code-block:: bash

    crash_prediction_log_extractor [options]

If no options are provided, the program prints help and exits with code ``1``.
Several options may be combined; they run in the order schema, example,
extraction.


Options
=======

``-h``, ``--help``
    Display the help message and exit.

``-v``, ``--version``
    Show the program version and exit.

``-s <schema folder>``, ``--schema <schema folder>``
    Write the JSON schemas of ``CollectionSessions``, ``CollectionActors``,
    ``CollectionSequences``, ``CollectionCheckpoints``, and
    ``CrashPredictionLogExtractorConfig`` to the specified directory.

``-e <example folder>``, ``--example <example folder>``
    Write example JSON payloads for the same models to the specified directory.

``-c <config file>``, ``--config <config file>``
    Path to the JSON
    :ref:`configuration file <crash_prediction_log_extractor_config_schema>`.
    The main fields are:

    * ``inputFilePathList``: log files to parse, each processed independently.
    * ``mapFilePathList``: OSM map files drawn on the interactive maps.
    * ``mapVehicleRoadTypeList``, ``mapSpecificCycleRoadTypeList``,
      ``mapSpecificPedestrianRoadTypeList``: road types kept from the maps
      (their union is used as filter).
    * ``mapMaxZoom``: maximum zoom level of the maps (17-25).
    * ``outputFolderPath``: directory of all output files; created if missing.
    * ``maxToleranceTime``: forecast-matching tolerance in milliseconds (0-200).
    * ``collisionRiskThreshold``: crash-marker risk threshold (1-7).
    * ``jsonIndentation``: JSON indentation spaces (1-10); ``null`` produces
      compact JSON.
    * ``log``: logging configuration (``LogConfig``).


Output files
============

For every entry of ``inputFilePathList`` with stem ``<stem>``, the extraction
writes to ``outputFolderPath``:

.. list-table::
   :header-rows: 1
   :widths: 45 55

   * - File
     - Content
   * - ``<stem>_sessions.json``
     - :ref:`CollectionSessions <collection_sessions_schema>` payload
   * - ``<stem>_sessions_map.html``
     - Folium map browsing the sessions
   * - ``<stem>_actors.json``
     - :ref:`CollectionActors <collection_actors_schema>` payload
   * - ``<stem>_actors_map.html``
     - Folium map browsing the sessions per actor
   * - ``<stem>.gpx``
     - Multi-track GPX file, one track per actor
   * - ``<stem>_sequences.json``
     - :ref:`CollectionSequences <collection_sequences_schema>` payload
   * - ``<stem>_distance_heading_dashboard.html``
     - Plotly dashboard of forecast distance and heading errors
   * - ``<stem>_checkpoints.json``
     - :ref:`CollectionCheckpoints <collection_checkpoints_schema>` payload
   * - ``<stem>_performance_dashboard.html``
     - Plotly dashboard of the elapsed time between checkpoints

A file from which no session is extracted produces no output file. The OSM map
files are parsed again for every input file.


Detailed command description
============================

Help command
------------

.. code-block:: bash

    crash_prediction_log_extractor --help

Shows usage instructions and available options.

Version command
---------------

.. code-block:: bash

    crash_prediction_log_extractor --version

Shows the installed package version.

Schema generation
-----------------

.. code-block:: bash

    crash_prediction_log_extractor --schema ./schemas

Writes the schema files of all models to the ``./schemas`` directory.

Example generation
------------------

.. code-block:: bash

    crash_prediction_log_extractor --example ./examples

Writes the example JSON files of all models to the ``./examples`` directory.

Log extraction via config file
------------------------------

.. code-block:: bash

    crash_prediction_log_extractor --config ./config/config.json

Reads the configuration file, configures logging from its ``log`` field, creates
``outputFolderPath``, and runs the whole pipeline for every input log file.
Relative paths in the configuration are resolved against the current working
directory.

If an unhandled exception occurs, the files already processed keep their
outputs and the remaining files are skipped.


Exit codes
==========

The program returns the following exit codes:

* ``0`` (OK): Successful termination.
* ``1`` (USAGE): No arguments provided.
* ``2`` (ERROR): Unhandled exception during execution.
* ``3`` (ABORTED): Interrupted by the user (``KeyboardInterrupt``, for example
  ``Ctrl+C``).


Examples
========

Generate schema files:

.. code-block:: bash

    crash_prediction_log_extractor -s ./schemas

Generate example files:

.. code-block:: bash

    crash_prediction_log_extractor -e ./examples

Run the bundled example (from the ``doc/examples`` folder):

.. code-block:: bash

    cd doc/examples
    crash_prediction_log_extractor -c ./config/config.json

Generate schemas and examples, then run extraction in one command:

.. code-block:: bash

    crash_prediction_log_extractor -s ./schemas -e ./examples -c ./config/config.json

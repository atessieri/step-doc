crash_prediction_log_extractor package

Crash Prediction Log Extractor package.

This library parses step_crash_prediction service logs and converts scenario markers into a structured CollectionsPoints JSON payload. The intended workflow is:

  1. Read a plain-text log file (for example doc/examples/log_file/step_crash_prediction.txt).

  2. Extract scenario data blocks emitted as marker lines by step_crash_prediction.

  3. Build typed models (actors, positions, crash events).

  4. Write the result as JSON (for example doc/examples/output/test.json).

Overview of what is parsed

The extractor is marker-driven. It scans every line and reacts only when one of the expected marker patterns is found. In practice these markers are emitted at INFO level in the sample log, but parsing is not hard-filtered by log level; any line containing a valid marker is accepted.

Expected envelope format of each log line:

YYYY-MM-DD HH:MM:SS.mmm [LEVEL][pid=...][thread=...][module=...][function=...]: <marker>

Only <marker> is semantically parsed.

Marker grammar

Scenario boundaries:

--Scenario start--
--Scenario end--

Section boundaries (always parsed in this order per scenario):

--Section normalized real start--
--Section normalized real end--
--Section normalized forecasted start--
--Section normalized forecasted end--
--Section anomaly real start--
--Section anomaly real end--
--Section anomaly forecasted start--
--Section anomaly forecasted end--
--Section crash start--
--Section crash end--

Actor identifier inside a section:

--Id: sid <station_id>, oid <object_id|None>--

Position point associated with the most recent --Id: ...--:

--t: <iso_time>, p: (<latitude>, <longitude>), s: <speed|None>, h: <heading|None>--

Crash record block inside the crash section:

--Crash start--
--Time: <ISO8601>, pos: (<lat>, <lon>), risk: <0.000-1.000>--
--Id: sid <station_id>, oid <object_id|None>--
[one or more additional actor Id lines]
--Crash end--

Notes

  • Scenario markers are interleaved with normal runtime/debug lines; non-marker lines are ignored.

  • normalized sections can be empty (start immediately followed by end).

  • anomaly real often contains long sequences of points for one actor.

  • Forecasted sections may be empty; when populated, speed/heading may be None.

  • Crash section can be empty or contain one/more crash blocks; each crash risk is recorded and linked to all listed actors.

Output model semantics

For each actor, the extractor emits session entries composed of:

  • dataType: normalized or anomaly.

  • realPositions and forecastedPositions.

  • lastRealTime from the last real point.

  • crashInfo entries where the actor appears in actorsInvolved.

When the same actor appears in both normalized and anomaly sets for one scenario, anomaly data overrides normalized data for that scenario merge.

CLI usage

The package provides the crash_prediction_log_extractor command.

Typical extraction command:

crash_prediction_log_extractor -i doc/examples/log_file/step_crash_prediction.txt -o doc/examples/output/test.json -f doc/examples/log/log_extractor.log -l debug

Options:

  • -i, --input_file: path of the input step_crash_prediction log file (required for extraction).

  • -o, --output_file: output JSON path. If omitted, output is written in the current directory with the input stem and .json extension.

  • -f, --log_file: optional internal extractor log file.

  • -l, --log_level: optional log level (for example debug, info, warning).

  • -d, --indentation: optional JSON indentation spacing (number of spaces).

Additional utility modes:

crash_prediction_log_extractor -s <schema_folder>
crash_prediction_log_extractor -e <example_folder>

  • -s, --schema writes the JSON schema for CollectionsPoints.

  • -e, --example writes an example JSON payload.

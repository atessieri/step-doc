crash_prediction_log_extractor.log_extractor module

Log extractor for crash prediction scenario data.

This module parses structured log files produced by the step_crash_prediction service and assembles the extracted data into CollectionSessions payloads.

The primary public interface is LogExtractor. Instantiate it with the path to a log file and a logging.Logger, call LogExtractor.extract, then read the result from LogExtractor.collections.

Log file format

Each line in the log file follows the standard Python logging layout:

YYYY-MM-DD HH:MM:SS.mmm [LEVEL][pid=...][thread=...][module=...][function=...]: <marker>

The extractor ignores regular log output and only reacts to marker lines embedded in the log. The markers delimit scenarios, section types (normalized / anomalous, real / forecasted), crash events, and individual data points.

Marker reference

  • Scenario boundary:

    --Scenario start--
--Scenario end--

  • Scenario time (required after --Scenario start--, before the sections):

    --Scenario t: <ISO8601>--

  • Section data boundaries (three blocks: normalized real, normalized forecasted, and anomaly real, always in this order):

    --Section normalized real start--
--Section normalized real end--
--Section normalized forecasted start--
--Section normalized forecasted end--
--Section anomaly real start--
--Section anomaly real end--

  • Actor identifier (inside a section data block):

    --sid: <station_id>, oid: <object_id|None>, type: <TrafficParticipantType>, confidence: <0-100|None>--

Example: --sid: 37, oid: None, type: passengerCar, confidence: 90--
         --sid: 36, oid: 5, type: cyclist, confidence: None--

  • Position data point (following an actor identifier):

    --t: <ISO8601>, p: (<lat>, <lon>), t: <PositionType>, s: <speed|None>, h: <heading|None>--

Example (real):      --t: 2026-02-24T05:25:51.339Z, p: (45.610087, 8.863476), t: GNSS, s: 0.00, h: 21.10--
Example (forecast):  --t: 2026-02-24T05:26:06.379Z, p: (45.609514, 8.863836), t: GNSS_predicted, s: None, h: None--

  • Checkpoint marker (timing / progress probe):

    --Checkpoint: <name>, timer: <ms.3f>--

where ``<ms>`` is a monotonic timer value in milliseconds (any number
of decimals is accepted).

Accepted checkpoint names are the ``CheckpointType`` values:

* ``scenario start``
* ``scenario norm start``
* ``scenario norm to dataframe``
* ``forecasting norm``
* ``forecasted snapping``
* ``log forecasted norm``
* ``scenario norm end``
* ``scenario anomaly start``
* ``scenario anomaly end``
* ``send forecasted data``
* ``process collision detection start``
* ``process collision detection end``
* ``send crash detection results``
* ``scenario end``

A checkpoint with any other name is skipped with a warning. Checkpoint
lines are collected anywhere in a scenario except inside individual
crash records.

  • Crash section boundaries:

    --Section crash start--
--Section crash end--

  • Individual crash record (inside a crash section):

    --Crash start--
--Time: <ISO8601>, pos: (<lat>, <lon>), risk: <1-7>--
--sid: <station_id>, oid: <object_id|None>, type: <TrafficParticipantType>, confidence: <0-100|None>--
... (one --sid:-- line per actor involved)
--Crash end--

Log example::

    --Crash start--
    --Time: 2026-02-24T05:25:51.339Z, pos: (45.610087, 8.863476), risk: 5--
    --sid: 36, oid: None, type: passengerCar, confidence: 90--
    --sid: 37, oid: None, type: pedestrian, confidence: 80--
    --Crash end--

Complexity:

  • - Time – O(B + K * a**2), dominated by LogExtractor.extract; B = size of the log file in characters (each line is scanned by a fixed set of regular expressions), K = crash records, a = actors per crash record (duplicate check).

  • - Space – O(P), dominated by LogExtractor.extract; P = positions, crashes, and checkpoints kept for the parsed sessions.

Classes:

  • ParserScenarioState: States of the scenario parser. Complexity: time O(1), space O(1).

  • ParserSectionDataState: States of the section-data parser. Complexity: time O(1), space O(1).

  • ParserCrashState: States of the crash-record parser. Complexity: time O(1), space O(1).

  • SectionDataType: Real or forecasted section kind. Complexity: time O(1), space O(1).

  • ParserTableDataMarkerItem: Hashable (data type, section kind) key of one section data block. Complexity: time O(1), space O(1).

  • SpeedHeading: Named tuple of derived speed and heading. Complexity: time O(1), space O(1).

  • LogExtractor: Marker-driven parser building a CollectionSessions payload. Complexity: time O(B + K * a**2), space O(P).

Parses a step_crash_prediction log file into CollectionSessions.

The extractor reads the log file line by line and drives a hierarchy of finite-state machines to recognize structured marker lines embedded in the standard Python logging output. A full scenario block looks like:

--Scenario start--
  --Scenario t: 2026-02-24T05:25:51.339Z--
  --Checkpoint: scenario start, timer: 1000.000--
  --Checkpoint: scenario norm start, timer: 1000.000--
  --Section normalized real start--
  --sid: 37, oid: None, type: passengerCar, confidence: 90--
  --t: 2026-02-24T05:25:51.339Z, p: (45.610087, 8.863476), t: GNSS, s: 0.00, h: 21.10--
  --Section normalized real end--
  --Checkpoint: log forecasted norm, timer: 1001.000--
  --Section normalized forecasted start--
  --sid: 37, oid: None, type: passengerCar, confidence: 90--
  --t: 2026-02-24T05:26:00.379Z, p: (45.609514, 8.863836), t: GNSS_predicted, s: None, h: None--
  --Section normalized forecasted end--
  --Checkpoint: scenario norm end, timer: 1001.000--
  --Checkpoint: scenario anomaly start, timer: 1001.000--
  --Section anomaly real start--
  --Section anomaly real end--
  --Checkpoint: scenario anomaly end, timer: 1002.000--
  --Checkpoint: send forecasted data, timer: 1002.000--
  --Checkpoint: send crash detection results, timer: 1002.000--
  --Section crash start--
  --Crash start--
  --Time: 2026-02-24T05:25:51.339Z, pos: (45.610087, 8.863476), risk: 5--
  --sid: 36, oid: None, type: passengerCar, confidence: 90--
  --sid: 37, oid: None, type: pedestrian, confidence: 80--
  --Crash end--
  --Section crash end--
  --Checkpoint: scenario end, timer: 1002.000--
--Scenario end--

Multiple scenarios may appear in one log file; each is processed independently and every complete scenario with at least one actor becomes one Session of a single CollectionSessions object, available through the collections property after extract has been called. Not thread-safe: the parser keeps per-scenario state (checkpoints and a shared ItsTime helper) on the instance.

extract() → None[source]

Parse the entire log file and populate collections.

Opens input_file as UTF-8 text and iteratively calls _extract_section until the end of the file is reached; every returned Session is kept and numbered consecutively from 0.

On success, collections holds a CollectionSessions payload with one Session per complete scenario that had at least one actor (possibly no sessions at all). If a sub-parser raises a ValueError (including pydantic.ValidationError), it is logged with its traceback and collections is left unchanged (None on a first call): the sessions parsed so far are discarded.

Returns:

The result is stored in collections.

Return type:

None

import logging

extractor = LogExtractor(
    input_file=Path("step_crash_prediction.txt"),
    logger=logging.getLogger(__name__),
)
extractor.extract()
payload = extractor.collections
if payload:
    payload.print_to_file(Path("output.json"), indentation=2)

======================
Command Line Interface
======================

Overview
========

The step_producer command line interface (CLI) provides a way to interact 
with the STEP Producer.

The CLI allows users to:

* View the program version
* Generate JSON schema documentation for configuration
* Create configuration templates
* Load and run the module with a specific configuration

Basic Usage
===========

.. code-block:: bash

    step_producer [options]

If no options are provided, the program displays the help message and exits with
code ``1`` (``USAGE``).

Options
=======

The following command line options are available:

``-h, --help``
    Display the help message and exit.

``-v, --version``
    Show the program version and exit.

``-s, --conf_schema <schema dir>``
    Write the configuration JSON schema (``step_producer_config_v1_schema.json``)
    into the specified directory, created if missing.

``-t, --conf_template <template dir>``
    Write a configuration template (``step_producer_config_v1_schema_template.json``)
    into the specified directory, created if missing.

``-c, --config <config file>``
    Load the configuration from the specified file and run the module.

``-i, --instance <instance name>``
    Specify the instance name, also used as the Redis stream consumer name.

.. note::
    The ``-c``/``--config`` and ``-i``/``--instance`` options must be given together:
    when only one of them is present, the program logs a single error line (no
    traceback) and exits with code ``1`` (``USAGE``). The Redis host, port and
    credentials are not command line options: they are read from the environment
    (see :ref:`step_producer_credentials`).

Detailed Command Description
============================

Help Command
------------

To display help information:

.. code-block:: bash

    step_producer --help

This will output usage instructions and a list of available options.

Version Command
---------------

To display the program version:

.. code-block:: bash

    step_producer --version

This will output the current version of the step_producer.

Configuration Schema Generation
-------------------------------

To generate a JSON schema file documenting all configuration options:

.. code-block:: bash

    step_producer --conf_schema /path/to/schema_dir

This command writes ``step_producer_config_v1_schema.json`` into the specified
directory, creating it if missing. The file describes
all available configuration options, their types, defaults, and constraints. 
The schema can be used for validation or as a reference for creating custom configurations.

Configuration Template Generation
---------------------------------

To generate a configuration template file with default values:

.. code-block:: bash

    step_producer --conf_template /path/to/template_dir

This command writes ``step_producer_config_v1_schema_template.json`` into the
specified directory, creating it if missing, with default values 
for all settings. Users can modify this file as needed to customize their configuration.

Running with Configuration
--------------------------

To run the module with a specific configuration:

.. code-block:: bash

    step_producer --instance test --config /path/to/config_file.json

This loads the configuration from the specified file, reconfigures the logger from its
``log`` section, logs the program, ``step_cloud_schemas`` and ``step_redis`` versions and
starts the step_producer. The module connects to the Redis streams specified in the
configuration, with the host, port and credentials read from the ``REDIS_*`` environment
variables or a ``.env`` file (see :ref:`step_producer_credentials`).

Exit Codes
==========

The program uses the following exit codes:

* ``0`` (OK): Successful termination, including ``-h``/``--help`` and ``-v``/``--version``
* ``1`` (USAGE): Command line usage error: no arguments, an invalid or unknown option, or
  only one of ``-c``/``--config`` and ``-i``/``--instance``
* ``2`` (ERROR): An unhandled exception (e.g. an invalid configuration file or a missing
  ``REDIS_URL``/``REDIS_PORT`` variable), or an error a reconnect cannot fix (rejected
  credentials, ACL denial, missing SSL file, untrusted certificate)
* ``3`` (ABORTED): Operation aborted by user or system (``Ctrl+C`` or a shutdown signal)

Examples
========

Generate a configuration schema:

.. code-block:: bash

    step_producer --conf_schema ./schema_dir

Create a configuration template:

.. code-block:: bash

    step_producer --conf_template ./template_dir

Run with specific configuration:

.. code-block:: bash

    step_producer --instance test --config ./my_config.json

Generate both schema and template:

.. code-block:: bash

    step_producer --conf_schema ./schema_dir --conf_template ./template_dir

Program Operation
=================

When running with a configuration file, the step_producer 
performs the following operations:

   #. Reads the Redis host, port and credentials from the environment once, before the
      first connection: a missing variable stops the program instead of being retried
   #. Connects to the Redis server using the provided connection settings (a pool of at
      most 2 connections) and opens the client output stream
   #. Starts three asynchronous tasks:

      - **Stream Message Reception**: Continuously listens to the Redis input stream for incoming
        messages and dispatches them by type: a DENM record with a negation removes the record it
        targets, a station collision array creates or updates the DENM records, whose DENMs are
        published to the client output stream; an unknown type is skipped with a warning, and a
        message whose processing fails validation is logged and dropped
      - **Periodic DENM Cleanup**: Every ``denmCheckLastUpdateInterval`` seconds, removes the
        expired DENM (Decentralized Environmental Notification Message) records and publishes
        a cancellation for each one still within its validity duration
      - **Redis Health Check**: Periodically pings the Redis server, so a lost connection
        triggers the reconnection

   #. Automatically handles reconnection if connections are lost (after ``reconnectInterval``
      seconds), keeping the tracked DENM records; an error a reconnect cannot fix ends the
      program with exit code ``2`` (``ERROR``)
   #. Manages graceful shutdown when interrupted

The module will continue running until manually interrupted (e.g., with Ctrl+C) or until a system signal is received.

Advanced Usage
==============

Signal Handling
---------------

The step_producer properly handles system signals for graceful shutdown. On ``SIGINT``/``SIGTERM``
(POSIX) or ``CTRL_C``/``CTRL_BREAK`` (Windows), the running tasks are cancelled, the Redis pool and
streams are released, the signal name is logged and the program exits with code ``3`` (``ABORTED``).

Logging
-------

The step_producer includes detailed logging capabilities. Log settings can be configured 
in the configuration file, including:

* Log level (DEBUG, INFO, WARNING, ERROR, CRITICAL)
* Console logging
* File logging with size or time based rotation options
* Null logging

The durations of the message processing, of the DENM publishing and of each cleanup
are logged at INFO level.

You can enable debug logging to troubleshoot connection or message handling issues.

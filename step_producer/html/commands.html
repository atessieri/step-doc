Command Line Interface

Overview

The step_producer command line interface (CLI) provides a way to interact with the STEP Producer.

The CLI allows users to:

  • View the program version

  • Generate JSON schema documentation for configuration

  • Create configuration templates

  • Load and run the module with a specific configuration

Basic Usage

step_producer [options]

If no options are provided, the program displays the help message and exits with code 1 (USAGE).

Options

The following command line options are available:

-h, --help

Display the help message and exit.

-v, --version

Show the program version and exit.

-s, --conf_schema <schema dir>

Write the configuration JSON schema (step_producer_config_v1_schema.json) into the specified directory, created if missing.

-t, --conf_template <template dir>

Write a configuration template (step_producer_config_v1_schema_template.json) into the specified directory, created if missing.

-c, --config <config file>

Load the configuration from the specified file and run the module.

-i, --instance <instance name>

Specify the instance name, also used as the Redis stream consumer name.

Note

The -c/--config and -i/--instance options must be given together: when only one of them is present, the program logs a single error line (no traceback) and exits with code 1 (USAGE). The Redis host, port and credentials are not command line options: they are read from the environment (see Environment Variables).

Detailed Command Description

Help Command

To display help information:

step_producer --help

This will output usage instructions and a list of available options.

Version Command

To display the program version:

step_producer --version

This will output the current version of the step_producer.

Configuration Schema Generation

To generate a JSON schema file documenting all configuration options:

step_producer --conf_schema /path/to/schema_dir

This command writes step_producer_config_v1_schema.json into the specified directory, creating it if missing. The file describes all available configuration options, their types, defaults, and constraints. The schema can be used for validation or as a reference for creating custom configurations.

Configuration Template Generation

To generate a configuration template file with default values:

step_producer --conf_template /path/to/template_dir

This command writes step_producer_config_v1_schema_template.json into the specified directory, creating it if missing, with default values for all settings. Users can modify this file as needed to customize their configuration.

Running with Configuration

To run the module with a specific configuration:

step_producer --instance test --config /path/to/config_file.json

This loads the configuration from the specified file, reconfigures the logger from its log section, logs the program, step_cloud_schemas and step_redis versions and starts the step_producer. The module connects to the Redis streams specified in the configuration, with the host, port and credentials read from the REDIS_* environment variables or a .env file (see Environment Variables).

Configuration File Structure

The configuration file is a JSON document that defines the behavior of the step_producer. It includes settings for:

  • Module basic settings

  • Redis client connection

  • Redis streams

  • Logging configuration

Here’s an example of the configuration structure:

{
  "templateVersion": "1",
  "stationId": 25648,
  "timeAfterCollision": 1,
  "denmLastUpdateMaxDelay": 1500,
  "denmCheckLastUpdateInterval": 30,
  "reconnectInterval": 2,
  "redis": {
    "connection": {
      "db": 0,
      "socketTimeout": 40,
      "socketConnectTimeout": 30,
      "socketKeepIdle": 30,
      "socketKeepAlive": 30,
      "socketKeepCnt": 5,
      "sslEnable": true,
      "sslClientKeyFile": "/path/to/client.key",
      "sslClientKeyFilePassword": "<password>",
      "sslClientCertFile": "/path/to/client.crt",
      "sslCertRequested": true,
      "sslCaCertsFile": "/path/to/ca_certs_file.crt",
      "healthCheckInterval": 20,
      "connectionAvailableTimeout": 10,
      "protocol": 3,
      "retryCount": 3
    },
    "streams": {
      "outputs": {
        "client": {
          "streamId": "stream id",
          "maxLength": 1000
        }
      },
      "input": {
        "streamId": "stream id",
        "groupId": "group id",
        "waitTimeout": 30000
      }
    }
  },
  "log": {
    "handlersConfig": [
      {
        "handler": {
          "handlerType": "file",
          "path": "./log",
          "filenameTrailer": ".log",
          "append": true
        },
        "level": "INFO",
        "format": "%(asctime)s.%(msecs)03dZ [%(levelname)s][pid=%(process)d][module=%(module)s][function=%(funcName)s]: %(message)s",
        "dateFormat": "%Y-%m-%d %H:%M:%S"
      }
    ],
    "globalLevel": "INFO"
  }
}

For the STEP Producer Configuration Schema with all configuration options, generate a schema file using the --conf_schema option.

Exit Codes

The program uses the following exit codes:

  • 0 (OK): Successful termination, including -h/--help and -v/--version

  • 1 (USAGE): Command line usage error: no arguments, an invalid or unknown option, or only one of -c/--config and -i/--instance

  • 2 (ERROR): An unhandled exception (e.g. an invalid configuration file or a missing REDIS_URL/REDIS_PORT variable), or an error a reconnect cannot fix (rejected credentials, ACL denial, missing SSL file, untrusted certificate)

  • 3 (ABORTED): Operation aborted by user or system (Ctrl+C or a shutdown signal)

Examples

Generate a configuration schema:

step_producer --conf_schema ./schema_dir

Create a configuration template:

step_producer --conf_template ./template_dir

Run with specific configuration:

step_producer --instance test --config ./my_config.json

Generate both schema and template:

step_producer --conf_schema ./schema_dir --conf_template ./template_dir

Program Operation

When running with a configuration file, the step_producer performs the following operations:

  1. Reads the Redis host, port and credentials from the environment once, before the first connection: a missing variable stops the program instead of being retried

  2. Connects to the Redis server using the provided connection settings (a pool of at most 2 connections) and opens the client output stream

  3. Starts three asynchronous tasks:

    • Stream Message Reception: Continuously listens to the Redis input stream for incoming messages and dispatches them by type: a DENM record with a negation removes the record it targets, a station collision array creates or updates the DENM records, whose DENMs are published to the client output stream; an unknown type is skipped with a warning, and a message whose processing fails validation is logged and dropped

    • Periodic DENM Cleanup: Every denmCheckLastUpdateInterval seconds, removes the expired DENM (Decentralized Environmental Notification Message) records and publishes a cancellation for each one still within its validity duration

    • Redis Health Check: Periodically pings the Redis server, so a lost connection triggers the reconnection

  4. Automatically handles reconnection if connections are lost (after reconnectInterval seconds), keeping the tracked DENM records; an error a reconnect cannot fix ends the program with exit code 2 (ERROR)

  5. Manages graceful shutdown when interrupted

The module will continue running until manually interrupted (e.g., with Ctrl+C) or until a system signal is received.

Advanced Usage

Signal Handling

The step_producer properly handles system signals for graceful shutdown. On SIGINT/SIGTERM (POSIX) or CTRL_C/CTRL_BREAK (Windows), the running tasks are cancelled, the Redis pool and streams are released, the signal name is logged and the program exits with code 3 (ABORTED).

Logging

The step_producer includes detailed logging capabilities. Log settings can be configured in the configuration file, including:

  • Log level (DEBUG, INFO, WARNING, ERROR, CRITICAL)

  • Console logging

  • File logging with size or time based rotation options

  • Null logging

The durations of the message processing, of the DENM publishing and of each cleanup are logged at INFO level.

You can enable debug logging to troubleshoot connection or message handling issues.

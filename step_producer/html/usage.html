STEP Producer Usage Guide

Introduction

The step_producer is a critical component of the STEP (Safer Transport for Europe Platform) ecosystem, specifically designed for processing and managing Decentralized Environmental Notification Messages (DENM) within Intelligent Transportation Systems (ITS) environments. This Redis-based microservice implements the DEN (Decentralized Environmental Notification) service for collision prediction and environmental hazard notifications.

Prerequisites

Before using the STEP Producer, make sure you have:

  1. Python 3.13 or higher installed

  2. A Redis server for stream processing

  3. The step_producer package installed in your environment

Installation

You can install the STEP Producer package using pip:

$pip install --extra-index-url https://gitlab.automotive.vodafone.com/api/v4/projects/1137/packages/pypi/simple step_producer

Or if you’re using a development version:

pip install -e /path/to/step_producer

Basic Concepts

STEP Producer consumes collision prediction data from a Redis input stream and publishes the resulting DENM messages to a Redis output stream, specifically designed for ITS message exchange. Key concepts include:

  • DENM (Decentralized Environmental Notification Messages): Environmental hazard notifications that inform other ITS stations about potential dangers like collisions, road conditions, or traffic incidents

  • Redis Stream Processing: Asynchronous message consumption from Redis streams for real-time processing of collision prediction data and station collision arrays

  • DEN Service Management: Lifecycle management of DENM messages including creation, processing, termination, and automatic cleanup of expired records

  • Station Collision Processing: Conversion of incoming collision data into standardized DENM messages for distribution to other ITS stations

  • Message Termination: Processing of DENM negations and cancellations to remove corresponding active records from the system

  • Periodic Cleanup: Automatic identification and cancellation of expired DENM records with configurable cleanup intervals

  • Event-Driven Architecture: Asynchronous task groups handling concurrent stream reception and periodic maintenance operations

  • Signal Handling: Graceful shutdown capabilities with proper resource cleanup when interrupted by system signals

  • Automatic Reconnection: Built-in retry mechanism with configurable intervals for handling connection failures

Environment Variables

Redis connection secrets are kept out of the (persisted) JSON configuration file and are instead read from the process environment. On startup, _get_redis_credential() calls python-dotenv’s load_dotenv(), which automatically loads a .env file from the current working directory (or an ancestor of it) into the environment before the following variables are read:

  • REDIS_URL (required): Redis server host address, without protocol or port

  • REDIS_PORT (required): Redis server port number

  • REDIS_USERNAME (optional): Username for Redis authentication

  • REDIS_PASSWORD (optional): Password for Redis authentication

REDIS_URL and REDIS_PORT raise a ValueError if left unset; REDIS_USERNAME and REDIS_PASSWORD default to unset.

An example .env file is provided below and can be copied to .env in the directory you run step_producer from, then filled in with your Redis server’s connection details:

REDIS_URL=<your_redis_host_without_protocol_port>
REDIS_PORT=<your_redis_port>
REDIS_USERNAME=<your_redis_username>
REDIS_PASSWORD=<your_redis_password>

Configuration

STEP Producer requires configuration for Redis connections. The configuration is managed through a JSON file.

Creating a Configuration File

To create a default configuration template:

step_producer --conf_template my_config_template.json

This generates a template that you can customize for your specific needs.

Key Configuration Parameters

  • Base Configuration:

    • stationId: Station identification number

    • timeAfterCollision: Time to keep broadcasting a DENM after the collision (seconds)

    • denmLastUpdateMaxDelay: Maximum delay for a DENM record’s reference time before it is treated as expired (milliseconds)

    • denmCheckLastUpdateInterval: Interval for checking DENM updates (seconds)

    • reconnectInterval: Time between reconnection attempts (seconds)

  • Redis Configuration:

    • connection: Redis server connection details

    • streams: Configuration for Redis streams (inputs and outputs)

  • Log Configuration:

    • level: Logging level (e.g., DEBUG, INFO, WARNING, ERROR)

    • format: Log message format

    • handlers: List of log handlers (e.g., console, file)

Example Configuration

The schema of the example below is: STEP Producer Configuration Schema

{
  "templateVersion": "1",
  "stationId": 25648,
  "timeAfterCollision": 1,
  "denmLastUpdateMaxDelay": 1500,
  "denmCheckLastUpdateInterval": 30,
  "reconnectInterval": 2,
  "redis": {
    "connection": {
      "db": 0,
      "socketTimeout": 30,
      "socketConnectTimeout": 30,
      "socketKeepIdle": 30,
      "socketKeepAlive": 30,
      "socketKeepCnt": 5,
      "sslEnable": true,
      "sslClientKeyFile": "/path/to/client.key",
      "sslClientKeyFilePassword": "password",
      "sslClientCertFile": "/path/to/client.crt",
      "sslCertRequested": true,
      "sslCaCertsFile": "/path/to/ca_certs_file.crt",
      "healthCheckInterval": 20,
      "connectionAvailableTimeout": 10,
      "protocol": 3,
      "retryCount": 3
    },
    "streams": {
      "outputs": {
        "client": {
          "streamId": "stream id",
          "maxLength": 1000
        }
      },
      "input": {
        "streamId": "stream id",
        "groupId": "group id",
        "waitTimeout": 30000
      }
    }
  },
  "log": {
    "handlersConfig": [
      {
        "handler": {
          "handlerType": "file",
          "path": "./log",
          "filenameTrailer": ".log",
          "append": true
        },
        "level": "INFO",
        "format": "%(asctime)s.%(msecs)03dZ [%(levelname)s][pid=%(process)d][module=%(module)s][function=%(funcName)s]: %(message)s",
        "dateFormat": "%Y-%m-%d %H:%M:%S"
      }
    ],
    "globalLevel": "INFO"
  }
}

Running STEP Producer as a Service

To run the STEP Producer as a standalone service:

step_producer --config /path/to/config.json

This will start the Producer, which will:

  1. Connect to Redis

  2. Process messages between STEP Client and STEP Crash Prediction

Command-Line Options

The STEP Producer supports several command-line options:

  • --version, -v: Show version information

  • --help, -h: Show help information

  • --conf_schema, -s: Generate a JSON schema for the configuration

  • --conf_template, -t: Generate a configuration template

  • --config, -c: Path to configuration file

  • --instance, -i: Specify the instance name

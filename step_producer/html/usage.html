STEP Producer Usage Guide

Introduction

The step_producer is a critical component of the STEP (Safer Transport for Europe Platform) ecosystem, specifically designed for processing and managing Decentralized Environmental Notification Messages (DENM) within Intelligent Transportation Systems (ITS) environments. This Redis-based microservice implements the DEN (Decentralized Environmental Notification) service for collision prediction and environmental hazard notifications.

Prerequisites

Before using the STEP Producer, make sure you have:

  1. Python 3.13 or higher installed

  2. A Redis server for stream processing

  3. The step_producer package installed in your environment

Installation

You can install the STEP Producer package using pip:

$pip install --extra-index-url https://gitlab.automotive.vodafone.com/api/v4/projects/1137/packages/pypi/simple step_producer

Or if you’re using a development version:

pip install -e /path/to/step_producer

Basic Concepts

STEP Producer consumes collision prediction data from a Redis input stream and publishes the resulting DENM messages to a Redis output stream, specifically designed for ITS message exchange. Key concepts include:

  • DENM (Decentralized Environmental Notification Messages): Environmental hazard notifications that inform other ITS stations about potential dangers like collisions, road conditions, or traffic incidents

  • Redis Stream Processing: Asynchronous message consumption from Redis streams for real-time processing of collision prediction data and station collision arrays

  • DEN Service Management: Lifecycle management of DENM messages including creation, processing, termination, and automatic cleanup of expired records

  • Station Collision Processing: Conversion of incoming collision data into standardized DENM messages for distribution to other ITS stations

  • Message Termination: Processing of DENM negations and cancellations to remove corresponding active records from the system

  • Periodic Cleanup: Automatic identification and cancellation of expired DENM records with configurable cleanup intervals

  • Event-Driven Architecture: Asynchronous task groups handling concurrent stream reception and periodic maintenance operations

  • Signal Handling: Graceful shutdown capabilities with proper resource cleanup when interrupted by system signals

  • Automatic Reconnection: Built-in retry mechanism with configurable intervals for handling connection failures

Environment Variables

The Redis connection settings (database, timeouts, keepalive, SSL, pool) are kept in the JSON configuration file, in the redis.connection section (step_redis RedisConnection), while the Redis host, port and credentials are read from the environment, so that secrets are never written to the configuration file:

Variable

Required

Description

REDIS_URL

yes

Redis server host name or IP address, without protocol or port

REDIS_PORT

yes

Redis server port (1-65535); usually 6380 with TLS (redis.connection.sslEnable true), 6379 without

REDIS_USERNAME

no

ACL username, when the server requires authentication

REDIS_PASSWORD

no

Password, when the server requires authentication

The StepProducerApp constructor reads them once, through step_redis RedisCredential.from_env, before the first connection cycle. A missing REDIS_URL or REDIS_PORT, a non-integer or out-of-range port, or an empty host raise ValueError: since the credential is read outside the reconnect loop, a misconfiguration stops the program with exit code 2 (ERROR) instead of being retried forever.

How RedisCredential.from_env reads them.

  • It first loads the .env file found in the current working directory or in its nearest parent directory (find_dotenv(usecwd=True)): what counts is the directory step_producer is launched from, not the directory of the installed package. Without a .env file only the environment is read.

  • A variable already set in the environment wins over the .env file: load_dotenv adds the missing variables and never overrides an existing one.

  • An empty REDIS_USERNAME or REDIS_PASSWORD counts as unset: without a username, authentication uses the default user, and without both no authentication is performed.

  • The host and port are logged at INFO level, together with whether a username is set; the username and the password never are.

Format of the .env file.

  • One KEY=VALUE line per variable, no export needed;

  • # starts a comment;

  • quote a value only if it contains spaces or # (REDIS_PASSWORD="a #b");

  • keep the file out of version control: .env is listed in .gitignore, only the .env.example template is versioned.

Template. doc/source/env/.env.example is a commented template:

# Template of the ".env" with the Redis host, port and credentials of
# step_producer. Copy it to ".env" (git-ignored) in the directory step_producer
# is launched from, or in one of its parent directories.
# RedisCredential.from_env (step_redis) reads it at start-up; a variable already
# set in the environment (shell, container) takes precedence over the value in
# ".env".

# Host name or IP address of the Redis server. Required.
REDIS_URL=redis.example.com

# TCP port of the Redis server (1-65535). Required. Usually 6380 with TLS
# (redis.connection.sslEnable true), 6379 without.
REDIS_PORT=6380

# ACL username. Optional: unset or empty authenticates as the "default" user
# (or not at all when the password is unset or empty too).
REDIS_USERNAME=my_user

# Password. Optional: unset or empty when the server requires no
# authentication.
REDIS_PASSWORD=my_secret

Download the template: .env.example (save it as .env). For the crash_prediction_demo, copy it to doc/examples, the directory the demo is launched from:

cp doc/source/env/.env.example doc/examples/.env

Copy-Item doc/source/env/.env.example doc/examples/.env

Alternatives to the file. Variables set in the shell or by a container runtime take precedence over .env:

export REDIS_URL=redis.example.com
export REDIS_PORT=6380

$env:REDIS_URL = "redis.example.com"
$env:REDIS_PORT = "6380"

services:
  step_producer:
    env_file: .env          # or, one by one:
    environment:
      REDIS_URL: redis.example.com
      REDIS_PORT: "6380"

Note

Credentials that the server rejects, an ACL denial, a missing SSL file or an untrusted certificate are classified by step_redis as StepRedisFatalError: the program ends with exit code 2 (ERROR) instead of reconnecting.

Configuration

STEP Producer requires configuration for Redis connections. The configuration is managed through a JSON file.

Creating a Configuration File

To create a default configuration template:

step_producer --conf_template ./my_config_dir

This writes the template file into the directory (created if missing), which you can customize for your specific needs.

Key Configuration Parameters

  • Base Configuration:

    • templateVersion: Configuration template version; only "1" is accepted

    • stationId: Station ID of the ITS station originating the DENMs, used as originatingStationId of their ActionIds (0-4294967295)

    • timeAfterCollision: Time to keep broadcasting a DENM after the estimated collision, added to the time to collision to form its validity duration (seconds, 0-10)

    • denmLastUpdateMaxDelay: Maximum age of a DENM record’s reference time before the record is treated as expired (milliseconds, 1-10000)

    • denmCheckLastUpdateInterval: Period of the cleanup of the expired DENM records (seconds, 1-60)

    • reconnectInterval: Time between reconnection attempts (seconds, 1-10)

  • Redis Configuration:

    • connection: Redis connection settings (database, timeouts, keepalive, SSL, pool); the host, port and credentials come from the REDIS_* environment variables (see Environment Variables)

    • streams.input: streamId and groupId of the input stream the producer messages are read from (consumer group, the instance name is the consumer name), and waitTimeout, the receive wait timeout (milliseconds, at least 10000)

    • streams.outputs.client: streamId of the client output stream the DENMs are published to, and maxLength, the approximate maximum number of entries retained in it (at least 1)

    Note

    connection.socketTimeout must be at least streams.input.waitTimeout plus 5000 milliseconds (RedisClientConfig.READ_TIMEOUT_MARGIN_MS), otherwise the configuration is rejected: a blocking read that times out first drops the connection and loses any message delivered in that instant, since the input stream is read without acknowledgement.

  • Log Configuration:

    • globalLevel: Level of the root logger (e.g., DEBUG, INFO, WARNING, ERROR)

    • handlersConfig: List of log handlers (stream, file, rotating file, null), each with its own level and format

Running STEP Producer as a Service

To run the STEP Producer as a standalone service:

step_producer --config /path/to/config.json --instance producer_1

This will start the Producer, which will:

  1. Read the Redis host, port and credentials from the environment (see Environment Variables)

  2. Connect to Redis

  3. Receive the station collision arrays (from STEP Crash Prediction) and the DENM negations (from STEP Client) on the input stream, and publish the derived DENMs to the client output stream

  4. Periodically remove the expired DENM records and publish their cancellations

  5. Reconnect after reconnectInterval seconds when the connection fails, keeping the tracked DENM records

The Producer runs until it receives SIGINT/SIGTERM (Ctrl+C/Ctrl+Break on Windows), then releases the Redis connections and exits with code 3 (ABORTED). An error a reconnect cannot fix (e.g. rejected credentials) ends it with code 2 (ERROR).

Command-Line Options

The STEP Producer supports several command-line options:

  • --version, -v: Show version information

  • --help, -h: Show help information

  • --conf_schema, -s: Write the JSON schema of the configuration into a directory

  • --conf_template, -t: Write a configuration template into a directory

  • --config, -c: Path to configuration file (requires --instance)

  • --instance, -i: Specify the instance name, also used as the Redis stream consumer name (requires --config)

See Command Line Interface for the exit codes.

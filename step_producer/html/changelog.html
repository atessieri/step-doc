Changelog

All notable changes to step_producer are documented in this file.

1.2.5 - 2026-11-05

1.2.5 - Added

  • pyrefly type checking: pyrefly>=1.4.1 dev dependency, [tool.pyrefly] configuration in pyproject.toml, pyrefly check step in the tox lint environment and a badge in README.rst and the documentation index.

  • The changelog is published in the Sphinx documentation (doc/source/changelog.rst, rendered through the myst_parser extension).

  • CI: TOX_UV_PYTHON_PREFERENCE=system makes the tests run on the Python of the Docker image instead of downloading another one; locally tox still defaults to only-managed.

1.2.5 - Changed

  • Requires step_cloud_schemas>=3.4.3,<4.0 and pydantic>=2.14.3,<3.0; also coverage>=7.17.2, mypy>=2.4.1, pytest>=9.2.0, ruff>=0.17.3, tox>=4.67.11, tox-uv>=1.37.5, types-docutils>=0.23.0.20261030, uv >=0.13.7 and ruff required-version>=0.17.3; uv.lock refreshed accordingly.

  • tox.ini: runner, package, uv_python_preference and parallel_show_output moved from [tox] to [testenv], skip_install = True replaced by package = skip; basepython, recreate and the PYTHONPATH setting were removed.

  • doc/source/conf.py locates the test package by path instead of importing it.

  • Unit tests were adjusted for the pyrefly checks.

1.2.5 - Fixed

  • crash_prediction_demo_app.py: message is initialized to None and built when still unset, so it can no longer be used unbound.

1.2.4 - 2026-10-26

1.2.4 - Changed

  • Requires step_cloud_schemas>=3.4.2,<4.0 and step_redis>=1.6.5,<2.0; also coverage>=7.17.0, pytest-asyncio>=1.4.1, ruff>=0.17.2, sphinx-jsonschema>=1.20.1, uv >=0.13.5 and ruff required-version>=0.17.0; uv.lock refreshed accordingly.

  • DENM messages (derived from received messages and the expired-record cancellations of the periodical cleanup) are published with a single publish_denm_messages Redis round trip instead of one publish_denm_message call each.

  • The read timeout check of RedisClientConfig now delegates to RedisConnection.check_read_timeout; the local READ_TIMEOUT_MARGIN_MS constant was removed in favor of RedisConnection.READ_TIMEOUT_MARGIN_MS.

  • The JSON schema is generated with make_schema_generator from step_cloud_schemas; the local _ConfigGenerateJsonSchema class was removed.

  • Documentation and unit tests were updated accordingly.

1.2.3 - 2026-10-21

1.2.3 - Changed

  • Requires step_cloud_schemas>=3.4.0,<4.0 and step_redis>=1.6.4,<2.0; also sphinx>=9.2.0, setuptools>=84.2.1 and uv >=0.13.4; uv.lock refreshed accordingly.

  • StepProducerConfig, RedisStreamInput and RedisStreamOutput field bounds now use the named *_MIN/*_MAX constants from step_cloud_schemas; string fields gained a maximum length.

  • The JSON schema fixture and the unit tests were updated to the new bounds.

  • CI: the .tox/.python/ uv-managed interpreters path was removed from the cache.

1.2.2 - 2026-10-20

1.2.2 - Changed

  • Requires step_cloud_schemas>=3.3.3,<4.0 and step_redis>=1.6.3,<2.0; uv.lock refreshed accordingly.

  • The GitLab pipeline is created only for tags (workflow:rules) and the per-job only: tags rules were removed.

  • CI: shallow fetch (GIT_DEPTH: 10, GIT_STRATEGY: fetch), stable uv cache key per Python version, uv-managed interpreters cached, default-jre-headless instead of openjdk-*-jre-headless.

  • CI: doc deploy runs in the step_doc resource group and retries git pull --rebase && git push up to 3 times.

  • tox.ini passes UV_CACHE_DIR through to the test environments.

  • CI: the test report of each Python version is saved and published as test_report_py*.xml.

1.2.1 - 2026-10-20

1.2.1 - Changed

  • Updated dependency constraints: step_redis>=1.6.2, sphinx>=9.1.1, setuptools>=84.2.0 (build requirement) and uv>=0.13.3 (required-version); uv.lock refreshed accordingly.

1.2.0 - 2026-10-19

1.2.0 - Added

  • New step_producer_app module with ExitCode and StepProducerApp, a step_cloud_schemas.ReconnectingApp: each connection cycle opens the Redis pool and client stream and runs the stream receive, periodical cleanup and health check tasks; on failure it reconnects after reconnectInterval keeping the tracked DENM records, while StepRedisFatalError ends the run with ExitCode.ERROR.

  • RedisClientConfig validator: connection.socketTimeout must exceed streams.input.waitTimeout by at least the read timeout margin.

  • DenServiceDataManager raises OverflowError when every ActionId sequence number is in use, instead of reusing one.

  • The root __all__ now also exports DenServiceDataManager, DenServiceManager, DenmRecordInfo, ExitCode, OrderedListRecord, RecordKey, StepCliError, StepProducerApp and StepProducerError.

  • pytest-timeout (300 s per test), a 100% coverage gate (fail_under = 100), a docstring doctest run in the lint tox env, myst-parser in the doc group and a .gitattributes for line-ending normalization.

1.2.0 - Changed

  • __main__ now only parses the CLI, loads the configuration and runs StepProducerApp through step_cloud_schemas.AppRunner, which owns signal handling (shutdown → ExitCode.ABORTED); argparse exits are mapped to ExitCode.OK/USAGE and StepCliError is logged as a single line.

  • The Redis connection model and credential now come from step_redis (RedisConnection, RedisCredential.from_env); the local copies and the python-dotenv dependency were removed, and the schema tightens the socket/keepalive bounds.

  • insert_station_collision_array commits the records of a collision array only when all of them were built.

  • doc/source/env/.env.example, the example config_redis.json (socketTimeout 40) and the crash_prediction_demo example (new crash_prediction_demo_app) were rewritten; README, architecture, commands, usage and index docs updated; docstrings and examples reviewed.

1.1.1 - Fixed

  • The main TaskGroup no longer hangs when all of the stream receive, periodical cleanup and Redis health check tasks finish: _wait_for_shutdown now also returns once every one of them is done, instead of waiting only on the shutdown event.

1.1.0 - 2026-09-15

1.1.0 - Added

  • Redis connection credentials (host/port/username/password) are now read from environment variables (REDIS_URL, REDIS_PORT, REDIS_USERNAME, REDIS_PASSWORD), loaded via a .env file (python-dotenv) instead of the persisted JSON configuration document, so secrets are no longer embedded in on-disk config. A new RedisCredential dataclass carries them; RedisConnection no longer has host/port/username/password fields. An example file is provided at doc/source/env/.env.example.

  • Graceful shutdown on POSIX (SIGINT/SIGTERM) is now handled cooperatively via loop.add_signal_handler and a new ShutdownRequestedError/_wait_for_shutdown task inside _main_async’s TaskGroup, instead of a raw signal.signal() handler raising KeyboardInterrupt from an arbitrary point in the event loop. This lets the Redis pool disconnect cleanly before _main_async returns; Windows SIGBREAK handling is unchanged. _main_async now returns an ExitCode instead of None.

  • DenmRecordInfo now stores its record_key directly (computed once at record creation) instead of reconstructing it from denm_data fields when removing an expired record; removes a code path that silently dropped a removal when those fields were missing.

  • MessageId/objectType fields added to generated DENM records; timeToCollision is now expressed in seconds; assorted validity/expiry edge-case fixes in den_service_data_manager.py.

  • src/step_producer/py.typed added, marking the package as PEP 561 typed.

1.1.0 - Changed

  • StepLogger/logging utilities moved out of step_producer into the step_cloud_schemas dependency (step_logger.py and test/test_step_logger.py removed); all Log* config classes removed from step_producer_config.py in favor of LogConfig imported from step_cloud_schemas.

  • __main__.py’s _main_async now runs a fourth concurrent task (the shutdown watcher) and factors the DENM-record and station-collision-array message handling out of _stream_receive_run into standalone _denm_message_handler / _station_collision_array_message_handler functions; stream TTL computation factored into _stream_ttl_seconds.

  • StepCliError now inherits from StepProducerError instead of Exception directly.

  • OrderedListRecord.__str__/__repr__ now include the class name in their output.

  • OrderedListRecord equality/hashing now include reference_time in addition to record_key (previously keyed on record_key alone).

  • RedisConnection.waitTimeout minimum raised to 10000 ms; retryCount field added.

  • Minimum dependency versions bumped: step_cloud_schemas>=2.4.0, step_redis>=1.5.3, pydantic>=2.13.5, plus assorted dev/doc tool bumps; python-dotenv>=1.2.3 added as a new runtime dependency.

  • Documentation updated throughout (README.rst, architecture.rst, usage.rst, index.rst) to describe the environment-variable-based Redis credentials, the new shutdown handling, and step_producer’s role in the STEP pipeline; new Sphinx coverage report pages (coverage_report.rst, docstring_coverage_report.rst) and a skip_namedtuple_fields autodoc extension added.

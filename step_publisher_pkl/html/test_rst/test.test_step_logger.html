test.test_step_logger module

Test Module: test_step_logger.

This module provides comprehensive unit tests for the logging utilities in the step_logger module. It validates the behavior of custom logging components including formatters, file rotation utilities, and logger configuration functions using pytest and pytest-mock frameworks.

Tested Components:

  • UtcFormatter: Custom logging formatter that converts timestamps to UTC time format

  • _namer: Utility function for renaming log files during rotation (replaces .log with .bz2)

  • _rotator: Utility function for compressing and rotating log files using BZIP2 compression

  • get_logger: Main function for creating and configuring loggers with various handler types

Test Coverage:

  • UTC timestamp conversion with edge cases (Unix epoch, specific timestamps, None values)

  • Log file naming conventions and extension handling during rotation

  • File compression and cleanup operations during log rotation

  • Logger configuration for multiple handler types:

    • StreamHandler (console output)

    • NullHandler (no output)

    • FileHandler (basic file logging)

    • RotatingFileHandler (size-based rotation)

    • TimedRotatingFileHandler (time-based rotation)

  • Custom formatter integration and proper handler setup

  • Directory creation for log file paths

  • Default configuration handling when no config is provided

The tests use parameterization to cover multiple scenarios and edge cases, ensuring robust logging behavior across different configurations and use cases in the step_publisher_pkl package.

Test suite for the UtcFormatter class, specifically testing the converter method.

This class contains parameterized tests to ensure that the UtcFormatter.converter method correctly converts a given timestamp into a struct_time object with the expected field values. The tests verify that the gmtime function is called with the correct arguments, the returned object is of the correct type, and all struct_time fields match the expected values for various input timestamps, including edge cases such as the Unix epoch and None.

Tested Scenarios:

  • Conversion of the Unix epoch timestamp (0).

  • Conversion of a specific timestamp (e.g., 1680307200).

  • Conversion when the timestamp is None (should use the current time).

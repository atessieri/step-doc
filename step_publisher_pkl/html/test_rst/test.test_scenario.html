test.test_scenario module

Test module for step_publisher_pkl scenario functionality.

This module contains comprehensive unit and integration tests for the Scenario class and related components in the step_publisher_pkl package. It validates scenario-based data publishing workflows, including timeline management, station positioning, data serialization, and integration with message queues and storage backends.

Key test areas:

  • TimeReference: Validates time reference dataclass behavior and immutability

  • StationPositionResult: Tests station position result structures

  • Scenario: Core scenario functionality including initialization, timeline iteration, data publishing, and integration with Redis, pickle storage, and logging systems

The tests ensure correct behavior across various scenarios, edge cases, and error conditions for the main publishing pipeline.

class test.test_scenario.TestScenario[source]

Bases: object

TestScenario contains unit tests for the Scenario class, validating its core functionalities related to vehicle trajectory data handling and time conversions.

Tested Features:

  • __slots__ definition: Ensures Scenario uses the correct slots for memory optimization.

  • Initialization: Verifies that the logger is correctly assigned during Scenario instantiation.

  • Data conversion: Tests conversion from dictionary data to CamDataV1 objects.

  • Time conversion: Validates scenario time to real-world time mapping.

  • CAM data time update: Ensures CamDataV1 creationTime is updated according to time references.

  • Data loading: Checks loading and parsing of vehicle trajectory data from pickle files, including correct storage and conversion.

  • Vehicle ID retrieval: Confirms that all vehicle IDs are correctly yielded from internal storage.

  • Vehicle position popping: Validates queue management for vehicle positions, including handling of future timestamps and logging.

  • Position array popping: Tests generator behavior for yielding all positions in a vehicle’s queue and emptying the queue.

Test Approach:

  • Uses pytest and pytest-mock for parameterized testing and mocking dependencies.

  • Covers edge cases such as empty data, single/multiple vehicles, future/past timestamps, and logger state.

  • Asserts correctness of internal state, output values, and logger interactions.

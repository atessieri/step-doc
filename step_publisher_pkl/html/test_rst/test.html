Unit Test package

Test package for the STEP Publisher Pickle microservice.

This package contains comprehensive unit tests for the STEP (Safer Transport for Europe Platform) Publisher Pickle, an MQTT-based microservice that publishes pre-recorded ITS (Intelligent Transport Systems) messages from pickle files to the STEP MQTT broker. The service enables scenario-based replay of ITS message timelines for testing, simulation, and development purposes.

The test suite provides thorough validation of all critical components including MQTT gateway communication, scenario timeline management, message format conversion, configuration management, pickle file handling, and logging capabilities.

Modules:
test_step_broker: Unit tests for the StepBroker MQTT gateway component, covering

SSL/TLS configuration, asynchronous context management, MQTT subscription handling, and ITS message publishing functionality.

test_step_publisher_pkl_config: Comprehensive tests for the configuration system,

including logging handler validation, parameter validation, schema generation, template file creation capabilities, and MQTT protocol configuration.

test_step_logger: Validation tests for the logging subsystem, ensuring proper

log formatting, handler configuration, file rotation utilities (namer, rotator), and log level management with various handler types.

test_scenario: Tests for scenario-based data publishing workflows, including

TimeReference dataclass validation, StationPositionResult structures, timeline iteration, station positioning, data serialization, and integration with Redis, pickle storage, and message queues.

test___init__: Tests for package initialization and module imports, verifying

that all expected components are properly exposed through the package’s public interface.

test___main__: Tests for command-line interface, application entry points,

signal handling, OS configuration, argument parsing, exception handling, Redis stream processing, and application lifecycle management.

Key Testing Features:

  • Asynchronous operation testing with proper context management

  • SSL/TLS security validation for MQTT broker connections

  • Scenario timeline management and time reference validation

  • Station positioning and trajectory data handling

  • Pickle file serialization and deserialization testing

  • Configuration schema validation and template generation verification

  • Redis stream operations and message queuing functionality

  • Error handling and edge case validation

  • File comparison testing for generated configuration files

  • Comprehensive coverage of ITS message types and formats

  • Cross-platform compatibility testing (Windows and Unix-like systems)

  • Signal handling and graceful shutdown procedures

Dependencies:

The test suite requires pytest for test execution, pytest-mock for mocking, temporary directory handling for file operations, and mock objects for testing external service interactions. Tests utilize file comparison utilities and parameterized testing for thorough validation coverage.

Note

All tests are designed to be independent and use temporary directories to avoid filesystem pollution. Mock objects are used extensively to isolate components under test from external dependencies like MQTT brokers and Redis instances.

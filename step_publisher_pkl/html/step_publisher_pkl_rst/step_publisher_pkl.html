step_publisher_pkl package

STEP Publisher Pickle Package.

This package provides a application for publishing vehicle position data to the STEP (Safer Transport for Europe Platform) using JSONL or PKL (Pickle) formatted scenario files. It simulates real-world Connected and Autonomous Vehicle (CAV) messaging by publishing CAM, CPM, and DENM ITS messages to an MQTT broker with realistic timing and multi-vehicle support.

The package is designed as an example implementation for testing and development within the STEP ecosystem, showcasing how to integrate vehicle trajectory data with the STEP cloud infrastructure.

Main Components:

  • Main Application (__main__.py): Asynchronous MQTT publisher with command-line interface

  • Scenario Management (scenario.py): Vehicle trajectory data loading and processing

Key Features:

  • Asynchronous publishing of CAM, CPM, and DENM messages from JSONL or PKL scenario data

  • Multi-vehicle simulation support with concurrent task execution

  • Configurable MQTT broker connection with TLS/SSL security

  • UTC-based logging with detailed debug information

  • Command-line interface for configuration and instance management

  • Realistic timing simulation based on original trajectory timestamps

  • Support for multiple vehicles from JSONL or pickle file scenarios

Architecture:

The package follows an event-driven architecture using Python’s asyncio framework. It creates separate publisher tasks for each vehicle in the scenario, allowing concurrent message publishing while maintaining realistic timing between position updates.

Message Flow:

  1. Load vehicle scenario data from JSONL or PKL format files

  2. Establish secure MQTT connection to STEP broker

  3. Create publisher tasks for each vehicle in the scenario

  4. Convert trajectory/message data to ITS messages with proper timing

  5. Continuously publish messages with scenario-based timing

  6. Handle graceful shutdown and cleanup

Data Format:

Each entry in inputFiles is auto-detected by Scenario.load_data() as one of four supported formats. The loader owning the file’s extension is tried first, then the remaining loaders in the order below:

  1. JSONL ITS messages (.jsonl-style text file): One JSON document per line, each validating as an ItsMessageRoot (CamDataV1, CpmDataV1, or DenmDataV1). A file with any invalid line or unsupported message type is rejected as a whole.

  2. Pickle actor/vehicle trajectories (.pkl): An unpickled dictionary shaped as {"trajectories": {"vehicles": {<station_id>: [<point>, ...]}}}, where each point contains:

    • Timestamped position data (latitude, longitude, altitude)

    • Vehicle dynamics (speed, heading)

    • Multiple vehicle trajectories in a single scenario file

    Each point is converted into a CAM message.

  3. Pickle camera/CPM data (.pkl): An unpickled list of dictionaries, each directly convertible to a CpmDataV1 (Collective Perception Message) object.

  4. GPX track (.gpx): Each track named Path actor <station_id>_<object_id> yields one CAM message per track point.

A file that fails validation against all four formats is skipped with a warning.

Usage Example:

Command line execution with configuration file:

python -m step_publisher_pkl -c config.json -i publisher_instance_1

Programmatic usage:

from step_publisher_pkl.loaders import PickleActorLoader, PickleCameraLoader
from step_publisher_pkl.scenario import Scenario
from logging import getLogger

logger = getLogger()
scenario = Scenario(
    stations_blacklist=set(),
    wait_time_before_starting_ms=1000,
    loaders=[PickleActorLoader(), PickleCameraLoader()],
    logger=logger,
)
scenario.load_data(input_files=["./data.pkl"])

for vehicle_id in scenario.get_vehicle_ids():
    for message in scenario.pop_message(vehicle_id):
        # Process the ITS message
        print(f"Vehicle {vehicle_id}: {message.message}")
Complexity:

  • - Time – O(1), this module only re-exports names from step_publisher_pkl_config and defines no classes or functions of its own.

  • - Space – O(1), this module only re-exports names from step_publisher_pkl_config and defines no classes or functions of its own.

Modules:

  • __main__: Command-line application: parses arguments, loads configuration, and drives the asyncio publisher event loop.

  • loaders: Pluggable FileLoader implementations (JSONL, pickle actor, pickle camera, GPX) that parse one file format each into FacilityMessage lists.

  • scenario: Loads vehicle trajectories/ITS messages through the configured FileLoader implementations and serves them per vehicle with real-world timing.

  • step_broker: MQTT/TLS gateway client for publishing ITS facility messages to the STEP broker.

  • step_exception: Exception hierarchy for CLI-specific errors.

  • step_publisher_pkl_config: Pydantic configuration models for MQTT client, MQTT protocol, STEP broker, and top-level application settings.

Complexity summary:

Let f be the number of input files, s the total number of trajectory points/messages loaded across all files, and v the number of vehicles (stations) in the scenario.

  • __main__._publisher_run / _main_async: time O(s log s) aggregated over every vehicle (O(n log n) per vehicle, popping from a sorted collection) / O(v) for task creation, space O(v).

  • loaders: GpxLoader / PickleActorLoader / PickleCameraLoader / JsonlLoader __call__: time O(p), space O(p), p = number of points/items/lines in the file.

  • scenario.Scenario.load_data / _store_messages / _update_time_stations: time O(s log s), space O(s).

  • step_broker.StepBroker.__init__: time O(p), space O(p), p = number of configured publish topics.

  • step_exception: all exception classes are O(1) time and space.

  • step_publisher_pkl_config.StepPublisherPklConfig.print_config_schema / _ConfigGenerateJsonSchema.generate: time O(n), space O(n), n = number of configuration fields.

Maximum complexity:

  • Time: O(s log s) in scenario.Scenario.load_data (and the end-to-end load-and-publish workflow it feeds), since each of the s trajectory points/messages is inserted into a sorted collection and s is unbounded and always greater than or equal to the number of vehicles v or the fixed configuration field count n.

  • Space: O(s) in scenario.Scenario.load_data / _update_time_stations, since all loaded messages are held in memory simultaneously until consumed.

Environment Variables:

MQTT broker connection secrets are kept out of the (persisted) JSON configuration file and are instead read from the process environment by __main__._get_mqtt_credential, which calls python-dotenv’s load_dotenv() before reading them so a .env file in the working directory (or an ancestor of it) is loaded automatically. The resulting values are assembled into a MqttCredential frozen dataclass.

  • MQTT_URL (required): MQTT broker host address (MqttCredential.mqtt_url, str).

  • MQTT_PORT (required): MQTT broker port number, parsed with int() (MqttCredential.mqtt_port, int).

  • MQTT_USERNAME (optional): Username for broker authentication (MqttCredential.mqtt_username, str | None).

  • MQTT_PASSWORD (optional): Password for broker authentication (MqttCredential.mqtt_password, str | None).

MQTT_URL and MQTT_PORT raise ValueError if unset; MQTT_USERNAME and MQTT_PASSWORD default to None when unset, allowing anonymous broker connections.

Example .env file:

MQTT_URL = broker.example.com
MQTT_PORT = 8883
MQTT_USERNAME = publisher
MQTT_PASSWORD = secret

Note

  • This is a package for development and testing purposes

  • Requires proper STEP broker configuration for message publishing

  • Vehicle trajectory data must be preprocessed into the expected pickle format

  • Timing accuracy depends on system performance and network latency

Exit Codes:

  • 0 (OK): Successful execution

  • 1 (USAGE): Command line usage error

  • 2 (ERROR): General runtime error

  • 3 (ABORTED): User or system interruption

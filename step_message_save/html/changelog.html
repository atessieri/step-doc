Changelog

All notable changes to step_message_save are documented in this file.

1.2.8 - 2026-10-21

1.2.8 - Changed

  • Requires step_cloud_schemas>=3.4.0,<4.0 and step_lib>=3.1.2,<4.0.

  • Build and tooling floors were raised: setuptools>=84.2.1, sphinx>=9.2.0,<10.0 and uv >=0.13.4.

  • Config field bounds now use the shared constants exported by step_cloud_schemas (STRING_MIN_LENGTH/STRING_MAX_LENGTH, UINT16_*, UINT32_*, TIMEOUT_S_*, QUEUE_SIZE_*, MQTT_PACKET_SIZE_*, TOPICS_*_LENGTH, …), so previously unbounded string, list and numeric fields now have upper limits.

  • The JSON schema of the configuration was regenerated to reflect the new bounds.

  • CI: the .tox/.python/ uv-managed interpreters path was removed from the cache.

1.2.7 - 2026-10-20

1.2.7 - Changed

  • Requires step_cloud_schemas>=3.3.3,<4.0 and step_lib>=3.1.1,<4.0.

  • Build and tooling floors were raised: setuptools>=84.2.0, sphinx>=9.1.1,<10.0 and uv >=0.13.3.

  • The GitLab pipeline is created only for tags (workflow:rules) and the per-job only: tags rules were removed.

  • CI: shallow fetch (GIT_DEPTH: 10, GIT_STRATEGY: fetch), stable uv cache key per Python version, uv-managed interpreters cached, default-jre-headless instead of openjdk-*-jre-headless.

  • CI: doc deploy runs in the step_doc resource group and retries git pull --rebase && git push up to 3 times.

  • tox.ini passes UV_CACHE_DIR through to the test environments.

  • CI: the test report of each Python version is saved and published as test_report_py*.xml.

1.2.6 - 2026-10-19

1.2.6 - Changed

  • MessageSaveApp now subclasses the step_cloud_schemas ReconnectingApp: the connection cycle is cycle() and the reconnect loop is the inherited work(), replacing the private _step_broker_run loop.

  • The MQTT credential is read by the step_lib MqttCredential.from_env; the local MqttCredential dataclass and the _get_mqtt_credential, _env_optional and _port_parse helpers were removed, and MqttCredential is no longer exported by the package.

  • Dropped the python-dotenv dependency (the .env file is loaded by step_lib).

  • Bumped step_cloud_schemas to >=3.3.1, step_lib to >=3.1.0, pytest-mock to >=3.17.0, tox to >=4.67.1 and sphinx-jsonschema to >=1.20.0.

  • Coverage gate set to 100% ([tool.coverage.report] fail_under), the JUnit report of each tox test environment is named after the environment, and the lint environment runs the source docstring doctests.

  • Rewrote the README and the architecture, usage, commands and index documentation for the new application runtime and the environment variables; documented .env.example with comments; fixed the package index URL in the installation guide.

  • Unit tests aligned to the new cycle/fatal_result workload and the step_lib MqttCredential.

1.2.6 - Fixed

  • A broker refusing the client’s authentication or authorization (StepLibMqttFatalError) now ends the program with exit code 2 (ERROR) instead of being retried forever.

1.2.5 - 2026-10-16

1.2.5 - Changed

  • Renamed “gateway” to “broker” / “broker client” in the step_broker and message_save_app module docstrings and in the package docstring.

  • MQTT_USERNAME and MQTT_PASSWORD are now optional environment variables where an empty value counts as unset.

  • The MQTT credential INFO log no longer prints the username; it reports only whether authentication is configured (auth=True|False).

  • A non-integer MQTT_PORT now raises a ValueError naming the environment variable.

  • Added unit tests for the new environment parsing helpers.

1.2.4 - 2026-10-16

1.2.4 - Changed

  • MqttProtocolConfig.sessionExpiry is now bounded to 0-4294967295 (the MQTT 5 four-byte property); the field description documents that 0 ends the session on disconnection.

  • MqttProtocolConfig.keepalive is now bounded to 0-65535 (the MQTT two-byte field); the field description documents that 0 disables the keepalive.

  • MqttProtocolConfig.timeout now requires a value of at least 1 (was 0).

  • Regenerated the v1 JSON schema and updated the config tests accordingly.

1.2.3 - 2026-10-16

1.2.3 - Fixed

  • .env file is now looked up from the current working directory (find_dotenv(usecwd=True)) instead of the installed module’s directory.

1.2.3 - Added

  • Debug log for received messages of unhandled types.

1.2.3 - Changed

  • MessageSaveApp is now instantiated inline in the app_runner.run() call.

  • Requires step_lib>=3.0.6,<4.0; dev dependencies ruff>=0.17.1, tox>=4.66.0.

1.2.2 - 2026-10-14

1.2.2 - Changed

  • Requires step_cloud_schemas>=3.2.1,<4.0 and step_lib>=3.0.5,<4.0; dev dependency tox>=4.65.5; uv>=0.13.1.

1.2.1 - 2026-10-12

1.2.1 - Added

  • message_save_app module: MessageSaveApp, the AbstractApp[ExitCode] workload holding the receive/write pipeline (receiver tasks, writer task, reconnect loop, queue drain at shutdown and MQTT credential loading), and ExitCode, both moved out of __main__.

  • MqttCredential exported from the package root.

  • Unit tests for MessageSaveApp; AppRunner section with sequence and class diagrams in the architecture docs.

1.2.1 - Changed

  • Requires step_cloud_schemas>=3.2.0,<4.0 and step_lib>=3.0.4,<4.0; pydantic>=2.14.1.

  • __main__ now only parses the command line, runs the optional conversion, loads the configuration and hands a MessageSaveApp to step_cloud_schemas.AppRunner, which owns the event loop, the loop exception handler, sys.unraisablehook, the shutdown signal handlers and the cooperative shutdown.

  • On Windows the shutdown is requested by SIGINT as well as SIGBREAK.

  • The MQTT environment variable names are private class constants of MessageSaveApp (_MQTT_URL_VAR_NAME, …); IS_WINDOWS comes from step_cloud_schemas.

  • Docstrings reviewed across the package (StepBroker, exceptions, configuration models, loaders, writers, FileConverter complexity).

  • Development dependencies updated (numpy, pylint, tox, tox-uv).

1.2.1 - Removed

  • ShutdownRequestedError and the __main__ helpers replaced by AppRunner (_main_async, _runner_run, _wait_for_shutdown, _signals_install, _signal_handler, _unraisable_handler, _exception_handler).

1.2.0 - 2026-10-09

1.2.0 - Added

  • File conversion from the command line: -f/--file (input file), -x/--convert (output format) and -o/--output (output file). The input format is deduced from the file; conversion errors exit with ExitCode.ERROR, misuse with ExitCode.USAGE.

  • file_converter.FileConverter, chaining the first accepting FileLoader with the selected FileWriter.

  • loaders subpackage: FileLoader base class, JsonlLoader and PickleActorLoader.

  • writers subpackage: FileWriter base class and GpxWriter (new gpx dependency).

  • LoaderError and WriterError exceptions.

  • sys.unraisablehook handler logging exceptions raised during object finalization.

1.0.3 - Fixed

  • StepBroker.subscribe_execution() no longer treats a broker-granted QoS lower than the configured maxSubscriptionQos as a subscription failure; only a QoS granted higher than requested (or an explicit SUBACK failure reason code, always greater than any valid QoS) now raises StepMessageSaveError. Previously, a broker legitimately downgrading QoS caused an unnecessary connection teardown, and since the same QoS was re-requested on every reconnect, this turned into an infinite reconnect loop instead of a one-time acceptance.

  • test_step_broker.py::test_init mocked TLSParameters, a symbol no longer used by StepBroker.__init__ since it was refactored to build an ssl.SSLContext directly; mocker.patch on that nonexistent attribute made the test fail outright. The test now mocks ssl.SSLContext and verifies the real construction logic (minimum TLS version, CA/client certificate loading, and the sslVerifyServerCert=False fallback that disables verification and logs a warning), restoring coverage of the TLS setup path that had none.

  • The same ssl.SSLContext refactor made every other StepBroker-constructing test in test_step_broker.py (test___aenter__ and the subscribe_execution tests) fail with FileNotFoundError, since MqttClientConfig.get_default()’s placeholder sslCaCertsFile path is now read eagerly at construction time instead of only at TLS handshake time. These tests don’t exercise SSL/TLS at all, so they now disable SSL in the config they build instead.

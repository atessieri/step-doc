   1"""Position dataset management with cubic spline interpolation.
   2
   3This module provides a comprehensive framework for managing position datasets with
   4advanced interpolation capabilities. It serves as a high-level interface for processing
   5tracking data, performing temporal validation, and generating smooth position trajectories
   6using cubic spline interpolation techniques.
   7
   8**Module Purpose:**
   9
  10The module is designed for real-time tracking applications where raw position measurements
  11need to be processed into smooth, regularly-sampled position data suitable for analysis,
  12visualization, or further processing. It handles common challenges in position data
  13processing including temporal irregularities, data validation, and cross-actor data
  14contamination prevention through multi-stage validation and bounded resource management.
  15
  16**Architecture Overview:**
  17
  18The module implements a stateful processing pipeline with two main components:
  19
  20    #. **PointDatasetConfig**: Configuration and validation dataclass that defines processing
  21       parameters including:
  22
  23        - Input queue size bounds (5-30 points)
  24        - Temporal constraints (period limits, local time deviation)
  25        - Output frequency configuration (100-1000ms nominal period)
  26        - Period deviation tolerance for interpolation
  27
  28    #. **PointDataset**: Main dataset manager that orchestrates:
  29
  30        - Position validation and temporal consistency checking
  31        - Cubic spline interpolation processing
  32        - Actor metadata management (vehicle dimensions)
  33        - Multi-path execution based on temporal characteristics
  34
  35The architecture follows a layered approach where PointDataset provides a user-friendly
  36interface while delegating core interpolation work to internal methods that handle
  37array population, spline construction, and position list generation.
  38
  39**Performance Characteristics:**
  40
  41Let:
  42    - n = input queue size (bounded by ``input_max_point_number``)
  43    - k = number of interpolated output points
  44    - m = current queue length at operation time
  45
  46**Time Complexity Analysis:**
  47
  48    - add_point() Method:
  49
  50
  51        * Overall: O(n + k*log(n) + k) worst case
  52        * No Interpolation: O(1)
  53        * Interpolation: O(n + k*log(n) + k) for 10-20% of calls
  54        * Components:
  55
  56          - Coherence validation: O(1) including haversine distance
  57          - Spline construction: O(n) for 3 dimensions
  58          - Spline evaluation: O(k*log(n)) binary search + polynomial evaluation
  59          - Position list construction: O(k)
  60
  61    - **Property Accessors**: O(1) constant time for all properties
  62    - **Configuration Validation**: O(1) constant time operations
  63
  64
  65**Space Complexity Analysis:**
  66
  67- **Persistent Storage**: O(n) - Configuration-bounded:
  68
  69    * Input queue: ~258n bytes for position records
  70    * Pre-allocated numpy arrays: ~32(n+1) bytes
  71    * Total: ~290n bytes per actor
  72
  73- **Transient Allocations** (per add_point() call):
  74
  75    * Fast path: O(1) → ~30 bytes (80-90% of calls)
  76    * Interpolation path: O(n + k) → ~(128n + 290k) bytes (10-20% of calls)
  77
  78- **Overall System**: O(n + k) with bounded growth
  79
  80    * n ≤ ``input_max_point_number`` (typically 5-30)
  81    * k ≤ ``input_max_period_ms / output_nominal_period_ms`` (typically 1-30)
  82
  83Memory Growth Characteristics:
  84    - **Bounded Growth**: Memory usage limited by configuration parameters, not by
  85      total processing duration
  86    - **Predictable Footprint**: Maximum memory calculated from ``input_max_point_number``
  87      and ``output_nominal_period_ms``
  88    - **No Memory Leaks**: Automatic cleanup via deque maxlen and garbage collection
  89      of transient allocations
  90    - **Typical Footprint**:
  91
  92      * n=30, k=20: ~8.7KB persistent, ~10KB transient peak
  93      * n=10, k=50: ~2.9KB persistent, ~16KB transient peak
  94
  95
  96Key Features:
  97    - **Temporal Coherence Validation**: Multi-stage validation ensuring positions are
  98      temporally consistent (minimum/maximum period, local time deviation, speed coherence)
  99    - **Cubic Spline Interpolation**: Generates smooth C² continuous trajectories between
 100      irregular position measurements using scipy's CubicSpline
 101    - **Configurable Output Frequency**: Supports flexible interpolation rates from 1Hz
 102      to 10Hz or higher based on configuration
 103    - **Actor Metadata Management**: Tracks and updates actor dimensions (length, width)
 104      alongside position data
 105    - **Temporal Consistency**: Validates and maintains proper time sequencing, rejecting
 106      out-of-order or temporally inconsistent data
 107    - **Gap Detection and Recovery**: Automatically handles large data gaps by clearing
 108      history to prevent unrealistic interpolation across discontinuities
 109    - **Resource Bounded Processing**: Guarantees predictable memory and computational
 110      resource usage through configuration-driven limits
 111    - **Multi-Path Execution**: Optimizes for high-frequency regular data (fast path)
 112      while handling edge cases (validation failures, interpolation needs)
 113
 114Thread Safety:
 115This module is **NOT thread-safe**. Applications requiring concurrent access from
 116multiple threads must implement external synchronization mechanisms:
 117
 118    - Recommended strategies:
 119
 120        * Thread-local instances (one PointDataset per thread per actor)
 121        * External mutex/lock for shared instance
 122        * Message passing architecture for concurrent systems
 123
 124    - Consider using thread-local storage or explicit locking strategies for
 125      multi-threaded environments
 126
 127Performance Recommendations:
 128    - **Configuration Tuning**: Balance ``input_max_point_number`` vs memory usage and
 129      ``output_nominal_period_ms`` based on downstream consumer needs
 130    - **Memory Monitoring**: Monitor memory usage in long-running applications, especially
 131      with high-frequency configurations or many actors
 132    - **Logging Levels**: Adjust logging verbosity in production to minimize I/O overhead
 133      from validation warnings
 134    - **Profiling**: Monitor interpolation path frequency and validation failure rates
 135      for optimization opportunities
 136
 137Notes:
 138    The interpolation quality is directly dependent on the density and temporal distribution
 139    of input position points. Applications should ensure sufficient point coverage within
 140    the configured period constraints for optimal results.
 141
 142    Large temporal gaps exceeding ``input_max_period_ms`` will trigger history clearing,
 143    which is necessary to prevent unrealistic interpolation across discontinuous data but
 144    may result in temporary output gaps. Consider application-level buffering for continuous
 145    output requirements.

 349class PointDataset:
 350    """Dataset manager for position tracking with cubic spline interpolation.
 351
 352    This class provides a comprehensive, high-level interface for managing position data
 353    from a specific actor (vehicle/object), performing cubic spline interpolation to
 354    generate smooth position trajectories at regular time intervals. It orchestrates
 355    position validation, temporal consistency checking, interpolation processing, and
 356    actor metadata management in a unified, cohesive system.
 357
 358    **Architecture & Design:**
 359
 360    PointDataset implements a stateful processing pipeline that maintains:
 361
 362        #. **Input Queue**: Bounded deque storing recent position measurements
 363        #. **Interpolation Buffers**: Pre-allocated numpy arrays for spline computation
 364        #. **Actor Metadata**: Vehicle dimensions (length, width) tracking
 365        #. **Configuration**: Immutable parameters controlling behavior
 366
 367    The class uses a multi-path execution model where incoming positions flow through
 368    validation gates and branch into different processing paths based on temporal
 369    characteristics, optimizing for the common case of high-frequency regular data
 370    while handling edge cases like data gaps, validation failures, and first positions.
 371
 372    Key Features:
 373        - **Temporal Coherence Validation**: Multi-stage validation ensuring positions
 374          are temporally consistent (minimum/maximum period, local time deviation, speed)
 375        - **Cubic Spline Interpolation**: Generates smooth C² continuous trajectories
 376          between irregular position measurements using scipy's CubicSpline
 377        - **Actor Metadata Tracking**: Maintains vehicle dimensions alongside position data
 378        - **Configurable Output Frequency**: Supports flexible interpolation rates from
 379          1Hz to 10Hz or higher based on configuration
 380        - **Temporal Consistency**: Validates and maintains proper time sequencing,
 381          rejecting out-of-order or temporally inconsistent data
 382        - **Gap Detection & Recovery**: Automatically handles large data gaps by clearing
 383          history to prevent unrealistic interpolation across discontinuities
 384        - **Bounded Resource Usage**: Configuration-driven limits ensure predictable
 385          memory and computational footprint
 386
 387    **Processing Pipeline:**
 388
 389    The ``add_point()`` method implements the core processing pipeline:
 390
 391    1. **Metadata Update**: Update vehicle dimensions if provided
 392    2. **Time Conversion**: Convert ISO 8601 timestamp to epoch milliseconds
 393    3. **First Position Handling**: Initialize queue if empty
 394    4. **Coherence Validation**: Check temporal and spatial consistency
 395    5. **Branching Logic**:

 397        - **Path A** (First Position): O(1) - Initialize queue
 398        - **Path B** (Too Short): O(1) - Reject position
 399        - **Path C** (Too Long/Error): O(m) - Clear history, reinitialize

 742    def _find_optimal_period(
 743        self, actor: ActorId, time_last_ms: int, time_new_ms: int
 744    ) -> tuple[int, int, bool]:
 745        """Find the optimal output period and interval count for interpolation.
 746
 747        This method computes the best possible output period (in ms) and number of intervals
 748        between two timestamps to achieve evenly-spaced interpolated points. The algorithm
 749        attempts to match the configured nominal output period while respecting the allowed
 750        deviation constraints.
 751
 752        Algorithm Overview:
 753            #. Define the valid period range: [nominal - deviation, nominal + deviation]
 754            #. Calculate the time difference between the two input timestamps
 755            #. Determine the valid range of interval counts that satisfy period constraints
 756            #. If a valid solution exists:
 757
 758                - Choose the interval count closest to the ideal (diff_time / nominal_period)
 759                - Calculate the period using integer division: diff_time // interval_count
 760
 761            #. If no exact solution exists (constraint conflict):
 762
 763                - Select the boundary interval count closest to ideal
 764                - Calculate the period using integer division: diff_time // interval_count
 765                - Mark as non-ideal solution
 766
 767        The algorithm guarantees that:
 768
 769            - All generated timestamps fall within [time_last_ms, time_new_ms]
 770            - The spacing between consecutive points respects the configured deviation
 771            - The total number of intervals optimally balances the nominal period target
 772            - Period calculation uses integer division to ensure whole millisecond values
 773
 774        Time Complexity: O(1) - All operations are constant time arithmetic
 775
 776        Args:
 777            actor (ActorId): The actor identifier for logging/debugging purposes.
 778            time_last_ms (int): Timestamp of the last recorded point in milliseconds.
 779            time_new_ms (int): Timestamp of the new incoming point in milliseconds.
 780
 781        Returns:
 782            tuple[int, int, bool]:
 783
 784            - period_optimal (int): The chosen output period in milliseconds (integer division result).
 785            - interval_number_optimal (int): The number of intervals between points.
 786            - period_ideal (bool): True if an exact solution within constraints was found,
 787              False if an approximation at the boundary was necessary.
 788
 789        Example:
 790            With nominal_period=1000ms, max_deviation=50ms:
 791
 792                - Valid period range: [950ms, 1050ms]
 793                - For diff_time=3000ms: Returns (1000, 3, True) - exact solution
 794                - For diff_time=2800ms: Returns (933, 3, False) - approximation needed
 795        """
 796        output_period_min = (
 797            self._config.output_nominal_period_ms
 798            - self._config.output_max_period_deviation_ms
 799        )
 800        output_period_max = (
 801            self._config.output_nominal_period_ms
 802            + self._config.output_max_period_deviation_ms
 803        )
 804        diff_time = time_new_ms - time_last_ms
 805        interval_number_ideal = diff_time / self._config.output_nominal_period_ms
 806        # Valid range for n: ceil(d/pt_max) <= n <= floor(d/pt_min)
 807        interval_number_min = ceil(diff_time / output_period_max)
 808        interval_number_max = floor(diff_time / output_period_min)
 809        # Solution exists with exact diff_time
 810        if interval_number_min <= interval_number_max:
 811            # Clamp to valid range
 812            interval_number_optimal = max(
 813                interval_number_min,
 814                min(interval_number_max, round(number=interval_number_ideal)),
 815            )
 816            period_optimal = diff_time // interval_number_optimal
 817            period_ideal = True
 818        # No exact solution - choose closest interval number to ideal
 819        elif abs(interval_number_max - interval_number_ideal) <= abs(
 820            interval_number_min - interval_number_ideal
 821        ):
 822            # Use interval number max
 823            interval_number_optimal = interval_number_max
 824            period_optimal = diff_time // interval_number_optimal
 825            period_ideal = False
 826        else:
 827            # Use interval number min
 828            interval_number_optimal = interval_number_min
 829            period_optimal = diff_time // interval_number_optimal
 830            period_ideal = False
 831        if self._logger.isEnabledFor(level=logging.DEBUG):
 832            self._logger.debug(
 833                msg=(
 834                    f"{actor}: period {'ideal' if period_ideal else 'optimal'}: "
 835                    f"period={period_optimal} ms, intervals={interval_number_optimal} "
 836                    f"for time diff time={diff_time} ms => range {time_last_ms} - {time_new_ms} ms, "
 837                    f"error={abs(period_optimal - self._config.output_nominal_period_ms)} ms"
 838                )
 839            )
 840        return (period_optimal, interval_number_optimal, period_ideal)

 842    def _create_interpolated_timestamp_array(
 843        self, actor: ActorId, new_position: PositionInfoRecord
 844    ) -> np.typing.NDArray[np.uint64]:
 845        """Creates an array of interpolated timestamps between the last queued position
 846        and a new position.
 847
 848        This method generates timestamps at regular intervals based on an optimal period calculated
 849        from the time difference between positions. If an ideal period cannot be found, it falls back
 850        to a non-optimal period calculation with constraints based on configured maximum deviations.
 851
 852        Time Complexity:
 853            O(k) where k is the number of intervals between the last and new position timestamps.
 854            The dominant operation is np.arange() which generates k timestamps.
 855
 856        Space Complexity:
 857            O(k) where k is the number of generated timestamps. The array size depends on the
 858            time difference and the optimal period calculated.
 859
 860        Args:
 861            actor (ActorId): The identifier of the actor for which timestamps are being generated.
 862            new_position (PositionInfoRecord): The new position record containing the target timestamp.
 863
 864        Returns:
 865            np.typing.NDArray[np.uint64]: Array of timestamps in milliseconds (epoch time) between
 866            the last position and the new position, excluding the new position timestamp itself.
 867
 868        Notes:
 869            - When ideal period is found, timestamps are generated from last_position + period
 870              to last_position + (period * interval_count) not included
 871            - When ideal period is not found (no exact multiple of output_nominal_period_ms
 872              fits within the deviation tolerance), the algorithm:
 873
 874                - Calculates the period using integer division: diff_time // interval_count
 875                - Works backwards from new_position_time to determine the first interpolated point
 876                - Ensures the first point is >= min_allowed (last_position + nominal - deviation)
 877                - May generate fewer interpolated points than the ideal case to maintain
 878                  period constraints
 879                - In extreme cases, may generate no interpolated points, outputting only
 880                  the new position
 881
 882            - Warning logs are generated when non-ideal periods are used, showing the actual
 883              time range and number of generated points
 884        """
 885        last_position_time = self._input_points_queue[-1].time
 886        new_position_time = new_position.time
 887        (period, interval_number, ideal_period_found) = self._find_optimal_period(
 888            actor=actor,
 889            time_last_ms=last_position_time.epoch_ms,
 890            time_new_ms=new_position_time.epoch_ms,
 891        )
 892        if ideal_period_found:
 893            # Create timestamp array with ideal period without the last point
 894            # substituted by new position time
 895            timestamp_ms_array = np.arange(
 896                int(last_position_time.epoch_ms + period),
 897                int(last_position_time.epoch_ms + (period * interval_number)),
 898                int(period),
 899                dtype=np.uint64,
 900            )
 901        else:
 902            # Create timestamp array with optimal period
 903            new_position_time_ms = new_position_time.epoch_ms
 904            # Minimum allowed first point
 905            min_allowed = (
 906                last_position_time.epoch_ms
 907                + self._config.output_nominal_period_ms
 908                - self._config.output_max_period_deviation_ms
 909            )
 910            # First point is new_point minus max_intervals * p
 911            first_point_ms = new_position_time_ms - (
 912                ((new_position_time_ms - min_allowed) // period) * period
 913            )
 914            # Generate timestamps from first_point to last_point with period p
 915            timestamp_ms_array = np.arange(
 916                int(first_point_ms),
 917                int(new_position_time_ms),
 918                int(period),
 919                dtype=np.uint64,
 920            )
 921            if self._logger.isEnabledFor(level=logging.WARNING):
 922                if timestamp_ms_array.size > 0:
 923                    self._logger.warning(
 924                        msg=(
 925                            f"{actor}: no ideal period => {period}, range {last_position_time} - {new_position_time} "
 926                            f"=> {ItsTime.create_from_epoch_ms(epoch_ms=timestamp_ms_array[0])} - {new_position_time} "
 927                            f"with {timestamp_ms_array.size} points without new point"
 928                        )
 929                    )
 930                else:
 931                    self._logger.warning(
 932                        msg=(
 933                            f"{actor}: no ideal period => {period}, range {last_position_time} - {new_position_time} "
 934                            f"=> only new point"
 935                        )
 936                    )
 937        return timestamp_ms_array

 939    def _create_interpolated_arrays(
 940        self, actor: ActorId, new_position: PositionInfoRecord
 941    ) -> tuple[
 942        np.typing.NDArray[np.uint64],
 943        np.typing.NDArray[np.float64],
 944        np.typing.NDArray[np.float64],
 945        np.typing.NDArray[np.int64],
 946    ]:
 947        """Create interpolated arrays for latitude, longitude, and altitude using cubic
 948        spline.
 949
 950        This method prepares numpy arrays from the input points queue and the new position,
 951        then creates cubic spline interpolators for latitude, longitude, and altitude (if available).
 952        It generates arrays of interpolated timestamps and corresponding interpolated position values.
 953
 954        **Time Complexity Analysis:**
 955
 956        Let:
 957            - n = number of input points (queue_len + 1)
 958            - k = number of output interpolated points
 959
 960        The overall time complexity is **O(n + k*log(n))**:
 961
 962        1. **Array Population Phase**: O(n)
 963           - Single pass through input queue to populate numpy arrays
 964           - Linear iteration with constant-time array assignments
 965           - Includes altitude availability check per point
 966
 967        2. **Cubic Spline Construction Phase**: O(n) for each dimension
 968           - CubicSpline constructor solves tridiagonal system of equations
 969           - Three splines created (latitude, longitude, altitude)
 970           - Scipy's CubicSpline uses Thomas algorithm with O(n) for tridiagonal solve
 971           - Total: 3 * O(n) = O(n)
 972
 973        3. **Interpolation Evaluation Phase**: O(k*log(n)) per dimension
 974           - Binary search to find intervals for each of k output points: O(k*log(n))
 975           - Polynomial evaluation per point: O(1)
 976           - Three dimensions evaluated: 3 * O(k*log(n)) = O(k*log(n))
 977
 978        4. **Timestamp Array Creation**: O(k)
 979           - Calls ``_create_interpolated_timestamp_array`` which generates k timestamps
 980           - Linear time generation using numpy operations
 981
 982        **Overall**: O(n + k*log(n)) where spline construction dominates for large n,
 983        and interpolation evaluation dominates for large k.
 984
 985        **Space Complexity Analysis:**
 986
 987        Let:
 988            - n = number of input points (queue_len + 1)
 989            - k = number of output interpolated points
 990
 991        The overall space complexity is **O(n + k)**:
 992
 993        1. **Input Storage**: O(n)
 994           - Pre-allocated numpy arrays (reused across calls):
 995             * ``_np_input_points_timestamp_ms``: n * 8 bytes (uint64)
 996             * ``_np_input_points_latitude``: n * 8 bytes (float64)
 997             * ``_np_input_points_longitude``: n * 8 bytes (float64)
 998             * ``_np_input_points_altitude``: n * 8 bytes (int64)
 999           - Total input storage: 4n * 8 = 32n bytes
1000
1001        2. **Spline Coefficients**: O(n)
1002           - Each CubicSpline stores coefficients for (n-1) intervals
1003           - Four coefficient arrays per spline (cubic polynomial)
1004           - Three splines total: 3 * 4 * (n-1) * 8 ≈ 96n bytes
1005
1006        3. **Output Storage**: O(k)
1007           - Four output arrays returned:
1008             * Interpolated timestamps: k * 8 bytes
1009             * Interpolated latitudes: k * 8 bytes
1010             * Interpolated longitudes: k * 8 bytes
1011             * Interpolated altitudes: k * 8 bytes
1012           - Total output storage: 4k * 8 = 32k bytes
1013
1014        4. **Temporary Storage**: O(k)
1015           - Intermediate arrays created during interpolation evaluation
1016           - Negligible compared to output arrays
1017
1018        **Overall**: O(n + k) with bounded growth based on configuration:
1019            - n ≤ ``max_actor_history_length_sec * input_sample_rate``
1020            - k ≤ ``max_actor_history_length_sec * output_nominal_sample_frequency``
1021
1022        **Memory Characteristics**:
1023            - Most arrays are pre-allocated and reused across method calls
1024            - Memory footprint is predictable and configuration-bounded
1025            - No dynamic memory growth beyond initial allocation
1026            - Total worst-case memory: ~(128n + 32k) bytes per actor
1027
1028        Args:
1029            actor (ActorId): The actor identifier.
1030            new_position (PositionInfoRecord): The new position to include in interpolation.
1031
1032        Returns:
1033            tuple[
1034                np.typing.NDArray[np.uint64],
1035                np.typing.NDArray[np.float64],
1036                np.typing.NDArray[np.float64],
1037                np.typing.NDArray[np.int64]]:
1038
1039            A 4-tuple of numpy arrays containing interpolated position data, structured as:
1040
1041            1. **Interpolated Timestamps** (np.typing.NDArray[np.uint64]):
1042               - Unix epoch timestamps in milliseconds for each interpolated point
1043               - Generated at regular intervals based on ``output_nominal_sample_frequency``
1044               - Array length k determined by temporal span and output frequency
1045               - Values are monotonically increasing within the interpolation window
1046               - Example: [1609459200000, 1609459200100, 1609459200200, ...] for 10Hz output
1047
1048            2. **Interpolated Latitudes** (np.typing.NDArray[np.float64]):
1049               - Latitude values in decimal degrees (WGS84 coordinate system)
1050               - Range: [-90.0, 90.0] with positive values for Northern hemisphere
1051               - Smoothly interpolated using cubic spline between input points
1052               - Same length k as timestamp array with corresponding 1:1 mapping
1053               - Precision: IEEE 754 double precision (~15-17 significant digits)
1054               - Example: [45.123456, 45.123478, 45.123501, ...]
1055
1056            3. **Interpolated Longitudes** (np.typing.NDArray[np.float64]):
1057               - Longitude values in decimal degrees (WGS84 coordinate system)
1058               - Range: [-180.0, 180.0] with positive values for Eastern hemisphere
1059               - Smoothly interpolated using cubic spline between input points
1060               - Same length k as timestamp array with corresponding 1:1 mapping
1061               - Precision: IEEE 754 double precision (~15-17 significant digits)
1062               - Example: [7.654321, 7.654345, 7.654369, ...]
1063
1064            4. **Interpolated Altitudes** (np.typing.NDArray[np.int64]):
1065               - Altitude values in centimeters above WGS84 ellipsoid
1066               - Interpolated using cubic spline if all input points have valid altitude
1067               - Filled with ``Altitude.VALUE_INVALID`` (-1) if any input lacks altitude
1068               - Same length k as timestamp array with corresponding 1:1 mapping
1069               - Integer precision sufficient for centimeter-level accuracy
1070               - Example: [45000, 45012, 45024, ...] (450.00m, 450.12m, 450.24m)
1071               - Note: Negative values other than VALUE_INVALID represent below-ellipsoid positions
1072
1073            All four arrays maintain temporal and spatial coherence, with each index i representing
1074            a complete position sample at time timestamps[i] with coordinates (latitudes[i],
1075            longitudes[i], altitudes[i]). The arrays can be directly used to construct
1076            PositionInfo objects or for trajectory analysis.
1077
1078        Raises:
1079            ValueError: If there are fewer than 2 points in the input queue.
1080
1081        Note:
1082            - Altitude interpolation is performed only if all input points and the new position have altitude.
1083            - Arrays are sized to match the queue length plus the new position.
1084        """
1085        queue_len = len(self._input_points_queue)
1086        if queue_len == 0:
1087            raise ValueError(
1088                f"{self._actor}: insufficient points to create interpolators, the queue is empty"
1089            )
1090        np_points_len = min(self._np_input_points_timestamp_ms.size, queue_len + 1)
1091        # Single vectorized pass through queue to populate arrays directly
1092        altitude_not_none = True
1093        for i, position_info_record in enumerate(self._input_points_queue):
1094            self._np_input_points_timestamp_ms[i] = position_info_record.time.epoch_ms
1095            self._np_input_points_latitude[i] = (
1096                position_info_record.position.position.latitude
1097            )
1098            self._np_input_points_longitude[i] = (
1099                position_info_record.position.position.longitude
1100            )
1101            if altitude_not_none:
1102                if position_info_record.position.position.altitude:
1103                    self._np_input_points_altitude[i] = (
1104                        position_info_record.position.position.altitude.value
1105                    )
1106                else:
1107                    altitude_not_none = False
1108        self._np_input_points_timestamp_ms[np_points_len - 1] = (
1109            new_position.time.epoch_ms
1110        )
1111        self._np_input_points_latitude[np_points_len - 1] = (
1112            new_position.position.position.latitude
1113        )
1114        self._np_input_points_longitude[np_points_len - 1] = (
1115            new_position.position.position.longitude
1116        )
1117        if altitude_not_none:
1118            if new_position.position.position.altitude:
1119                self._np_input_points_altitude[np_points_len - 1] = (
1120                    new_position.position.position.altitude.value
1121                )
1122            else:
1123                altitude_not_none = False
1124        lat_interpolator = CubicSpline(
1125            x=self._np_input_points_timestamp_ms[:np_points_len],
1126            y=self._np_input_points_latitude[:np_points_len],
1127        )
1128        lon_interpolator = CubicSpline(
1129            x=self._np_input_points_timestamp_ms[:np_points_len],
1130            y=self._np_input_points_longitude[:np_points_len],
1131        )
1132        alt_interpolator = (
1133            CubicSpline(
1134                x=self._np_input_points_timestamp_ms[:np_points_len],
1135                y=self._np_input_points_altitude[:np_points_len],
1136            )
1137            if altitude_not_none
1138            else None
1139        )
1140        interpolation_time_ms = self._create_interpolated_timestamp_array(
1141            actor=actor, new_position=new_position
1142        )
1143        return (
1144            interpolation_time_ms,
1145            lat_interpolator(x=interpolation_time_ms, extrapolate=False),
1146            lon_interpolator(x=interpolation_time_ms, extrapolate=False),
1147            (
1148                alt_interpolator(x=interpolation_time_ms, extrapolate=False).astype(
1149                    np.int64
1150                )
1151                if alt_interpolator
1152                else np.full(
1153                    shape=interpolation_time_ms.shape,
1154                    fill_value=Altitude.VALUE_INVALID,
1155                    dtype=np.int64,
1156                )
1157            ),
1158        )

1160    def _create_interpolated_position(
1161        self, params: InterpolatedPositionParams
1162    ) -> PositionInfo:
1163        """Create an interpolated position with calculated speed and heading.
1164
1165        Generates a new PositionInfo object for an interpolated position by calculating
1166        the speed and heading based on the distance and bearing between the previous
1167        and current positions. The position is marked as estimated and includes
1168        computed motion parameters.
1169
1170        Time Complexity:
1171            O(1): All operations are constant time:
1172
1173            - Geocode distance calculation: O(1) (haversine formula)
1174            - Geocode bearing calculation: O(1) (atan2 trigonometric function)
1175            - Object instantiation: O(1)
1176            - Mathematical operations: O(1)
1177
1178        Space Complexity:
1179            O(1): Constant space usage:
1180
1181            - Fixed number of local variables regardless of input size
1182            - Object creation uses constant memory
1183            - No data structures that grow with input parameters
1184
1185        Args:
1186            params (InterpolatedPositionParams): Parameters for creating the interpolated position.
1187                This includes all necessary information such as station info, object ID, current and previous
1188                timestamps, coordinates, altitude, and position type.
1189
1190
1191        Returns:
1192            PositionInfo: A new PositionInfo object containing:
1193
1194            - Station and object identification
1195            - Position type marked as ``POSITION_GNSS_ESTIMATED`` or ``POSITION_PERCEIVED_ESTIMATED``
1196            - Interpolated spatial coordinates (lat, lon, alt)
1197            - Calculated speed based on distance and time difference (None if time_diff <= 0)
1198            - Calculated heading based on bearing between positions
1199            - Drive direction set to None
1200
1201        Raises:
1202            ValidationError: If calculated speed or heading values are outside valid ranges
1203            defined by Speed and Heading schemas.
1204
1205        Note:
1206            Speed calculation uses the formula: (distance_m * Speed.SCALE_FACTOR) / time_diff_ms
1207            where Speed.SCALE_FACTOR converts from m/ms to 0.01 m/s units.
1208            Heading is scaled by Heading.SCALE_FACTOR to convert degrees to 0.1 degree units.
1209        """
1210        time_diff_ms = params.current_time.time_difference(
1211            other_time=params.previous_time
1212        )
1213        self._geocode.point_a = (params.previous_lat, params.previous_lon)
1214        self._geocode.point_b = (params.current_lat, params.current_lon)
1215        distance_m = self._geocode.get_distance(unit=DistanceUnit.METERS)
1216        bearing_deg = self._geocode.get_bearing(unit=AngleUnit.DEGREES)
1217        if time_diff_ms > 0:
1218            speed_obj = Speed(
1219                value=round(
1220                    (distance_m * Speed.SCALE_FACTOR * ItsTime.SEC_TO_MS_FACTOR)
1221                    / time_diff_ms
1222                ),
1223                confidence=None,
1224            )
1225            heading_obj = Heading(
1226                value=round(bearing_deg * Heading.SCALE_FACTOR), confidence=None
1227            )
1228        else:
1229            speed_obj = None
1230            heading_obj = None
1231        if self._logger.isEnabledFor(level=logging.DEBUG):
1232            self._logger.debug(
1233                msg=(
1234                    f"{params.object_id}: creating interpolated position at {params.current_time} "
1235                    f"with distance={distance_m:.2f} m, bearing={bearing_deg:.2f} deg, "
1236                    f"time_diff={time_diff_ms} ms => speed={speed_obj} (0.01 m/s)"
1237                )
1238            )
1239        return PositionInfo(
1240            stationInfo=params.station_info,
1241            objectId=params.object_id,
1242            positionType=params.position_type,
1243            time=str(object=params.current_time),
1244            position=ReferencePosition(
1245                latitude=params.current_lat,
1246                longitude=params.current_lon,
1247                positionConfidence=None,
1248                altitude=Altitude(value=params.current_alt, confidence=None)
1249                if params.current_alt is not None
1250                else None,
1251            ),
1252            speed=speed_obj,
1253            heading=heading_obj,
1254            driveDirection=None,
1255        )

1257    def _manage_real_position_speed_heading(
1258        self,
1259        real_position_time: ItsTime,
1260        real_position: PositionInfo,
1261        previous_time: ItsTime,
1262        previous_lat: float,
1263        previous_lon: float,
1264    ) -> PositionInfo:
1265        """Update speed and heading on a real (measured) position if they are not set.
1266
1267        If the position already has both speed and heading defined, it is returned
1268        unchanged. Otherwise, speed and heading are computed from the geodesic distance
1269        and bearing between the previous position coordinates and the current real
1270        position, then applied via a model copy.
1271
1272        Time Complexity:
1273            O(1): All operations execute in constant time:
1274
1275            - Speed/heading presence check: O(1)
1276            - Geocode distance calculation: O(1) (haversine formula)
1277            - Geocode bearing calculation: O(1) (atan2 trigonometric function)
1278            - Speed and heading object instantiation: O(1)
1279            - model_copy with updated fields: O(1)
1280
1281        Space Complexity:
1282            O(1): Constant space usage regardless of input:
1283
1284            - Fixed number of local variables (speed_obj, heading_obj, etc.)
1285            - model_copy creates a shallow copy with only the updated fields replaced
1286
1287        Args:
1288            real_position_time (ItsTime): Timestamp of the real (measured) position,
1289                used for time-difference and speed computation.
1290            real_position (PositionInfo): The measured position to enrich with motion
1291                data. Returned unchanged if both speed and heading are already set.
1292            previous_time (ItsTime): Timestamp of the immediately preceding position.
1293            previous_lat (float): Latitude of the preceding position in decimal degrees.
1294            previous_lon (float): Longitude of the preceding position in decimal degrees.
1295
1296        Returns:
1297            PositionInfo: The original ``real_position`` unchanged if both speed and
1298            heading are already set; otherwise a shallow copy with speed and heading
1299            computed from the displacement relative to the previous position.
1300
1301        Note:
1302            Speed calculation yields None when the time difference between
1303            ``real_position_time`` and ``previous_time`` is zero or negative.
1304        """
1305        if (real_position.speed is not None) and (real_position.heading is not None):
1306            return real_position
1307        time_diff_ms = real_position_time.time_difference(other_time=previous_time)
1308        self._geocode.point_a = (previous_lat, previous_lon)
1309        self._geocode.point_b = (
1310            real_position.position.latitude,
1311            real_position.position.longitude,
1312        )
1313        distance_m = self._geocode.get_distance(unit=DistanceUnit.METERS)
1314        bearing_deg = self._geocode.get_bearing(unit=AngleUnit.DEGREES)
1315        if time_diff_ms > 0:
1316            speed_obj = Speed(
1317                value=round(
1318                    (distance_m * Speed.SCALE_FACTOR * ItsTime.SEC_TO_MS_FACTOR)
1319                    / time_diff_ms
1320                ),
1321                confidence=None,
1322            )
1323            heading_obj = Heading(
1324                value=round(bearing_deg * Heading.SCALE_FACTOR), confidence=None
1325            )
1326        else:
1327            speed_obj = None
1328            heading_obj = None
1329        if self._logger.isEnabledFor(level=logging.DEBUG):
1330            self._logger.debug(
1331                msg=(
1332                    f"Calculated speed {speed_obj.value if speed_obj else 'None'} {(1 / Speed.SCALE_FACTOR):.2f}m/s, "
1333                    f"heading: {heading_obj.value if heading_obj else 'None'} {(1 / Heading.SCALE_FACTOR):.2f}deg, "
1334                    f"current position time: {real_position_time!s}, previous position time: {previous_time!s}"
1335                )
1336            )
1337        return real_position.model_copy(
1338            update={"speed": speed_obj, "heading": heading_obj}
1339        )

1341    def _create_positions_list(  # pylint: disable=too-many-locals
1342        self, actor: ActorId, new_position: PositionInfoRecord
1343    ) -> list[PositionInfo]:
1344        """Create a list of interpolated positions from the last queued position to the
1345        new position.
1346
1347        This method generates a complete trajectory of position points between the most recent
1348        position in the input queue and a newly arrived position. It implements two distinct
1349        processing paths based on the temporal gap between positions:
1350
1351        1. **Fast Path (No Interpolation)**: When the time difference is within the nominal
1352           output period plus deviation, the new position is directly appended without
1353           interpolation, optimizing for high-frequency data streams.
1354
1355        2. **Interpolation Path**: When the time gap exceeds the threshold, cubic spline
1356           interpolation generates intermediate positions at regular intervals, ensuring
1357           smooth trajectory continuity for visualization and analysis.
1358
1359        The method orchestrates the complete interpolation pipeline: generating interpolated
1360        coordinate arrays, constructing PositionInfo objects with calculated motion parameters
1361        (speed and heading), and maintaining the input queue state.
1362
1363        **Processing Workflow:**
1364
1365        1. Validate input queue is not empty (raises exception if empty)
1366        2. Calculate time difference between last queued position and new position
1367        3. **Decision Point:**
1368
1369           a. If diff_time ≤ nominal_period + max_deviation:
1370              - Append new position to queue
1371              - Return single-element list [new_position]
1372              - Complexity: O(1)
1373
1374           b. If diff_time > nominal_period + max_deviation:
1375              - Generate interpolated arrays via ``_create_interpolated_arrays()``
1376              - Iterate through interpolated timestamps
1377              - For each timestamp, create PositionInfo with:
1378                * Interpolated coordinates (lat, lon, alt)
1379                * Calculated speed and heading from previous position
1380                * Station and object identification
1381              - Append new position as final point
1382              - Add new position to queue
1383              - Return complete positions list
1384              - Complexity: O(n + k*log(n) + k)
1385
1386        **Time Complexity Analysis:**
1387
1388        Let:
1389            - n = number of input points in queue (bounded by ``input_max_point_number``)
1390            - k = number of interpolated output points generated
1391
1392        **Overall Complexity: O(n + k*log(n) + k)**
1393
1394        **Component Breakdown:**
1395
1396        1. **Initial Validation & Time Calculation**: O(1)
1397           - Queue length check: O(1)
1398           - Time difference calculation: O(1)
1399
1400        2. **Fast Path (No Interpolation)**: O(1)
1401           - Condition check: O(1)
1402           - Queue append: O(1) amortized (deque with maxlen)
1403           - List creation: O(1)
1404           - **Total Fast Path: O(1)**
1405
1406        3. **Interpolation Path**: O(n + k*log(n) + k)
1407
1408           a. **Array Interpolation**: O(n + k*log(n))
1409
1410              - Calls ``_create_interpolated_arrays()``:
1411
1412                * Input array population: O(n)
1413                * Cubic spline construction: O(n) for 3 dimensions
1414                * Spline evaluation: O(k*log(n)) for k output points
1415
1416
1417           b. **Position List Construction**: O(k)
1418
1419              - Iterate k interpolated timestamps: O(k) iterations
1420              - Per iteration:
1421
1422                * Type conversions: O(1)
1423                * Call ``_create_interpolated_position()``: O(1)
1424
1425                  - Distance calculation (haversine): O(1)
1426                  - Bearing calculation: O(1)
1427                  - Speed/heading computation: O(1)
1428                  - PositionInfo instantiation: O(1)
1429
1430                * List append: O(1) amortized
1431
1432              - **Total Loop: k * O(1) = O(k)**
1433
1434
1435           c. **Finalization**: O(1)
1436
1437              - Append new position to list: O(1)
1438              - Append new position to queue: O(1)
1439
1440
1441           **Total Interpolation Path: O(n + k*log(n) + k)**
1442
1443        4. **Dominant Operations by Input Size:**
1444           - Small k (few interpolated points): O(n) dominates (spline construction)
1445           - Large k (many interpolated points): O(k*log(n)) dominates (spline evaluation)
1446           - Queue operations: O(1) amortized, negligible impact
1447
1448        **Space Complexity Analysis:**
1449
1450        Let:
1451            - n = number of input points in queue
1452            - k = number of interpolated output points
1453
1454        **Overall Complexity: O(n + k)**
1455
1456        **Component Breakdown:**
1457
1458        1. **Fast Path Space**: O(1)
1459           - Single PositionInfo reference in result list
1460           - Queue append reuses internal deque capacity
1461           - No additional allocations
1462           - **Total: O(1)**
1463

1651        last_position_time: Optional[ItsTime],

1654        """Check the temporal and spatial coherence of a new position relative to the
1655        last recorded position.
1656
1657        This method validates the new position by performing the following checks:
1658            - Minimum period: Ensures the time difference between the new and
1659              last position is not below the configured minimum.
1660            - Maximum period: Ensures the time difference does not exceed the
1661              configured maximum.
1662            - Local time deviation: Checks if the new position's timestamp is
1663              coherent with the system's local time.
1664            - Speed coherence: Calculates the speed between the two positions and
1665              ensures it does not exceed the defined threshold.
1666
1667        If any check fails, an appropriate InsertPointResult is returned and a warning is logged.
1668
1669        Args:
1670            new_position_time (ItsTime): Time of the new position.
1671            new_position (PositionInfo): Information about the new position.
1672            last_position_time (Optional[ItsTime]): Time of the last recorded position.
1673            last_position (Optional[PositionInfo]): Information about the last recorded position.
1674
1675        Returns:
1676            InsertPointResult: Result indicating the outcome of the coherence check.
1677
1678        Time Complexity:
1679            O(1): All checks — time difference, period bounds, local-time deviation,
1680            haversine distance, and speed comparison — execute in constant time.
1681
1682        Space Complexity:
1683            O(1): A fixed number of local variables are used; no data structures
1684            grow with input size.
1685        """
1686        if last_position_time and last_position:
1687            diff_time_ms = new_position_time.time_difference(
1688                other_time=last_position_time
1689            )
1690            # Minimum period
1691            minimum_period = (
1692                self._config.output_nominal_period_ms
1693                - self._config.output_max_period_deviation_ms
1694            )
1695            if diff_time_ms < minimum_period:
1696                if self._logger.isEnabledFor(level=logging.WARNING):
1697                    self._logger.warning(
1698                        msg=f"{self._actor}: new position time {new_position_time} "
1699                        f"is too close (min {minimum_period} ms) to last position time "
1700                        f"{last_position_time}, diff time {diff_time_ms} ms"
1701                    )
1702                return InsertPointResult.PERIOD_TOO_SHORT_ERROR
1703            # Maximum period
1704            if diff_time_ms > self._config.input_max_period_ms:
1705                if self._logger.isEnabledFor(level=logging.WARNING):
1706                    self._logger.warning(
1707                        msg=f"{self._actor}: new position time {new_position_time} "
1708                        f"is too far (max {self._config.input_max_period_ms} ms) from the last recorded time "
1709                        f"{last_position_time}, diff time {diff_time_ms} ms"
1710                    )
1711                return InsertPointResult.PERIOD_TOO_LONG_ERROR
1712            # Speed coherence
1713            self._geocode.point_a = (
1714                last_position.position.latitude,
1715                last_position.position.longitude,
1716            )
1717            self._geocode.point_b = (
1718                new_position.position.latitude,
1719                new_position.position.longitude,
1720            )
1721            # Speed calculation in m/s
1722            speed = (
1723                self._geocode.get_distance(DistanceUnit.METERS)
1724                * ItsTime.SEC_TO_MS_FACTOR
1725            ) / diff_time_ms
1726            if speed > self.SPEED_COHERENCE_THRESHOLD:
1727                if self._logger.isEnabledFor(level=logging.WARNING):
1728                    self._logger.warning(
1729                        msg=f"{self._actor}: position speed {speed} m/s exceeds threshold "
1730                        f"{self.SPEED_COHERENCE_THRESHOLD} m/s"
1731                    )
1732                return InsertPointResult.POSITION_ERROR
1733        # Local time deviation
1734        now = ItsTime()
1735        if not (
1736            now.epoch_ms - self._config.input_max_local_time_deviation_ms
1737            <= new_position_time.epoch_ms
1738            <= now.epoch_ms + self._config.input_max_local_time_deviation_ms
1739        ):
1740            if self._logger.isEnabledFor(level=logging.WARNING):
1741                self._logger.warning(
1742                    msg=f"{self._actor}: new position time {new_position_time} "
1743                    f"is not coherent with local system time {now} "
1744                    f"due to deviation threshold of {self._config.input_max_local_time_deviation_ms} ms"
1745                )
1746            return InsertPointResult.LOCAL_TIME_NOT_COHERENT_ERROR
1747        return InsertPointResult.SUCCESS

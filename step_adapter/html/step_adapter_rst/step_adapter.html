step_adapter package

STEP Adapter - conversion of CAM and CPM messages into position arrays.

The package implements the STEP Adapter program: it reads CAM and CPM messages from a Redis input stream, converts them into PositionArrayV1 messages and publishes them to the crash prediction Redis stream.

Processing:

  • CAM messages (ActorDataset): every sender (ActorId) has its own PointDataset holding the last n positions. A new position is validated against the previous one (minimum/maximum period, implied speed, local time deviation); when the gap from the previous position exceeds the nominal output period plus the deviation, the gap is filled with positions interpolated by a Hermite segment on the reported speed and heading at the configured output frequency (outputNominalSampleFrequency). Speed and heading are recomputed from the geodesic displacement (a real position after a filled gap keeps them when it reports both). A too large gap, or an implausible speed against a single position, clears the history and restarts the trajectory from the new position; an implausible speed against a confirmed history discards the new position. Actors whose last position is older than inputOldestAllowedTime are removed periodically by the cleaner task.

  • CPM messages (ObjectPerceivedDataset): every perceived object is converted into one position array, from its measured position and its predicted path resampled at the output frequency (interpolated when the CPM period is longer, decimated when shorter), without any history between messages.

  • Resampling (step_cloud_schemas.GapFiller): the Hermite and cubic spline interpolation and the output period grid shared by the CAM and CPM datasets, provided by the step_cloud_schemas.gnss subpackage.

  • Program (StepAdapterApp, step_adapter.__main__): a reconnecting AppRunner workload running the stream receive, cleaner and Redis health check tasks on a single asyncio event loop; the datasets are not thread-safe and need no lock there.

Let:

  • n = maxActorHistoryPointNumber (input_max_point_number), the per-actor history size (5-30).

  • k = interpolated positions generated by one CAM insertion, bounded by inputMaxPeriod / (output nominal period - outputPeriodMaxDeviation).

  • m = number of tracked actors.

  • r = number of actors expired by one cleanup.

  • o = perceived objects in one CPM message, at most CpmDataV1.PERCEIVED_OBJECTS_MAX_LENGTH (255).

  • p = predicted path points of one perceived object, at most PerceivedObject.POSITION_PREDICTED_MAX_LENGTH (255).

  • g = resampled points of one perceived object, at most PositionArrayV1.POINTS_MAX_LENGTH (101).

  • s = size of the generated configuration JSON schema.

  • f = size of the loaded configuration file.

Modules:

  • __main__: Command-line entry point; writes the configuration schema and template, or loads the configuration and runs StepAdapterApp.

  • actor_dataset: Per-actor PointDataset registry fed by CAM messages, with time-ordered cleanup of expired actors.

  • numeric_bounds: Inclusive numeric bounds shared by the JSON configuration and PointDatasetConfig.

  • object_perceived_dataset: Conversion of CPM perceived objects into position arrays resampled at the output period.

  • point_dataset: Per-actor position history with coherence checks; the gaps are filled by step_cloud_schemas.GapFiller.

  • step_adapter_app: The reconnecting adapter workload on the Redis streams and the program exit codes.

  • step_adapter_config: Pydantic configuration models, JSON schema and template generation.

  • step_exception: Exception hierarchy of the package.

Complexity:

  • - Time – O(1), this module only re-exports names and defines constants.

  • - Space – O(1), a fixed number of names is exported.

Complexity summary:

  • __main__.main: time O(s + f) for the setup, then the indefinite run of StepAdapterApp; space O(s + f) for the setup.

  • actor_dataset.ActorDataset: time O(n + k + log(m)) per CAM message (add_cam_message) and up to O(m*log(m)) per cleanup (clear_old_points); space O(m*n + k).

  • numeric_bounds: constants only; time O(1), space O(1).

  • object_perceived_dataset.ObjectPerceivedDataset.add_cpm_message: time O(o*(p + g*log(p))), space O(o*g + p).

  • point_dataset.PointDataset.add_point: time O(n + k), space O(n + k).

  • step_adapter_app.StepAdapterApp: time O(n + k + log(m)) per CAM message, O(o*(p + g*log(p))) per CPM message and up to O(m*log(m)) per cleaner iteration; space O(m*n + k + o*g + p).

  • step_adapter_config.StepAdapterConfig.print_config_schema: time O(s), space O(s).

  • step_exception.StepAdapterError: time O(1), space O(1).

Maximum complexity:

  • Time: O(m*log(m)) in actor_dataset.ActorDataset.clear_old_points (worst case of the SortedList slice deletion) and O(o*(p + g*log(p))) in object_perceived_dataset.ObjectPerceivedDataset.add_cpm_message, not comparable: m is the only quantity bounded by neither the configuration nor the schemas, while o, p and g are bounded by the schemas.

  • Space: O(m*n + k + o*g + p) in step_adapter_app.StepAdapterApp, dominated by the O(m*n) actor histories of actor_dataset.ActorDataset.

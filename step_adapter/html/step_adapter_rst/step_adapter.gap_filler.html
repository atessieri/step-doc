step_adapter.gap_filler module

Output period resampling shared by the CAM and CPM position datasets.

Turns irregularly-timed positions into positions at the configured output period, using cubic spline interpolation between real measurements:

  • GapFiller.fill (streaming, CAM): fills the gap between the last queued position of an actor and a new one with interpolated positions, used by PointDataset when the gap exceeds the nominal output period plus the deviation. A gap shorter than the nominal period minus the deviation never reaches it: PointDataset rejects the position (streaming decimation).

  • GapFiller.resample (batch, CPM): resamples a whole time-ordered list of positions on the output period grid, used by ObjectPerceivedDataset: longer input periods are interpolated, shorter ones decimated.

Main components:

  • GapFillerConfig: immutable, validated resampling parameters (output period, deviation, altitude trailing run percentage).

  • GapFiller: stateless resampler (configuration and logger only), so one instance can be shared.

Let:

  • n = number of input points of one spline (CAM: queue plus new point, 2-31; CPM: measured plus predicted points).

  • k = number of output points generated by one call (CAM: interpolated positions; CPM: grid points, at most the given maximum point number).

Thread Safety:

GapFiller keeps no mutable state, so concurrent calls are safe as long as the logger is.

Complexity:

  • - Time – O(n + k*log(n)), dominated by GapFiller.interpolate (spline construction O(n), evaluation O(k*log(n))).

  • - Space – O(n + k), the spline coefficients plus the k output positions.

Classes:

  • GapFillerConfig: Validated, immutable resampling parameters. Complexity: time O(1), space O(1).

  • OptimalPeriod: Output period chosen for one interpolation. Complexity: time O(1), space O(1).

  • InterpolatedArrays: Interpolated coordinates of one interpolation. Complexity: time O(1), space O(k).

  • MotionValues: Speed and heading computed from a displacement. Complexity: time O(1), space O(1).

  • ChainMotion: Vectorized motion arrays of one position chain. Complexity: time O(1), space O(k).

  • GapFiller: Stateless output period resampler. Complexity: time O(n + k*log(n)), space O(n + k).

Vectorized geodesic and motion arrays for one position chain.

The chain is a sequence of c time-ordered points (origin first), i.e. c - 1 consecutive pairs; row i (for i in [0, c - 2]) holds the values for the pair from chain point i to chain point i + 1.

class step_adapter.gap_filler.GapFiller(config_par: GapFillerConfig, logger: Logger)[source]

Bases: object

Stateless output period resampler with cubic spline interpolation.

Holds only the configuration and the logger. fill interpolates the gap between two consecutive positions of a stream (CAM), resample puts a whole time-ordered list of positions on the output period grid (CPM). Estimated positions are typed POSITION_GNSS_ESTIMATED for a GNSS template, POSITION_PERCEIVED_ESTIMATED otherwise, and the speed/heading of every output position after the first one is recomputed from the geodesic displacement.

config_par

Resampling parameters (output period, deviation, altitude trailing run percentage).

Type:

GapFillerConfig

logger

Logger for the debug traces and the non-ideal period warnings.

Type:

Logger

Thread Safety:

No mutable state is kept: concurrent calls are safe as long as the logger is.

Complexity:

  • - Time – O(n + k*log(n)), driven by fill and resample (see interpolate).

  • - Space – O(n + k), the spline coefficients plus the k output positions.

apply_motion(position: PositionInfo, distance_m: float, heading_deg: float, time_diff_ms: int) → PositionInfo[source]

Return position with speed/heading (re)computed from the given motion.

Speed and heading reported by the sender are intentionally not trusted or preserved here: they are always recomputed (_speed_heading_from_motion) from the geodesic displacement relative to the previous point, since the caller already has that distance/heading available (no extra Geocode call is made). The computed values are logged at DEBUG level.

Parameters:

  • position (PositionInfo) – Real (measured) position to enrich with motion data.

  • distance_m (float) – Geodesic distance to the previous point, in meters.

  • heading_deg (float) – Forward azimuth from the previous point, in degrees.

  • time_diff_ms (int) – Time elapsed since the previous point, in milliseconds.

Returns:

Shallow copy of position with recomputed speed and

heading (both None when time_diff_ms is not strictly positive).

Return type:

PositionInfo

Complexity:

  • - Time – O(1), a fixed amount of arithmetic and one shallow model copy.

  • - Space – O(1), model_copy creates a shallow copy with only speed/heading replaced.

Interpolate latitude, longitude and (if available) altitude via cubic spline.

Fits a vector-valued CubicSpline over (latitude, longitude[, altitude]) of the input points - sharing one tridiagonal solve across columns - and evaluates it, without extrapolation, at target_times_ms. The longitudes are unwrapped (numpy.unwrap with period LONGITUDE_RANGE) before the fit, so a trajectory crossing the antimeridian stays continuous; the interpolated longitudes may then lie outside [LONGITUDE_MIN, LONGITUDE_MIN + LONGITUDE_RANGE). The altitude is a column of the shared spline when every point has one. Otherwise only the trailing run of consecutive points with altitude (ending at the last point) is used, by a separate spline, when its length reaches _required_altitude_trailing_point_number; a target time before the run gets NaN (no extrapolation).   • longitudes (np.typing.NDArray[np.float64]) – Input longitudes in decimal degrees.

  • altitudes_m (np.typing.NDArray[np.float64]) – Input altitudes in meters, NaN where missing.

  • target_times_ms (np.typing.NDArray[np.int64]) – Timestamps in milliseconds (epoch time) at which the spline is evaluated, within the input range.

Returns:

unwrapped longitudes (decimal degrees) and altitudes (meters, NaN where the altitude cannot be interpolated).

Return type:

interpolation_timestamps(actor: ActorId, time_last_ms: int, time_new_ms: int) → NDArray[int64][source]

Create the interpolated timestamps between two timestamps.

Gets the interval count n from optimal_period and spreads the n - 1 timestamps evenly over the gap d: timestamp i (1 <= i < n) is time_last_ms + floor(i * d / n). Every interval, the last one up to time_new_ms included, is then the floor or the ceiling of d / n, so the d % n remainder is spread instead of piling up on the last interval. With an ideal period (d / n within the integer bounds nominal period -/+ deviation) every interval stays within the configured deviation; with a non-ideal period the intervals are the closest achievable to the nominal period and a warning is logged. A single interval gives no timestamp.

Parameters:

  • actor (ActorId) – The identifier of the actor for which timestamps are being generated.

  • time_last_ms (int) – Timestamp of the range start in milliseconds (epoch time).

  • time_new_ms (int) – Timestamp of the range end in milliseconds (epoch time).

Returns:

Array of n - 1 timestamps in milliseconds

(epoch time) between time_last_ms and time_new_ms, excluding both of them.

Return type:

np.typing.NDArray[np.int64]

Raises:

ValueError – If time_new_ms does not follow time_last_ms.

Example

Ideal period, 10 Hz (nominal 100 ms, deviation 25 ms, intervals allowed in [75, 125] ms), range from 0 ms to 2999 ms: n = 30. Each timestamp is placed on its own proportional position, so its rounding error stays below 1 ms and never accumulates:

  • i = 1: floor(1 * 2999 / 30) = floor(99.97) = 99, interval 99.

  • i = 2: floor(2 * 2999 / 30) = floor(199.93) = 199, interval 199 - 99 = 100.

  • …

  • i = 29: floor(29 * 2999 / 30) = floor(2899.03) = 2899, interval 100; last interval up to the range end 2999 - 2899 = 100.

Every interval is 99 or 100 ms. Adding the rounded period 2999 // 30 = 99 thirty times instead would place the last timestamp at 2871 ms, leaving a last interval of 2999 - 2871 = 128 ms, above 125.

Non-ideal period, 1 Hz (nominal 1000 ms, deviation 25 ms, intervals allowed in [975, 1025] ms), range from 0 ms to 1900 ms: no n fits (n = 1 gives 1900, n = 2 gives 950), so optimal_period picks n = 2, the closest to the nominal period. The single timestamp is floor(1 * 1900 / 2) = 950, giving two intervals of 950 ms, 25 ms below the minimum but the closest achievable, instead of dropping it and leaving one interval of 1900 ms.

Complexity:

  • - Time – O(k), k = n - 1 generated timestamps, for np.arange and the vectorized arithmetic.

  • - Space – O(k), for the returned array.

optimal_period(actor: ActorId, time_last_ms: int, time_new_ms: int) → OptimalPeriod[source]

Find the optimal output period and interval count for interpolation.

This method computes the best possible output period (in ms) and number of intervals between two timestamps to achieve evenly-spaced interpolated points. The algorithm attempts to match the configured nominal output period while respecting the allowed deviation constraints.

Algorithm Overview:

  1. Define the valid period range: [nominal - deviation, nominal + deviation]

  2. Calculate the time difference between the two input timestamps

  3. Determine the valid range of interval counts that satisfy period constraints: ceil(diff / period_max) <= count <= floor(diff / period_min)

  4. If a valid solution exists:

    • Take as candidates the floor and the ceiling of the ideal count (diff_time / nominal_period), each clamped to the valid range

    • Mark as ideal solution

  5. If no exact solution exists (constraint conflict):

    • Take as candidates the two boundary counts, the maximum one only when at least one (a time difference shorter than the minimum period gives one interval)

    • Mark as non-ideal solution

  6. Choose the candidate whose period diff_time / count is closest to the nominal period (the smaller count on a tie) and calculate the period using integer division: diff_time // count

The chosen period and interval count are logged at DEBUG level.

Parameters:

  • actor (ActorId) – The actor identifier for logging/debugging purposes.

  • time_last_ms (int) – Timestamp of the last recorded point in milliseconds.

  • time_new_ms (int) – Timestamp of the new incoming point in milliseconds.

Returns:

The chosen period in milliseconds (integer division

result), the number of intervals between the points, and the ideal flag (True if an exact solution within constraints was found, False if an approximation at the boundary was necessary).

Return type:

OptimalPeriod

Raises:

ValueError – If time_new_ms does not follow time_last_ms.

Example

Ideal solution, 10 Hz (nominal 100 ms, deviation 25 ms, valid period range [75, 125] ms), diff_time = 245 ms:

  • Ideal count: 245 / 100 = 2.45.

  • Valid counts: ceil(245 / 125) = 2 <= n <= floor(245 / 75) = 3, so an exact solution exists.

  • Candidates: floor(2.45) = 2 and ceil(2.45) = 3, both valid.

  • n = 2: period 245 / 2 = 122.5 ms, error abs(122.5 - 100) = 22.5 ms.

  • n = 3: period 245 / 3 = 81.7 ms, error abs(81.7 - 100) = 18.3 ms.

  • Returns OptimalPeriod(81, 3, True): n = 3 has the smaller error and 245 // 3 = 81. Rounding the ideal count, round(2.45) = 2, would have picked the worse candidate.

Non-ideal solution, 1 Hz (nominal 1000 ms, deviation 50 ms, valid period range [950, 1050] ms), diff_time = 2800 ms:

  • Ideal count: 2800 / 1000 = 2.8.

  • Valid counts: ceil(2800 / 1050) = 3 > floor(2800 / 950) = 2, so no count keeps the period within the range.

  • Candidates: the boundary counts 3 and 2.

  • n = 3: period 2800 / 3 = 933.3 ms, error abs(933.3 - 1000) = 66.7 ms.

  • n = 2: period 2800 / 2 = 1400 ms, error abs(1400 - 1000) = 400 ms.

  • Returns OptimalPeriod(933, 3, False): n = 3 has the smaller error and 2800 // 3 = 933, outside the range but the closest achievable.

Complexity:

  • - Time – O(1), constant-time arithmetic over at most two candidates.

  • - Space – O(1), a fixed number of local variables.

resample(*, actor: ActorId, records: Sequence[PositionInfoRecord], max_point_number: int) → list[PositionInfo][source]

Resample time-ordered positions on the output period grid.

Fewer than RESAMPLE_POINT_NUMBER_MIN positions, or positions whose every interval is already within [output period min, output period max], are returned as-is. Otherwise the grid is first time + floor(i * span / n), for i in [0, n], with n chosen by optimal_period over the whole span (interpolation_timestamps for the inner points, so a non-ideal period is logged as a warning): a longer input period is interpolated, a shorter one decimated. A grid time equal to an input time keeps that real position (an input period that divides the output one is a pure decimation); the other grid times become estimated positions from the spline fitted on every input position (interpolate). The first position is returned unchanged; the speed/heading of every following position, real or estimated, is recomputed from the displacement from the previous grid point (_build_chain_positions). The output is truncated to max_point_number positions, with a warning.

Parameters:

  • actor (ActorId) – The actor identifier, used for logging.

  • records (Sequence[PositionInfoRecord]) – Positions with their parsed time, in strictly increasing time order; the first one is the template of the estimated positions (stationInfo, objectId, position type).

  • max_point_number (int) – Maximum number of returned positions.

Returns:

The positions at the output period, first and last

grid times on the first and last input positions (before truncation).

Return type:

list[PositionInfo]

Raises:

ValueError – If the record times are not strictly increasing.

Complexity:

  • - Time – O(n + k*log(n)), O(n) input arrays, O(k*log(n)) grid matching (numpy.searchsorted) and interpolate.

  • - Space – O(n + k), the input and grid arrays plus the k returned positions.

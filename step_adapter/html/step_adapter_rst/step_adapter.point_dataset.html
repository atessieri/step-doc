step_adapter.point_dataset module

Position dataset management with Hermite interpolation.

Processes raw, irregularly-timed position measurements (e.g. GNSS fixes from CAM messages) into smooth, regularly-sampled trajectories, using Hermite interpolation of latitude and longitude and linear interpolation of the altitude between real measurements (step_cloud_schemas.GapFiller.fill).

Main components:

  • PointDatasetConfig: immutable, validated processing parameters (queue size bounds, period/deviation limits, output period); the resampling ones are validated by the GapFillerConfig it builds.

  • PointDataset: per-actor dataset manager. Checks each incoming position against the coherence rules, then either appends it directly (consecutive positions close to the nominal output period), has its GapFiller generate interpolated positions to fill the gap (larger temporal gaps), rejects it, or clears the history and restarts the trajectory from it.

Coherence rules:

PointDataset._COHERENCE_RULES binds every check of a new position to the action taken when it fails (CoherenceRule); the checks run in order and the first failure decides the action of PointDataset.add_point, so the order is also the precedence:

  1. Local time (REJECT): the position time must be within input_max_local_time_deviation_ms of the local clock. The reference is the clock, not the history, so the new position is wrong; being first, a stale or future-dated position never clears the history.

  2. Minimum period (REJECT): a position too close to, or not following, the last one is a downsampling or an out-of-order message. A last position in the future can be ahead by at most the local time deviation, so such a block ends by itself.

  3. Maximum period (RESTART): a gap above input_max_period_ms makes neither position wrong, but interpolating across it is not meaningful.

  4. Speed against a confirmed history (REJECT): with at least PointDataset.CONFIRMED_HISTORY_POINT_NUMBER_MIN positions, each one coherent in speed with the previous, the trajectory confirms itself, so a speed above PointDataset.SPEED_COHERENCE_THRESHOLD points at the new position (e.g. an isolated GNSS jump), which is discarded and never published.

  5. Speed against a single position (RESTART): nothing confirms the last position, so the trajectory restarts from the new one.

A wrong history recovers by itself: rejected positions do not update the last time, so within input_max_period_ms the maximum period rule restarts the trajectory; the worst case is an output gap of that length for the actor.

Let:

  • n = input_max_point_number, the input queue size (5-30).

  • k = number of interpolated positions generated by one insertion, bounded by input_max_period_ms / (output nominal period - output deviation).

Thread Safety:

This module is NOT thread-safe. Concurrent access requires external synchronization (e.g. one PointDataset per thread per actor, or a lock around a shared instance).

Note

A restart clears the history rather than interpolating across a likely discontinuity, which may produce temporary output gaps; downstream consumers needing continuous output should buffer accordingly.

Complexity:

  • - Time – O(n + k), dominated by PointDataset.add_point: O(k) on the interpolation path (one Hermite segment between the last and the new position), O(n) on a restart (history cleared).

  • - Space – O(n + k), dominated by PointDataset: history queue of n records plus the k + 1 output positions of the interpolation path.

Classes:

  • PointDatasetConfig: Validated, immutable processing parameters. Complexity: time O(1), space O(1).

  • InsertPointResult: Outcome of a coherence check of a new position. Complexity: time O(1), space O(1).

  • CoherenceAction: Action taken on a new position after its checks. Complexity: time O(1), space O(1).

  • CoherenceCheck: Coherence result with its action and the reusable distance/heading. Complexity: time O(1), space O(1).

  • CoherenceInput: Positions a coherence check works on. Complexity: time O(1), space O(1).

  • CoherenceRule: A coherence check bound to the action of its failure. Complexity: time O(1), space O(1).

  • PointDataset: Per-actor position dataset with Hermite interpolation. Complexity: time O(n + k), space O(n + k).

class step_adapter.point_dataset.PointDataset(actor_par: ActorId, config: PointDatasetConfig, logger: Logger)[source]

Bases: object

Per-actor position dataset with Hermite interpolation.

Maintains a bounded history of recent position measurements for a single actor (a deque of at most n PositionInfoRecord) and, on each add_point() call, either appends the new position directly (consecutive positions close to the nominal output period) or has its GapFiller fill the gap with interpolated positions (larger gaps). Every new position is checked against _COHERENCE_RULES (see the module overview): the first failed rule rejects the position or clears the history and restarts the trajectory from it. Speed and heading of the returned positions are recomputed from the geodesic displacement, except a real position after a filled gap reporting both, returned unchanged by GapFiller.fill. Below GapFiller.HEADING_SPEED_MIN_M_S the heading of the displacement is noise and the last output heading is held instead.

actor_par

The actor identifier for this dataset instance.

Type:

ActorId

config

Configuration object containing dataset parameters including input_max_point_number for queue sizing.

Type:

PointDatasetConfig

logger

Logger instance for recording events and debugging information.

Type:

Logger

Thread Safety:

This class is NOT thread-safe. Concurrent access from multiple threads requires external synchronization (e.g. one instance per thread per actor).

Example

>>> config = PointDatasetConfig(
...     input_max_point_number=20,
...     input_min_altitude_trailing_point_percent=25,
...     input_max_period_ms=2000,
...     input_max_local_time_deviation_ms=5000,
...     output_nominal_period_ms=200,  # 5 Hz
...     output_max_period_deviation_ms=20,
... )
>>> from datetime import UTC, datetime
>>> from step_cloud_schemas import ItsTime
>>> now = str(ItsTime.create_from_datetime(datetime.now(tz=UTC)))
>>> position_info = PositionInfo.model_validate(
...     obj=PositionInfo.get_default().model_dump() | {"time": now}
... )
>>> actor_id = ActorId(
...     station_id=position_info.stationInfo.stationId,
...     object_id=position_info.objectId,
... )
>>> dataset = PointDataset(
...     actor_par=actor_id, config=config, logger=logging.getLogger(__name__)
... )
>>> result = dataset.add_point(new_position=position_info)
>>> result == [position_info]  # the first position is returned as-is
True

Note

Interpolation quality depends on the speed and heading reported with the two positions bounding a gap: the Hermite tangents fall back to the chord when they are missing or unreliable (see GapFiller.fill).

  • - Time – O(n + k), driven by add_point: O(k) on the interpolation path (see GapFiller.fill), O(n) on a restart.

  • - Space – O(n + k), the O(n) history queue plus the O(k) output of the interpolation path.

add_point(new_position: PositionInfo) → list[PositionInfo] | None[source]

Validate and add a new position to the actor trajectory.

Rejects positions belonging to a different actor. Otherwise runs the coherence rules (_check_position_coherence, _COHERENCE_RULES) and takes the action they return:

  • ACCEPT: the first position is appended as-is; subsequent positions are delegated to _create_positions_list, which either appends directly or fills the gap with interpolated positions.

  • RESTART (a gap exceeding input_max_period_ms, or an implied speed above SPEED_COHERENCE_THRESHOLD against a single, unconfirmed position): the history is cleared and the trajectory restarts from the new position.

  • REJECT (not coherent with the local time, checked first, arriving too soon after the last position, or an implied speed above SPEED_COHERENCE_THRESHOLD against a confirmed history): the position is discarded (None) and the history is kept.

Parameters:

new_position (PositionInfo) – Position measurement, including coordinates and an ISO 8601 timestamp.

Returns:

  • None: actor mismatch or REJECT.

  • Single-element list: first position, RESTART, or no interpolation needed.

  • k+1-element list: k interpolated positions (POSITION_*_ESTIMATED) followed by the real position.

Return type:

list[PositionInfo] | None

Raises:

StepAdapterError – If internal state is inconsistent (detected by _create_positions_list).

Note

Not thread-safe; external synchronization is required for concurrent access. Debug logs are emitted for first positions/restarts, warnings for validation failures - consider log volume in high-throughput scenarios.

Complexity:

  • - Time – O(k) on the interpolation path (see _create_positions_list); O(n) on a restart; O(1) for a rejection, the first position or the fast path.

  • - Space – O(k) on the interpolation path; O(1) otherwise.

step_adapter.point_dataset module

Position dataset management with cubic spline interpolation.

Processes raw, irregularly-timed position measurements (e.g. GNSS fixes from CAM messages) into smooth, regularly-sampled trajectories, using cubic spline interpolation between real measurements.

Two components:

  • PointDatasetConfig: immutable, validated processing parameters (queue size bounds, period/deviation limits, output frequency).

  • PointDataset: per-actor dataset manager. Validates each incoming position for temporal/spatial coherence, then either appends it directly (consecutive positions close to the nominal output period) or generates interpolated positions to fill the gap (larger temporal gaps). Large gaps beyond input_max_period_ms clear the history instead of interpolating across a likely discontinuity.

Complexity is documented per-method; broadly, add_point is O(1) for the common case (no interpolation needed) and O(n + k) when interpolating, where n is the input queue size and k is the number of generated output points - both bounded by configuration.

Thread Safety:

This module is NOT thread-safe. Concurrent access requires external synchronization (e.g. one PointDataset per thread per actor, or a lock around a shared instance).

Note

Large temporal gaps exceeding input_max_period_ms clear history rather than interpolate across a likely discontinuity, which may produce temporary output gaps; downstream consumers needing continuous output should buffer accordingly.

Vectorized geodesic and motion arrays for one interpolation chain.

The chain is: last queued position -> interpolated point 0 -> … -> interpolated point k-1 -> new real position, i.e. k+1 consecutive pairs. Row i (for i in [0, k]) holds the values for the pair ending at chain point i, so row k is the motion into the trailing real position.

class step_adapter.point_dataset.PointDataset(actor_par: ActorId, config: PointDatasetConfig, logger: Logger)[source]

Bases: object

Per-actor position dataset with cubic spline interpolation.

Maintains a bounded history of recent position measurements for a single actor and, on each add_point() call, either appends the new position directly (consecutive positions close to the nominal output period) or fills the gap with cubic-spline-interpolated positions (larger gaps). Large temporal gaps or coherence failures trigger a history reset instead of interpolating across a likely discontinuity.

actor_par

The actor identifier for this dataset instance.

Type:

ActorId

config

Configuration object containing dataset parameters including input_max_point_number for queue and array sizing.

Type:

PointDatasetConfig

logger

Logger instance for recording events and debugging information.

Type:

Logger

Complexity is documented per-method; see add_point and _create_positions_list for the two execution paths.

Thread Safety:

This class is NOT thread-safe. Concurrent access from multiple threads requires external synchronization (e.g. one instance per thread per actor).

Example

>>> config = PointDatasetConfig(
...     input_max_point_number=20,
...     input_max_period_ms=2000,
...     input_max_local_time_deviation_ms=5000,
...     output_nominal_period_ms=200,  # 5 Hz
...     output_max_period_deviation_ms=20,
... )
>>> dataset = PointDataset(actor_par=actor_id, config=config, logger=logger)
>>> result = dataset.add_point(
...     new_position=position_info,
...     vehicle_length=vehicle_length,
...     vehicle_width=vehicle_width,
... )
>>> if result is not None:
...     for pos in result:
...         print(
...             f"{pos.time}: ({pos.position.latitude}, {pos.position.longitude})"
...         )

Note

Interpolation quality depends on input point density and temporal distribution; a minimum of 2 points is required (handled automatically), and insufficient coverage may cause extrapolation artifacts (mitigated by extrapolate=False in spline evaluation).

add_point(new_position: PositionInfo, vehicle_length: VehicleLength | None, vehicle_width: int | None) → list[PositionInfo] | None[source]

Validate and add a new position, updating actor dimensions and trajectory.

Rejects positions belonging to a different actor (returns None) or arriving too quickly per _check_position_coherence (returns None). Otherwise: the first position (or the one right after a history reset) is appended as-is; subsequent positions are delegated to _create_positions_list, which either appends directly or fills the gap with interpolated positions. A gap exceeding input_max_period_ms, or a coherence failure, clears history and restarts the trajectory.

Vehicle dimensions (vehicle_length/vehicle_width) are updated on any accepted position (first, reset, or normal) when provided; a None value preserves the existing dimension.

Time complexity:

O(1) for the common case (rejection, first position, or fast-path append). O(n + k) when interpolating, where n is the input queue size and k is the number of generated points (see _create_positions_list). O(m) when resetting history, where m is the current queue length.

Space complexity:

O(1) for the common case; O(n + k) when interpolating.

Parameters:

  • new_position (PositionInfo) – Position measurement, including coordinates and an ISO 8601 timestamp.

  • vehicle_length (Optional[VehicleLength]) – Actor length; None preserves the existing value.

  • vehicle_width (Optional[int]) – Actor width in centimeters; None preserves the existing value.

Returns:

  • None: actor mismatch or coherence rejection (period too short or not locally time-coherent).

  • Single-element list: first position, history reset, or no interpolation needed.

  • k+1-element list: k interpolated positions (POSITION_*_ESTIMATED) followed by the real position.

Return type:

Optional[list[PositionInfo]]

Raises:

StepAdapterError – If internal state is inconsistent (e.g. an unhandled InsertPointResult, or a missing empty queue during interpolation).

Note

Not thread-safe; external synchronization is required for concurrent access. Debug logs are emitted for first positions/resets, warnings for validation failures - consider log volume in high-throughput scenarios.

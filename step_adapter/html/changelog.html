Changelog

All notable changes to step_adapter are documented in this file.

1.2.2 - 2026-11-11

1.2.2 - Changed

  • GapFiller (with GapFillerConfig, ChainMotion, InterpolatedArrays, MotionValues and OptimalPeriod) moved to step_cloud_schemas (step_cloud_schemas.gnss) and imported from there; the dependency on step_cloud_schemas is raised to >=3.6.2.

  • CAM gap filling: the altitude is interpolated linearly between the two positions, and PointDataset.add_point runs one Hermite segment between the last queued and the new position, so the interpolation path costs O(k) instead of O(n + k*log(n)); complexity notes updated accordingly.

  • A real position after a filled gap keeps its reported speed and heading when it has both, instead of having them recomputed from the displacement.

  • On the fast path, below GapFiller.HEADING_SPEED_MIN_M_S the last output heading is held instead of the noisy displacement heading.

  • CPM: the points interpolated between the predicted ones are typed POSITION_PERCEIVED_PREDICTED, like the predicted path.

  • Example Redis configuration: consumer group renamed to stepAdapterGroupServer.

  • Dependency floors bumped (pytest-asyncio, ruff, tox, tox-uv, types-docutils, myst-parser, regex), also in tox.ini; uv.lock refreshed.

  • README and Sphinx pages (architecture, index, usage, find_period) updated to describe the step_cloud_schemas.GapFiller.

1.2.2 - Removed

  • step_adapter.gap_filler module, its tests and its API pages.

  • Direct numpy, scipy and scipy-stubs dependencies.

  • The pre-allocated numpy buffers of PointDataset and PointDataset._populate_input_arrays.

  • doc/source/spline_cubic.rst, doc/source/spline_hermite.rst and doc/spline_cubic/note_spline.pdf (now documented in step_cloud_schemas).

  • create_env.bat and create_env.sh.

1.2.1 - 2026-11-05

1.2.1 - Fixed

  • GapFiller.resample: positions already at the output period now get their speed and heading recomputed after the first one, like the resampled ones, instead of being returned as-is.

  • GapFiller.resample: only the grid points within the maximum number of points are generated, so the cost no longer depends on the span of the input.

  • GapFiller._build_chain_positions: a chain holding only its origin returns no position and makes no geodesic call.

  • GitLab CI: tests run on the Python of the Docker image (TOX_UV_PYTHON_PREFERENCE=system), without downloading another one.

  • tox.ini: runner, package, uv_python_preference and parallel_show_output moved from [tox] to [testenv], and skip_install replaced by package = skip.

  • Sphinx conf.py: the test directory is resolved from its path, without importing the test package.

1.2.1 - Added

  • inputMaxCpmSpan configuration parameter (1-120 s), required: the path of a CPM perceived object is cut this many seconds after its measured position, with a warning. Existing configuration files must add it.

  • doc/source/spline_hermite.rst page, changelog page generated from CHANGELOG.md and the cpm_data_v1_schema and cpm_message schema pages.

  • Pyrefly type checking (strict preset) in the lint environment, with its badge; new pyrefly and scipy-stubs dev dependencies.

  • Unit tests for the Hermite interpolation, the CPM span and the skipped objects.

1.2.1 - Changed

  • CAM gap filling (GapFiller.fill): latitude and longitude now follow a Hermite segment built on the reported speed and heading (CubicHermiteSpline), falling back to the chord when the speed or heading is missing, the speed is below 0.5 m/s or more than 3 times the chord speed. The altitude and the CPM positions keep the cubic spline.

  • ObjectPerceivedDataset: an object whose kept points span less than the minimum output period is skipped with a warning.

  • Dependencies: step_cloud_schemas>=3.4.3,<4.0, updated pydantic and the dev tools; uv>=0.13.7, ruff required-version>=0.17.3.

  • Documentation (README, architecture, usage, index, cubic spline) and docstring complexity figures aligned with the code.

1.2.0 - 2026-10-26

1.2.0 - Added

  • step_adapter_app module: StepAdapterApp, a ReconnectingApp run by AppRunner, reading the Redis credential from the environment and running the stream listener, the actor dataset cleaner and the Redis health check in a TaskGroup, reconnecting after reconnectInterval seconds on Redis failures.

  • object_perceived_dataset module: ObjectPerceivedDataset converts each perceived object of a CPM message into a PositionArrayV1 resampled at the output period.

  • gap_filler module: GapFiller/GapFillerConfig, cubic spline resampling shared by the CAM (streaming fill) and CPM (batch resample) datasets.

  • numeric_bounds module: single source of the MIN/MAX bounds shared by the JSON configuration, PointDatasetConfig and GapFillerConfig.

  • PointDataset coherence rules (CoherenceAction, CoherenceCheck, CoherenceInput, CoherenceRule): local time, minimum/maximum period and speed checks deciding whether a new position is appended, rejected or restarts the trajectory.

  • minActorHistoryAltitudeTrailingPointPercent and Redis retryCount configuration parameters.

  • Root __all__ exporting the whole public API, py.typed marker.

  • client_demo_app example (ClientDemoApp), new unit tests for the new modules and StepCliError/StepAdapterError, coverage and docstring coverage reports, .env.example and .gitattributes.

1.2.0 - Changed

  • __main__ reduced to the command-line entry point; the service workload moved to StepAdapterApp.

  • Redis host, port, username and password are read from the environment instead of the JSON configuration; receiveClientNumber removed.

  • ActorDataset, PointDataset and StepAdapterConfig refactored around GapFiller and numeric_bounds; configuration bounds expressed as MIN/MAX constant pairs.

  • Dependencies: step_cloud_schemas>=3.4.2,<4.0, step_redis>=1.6.5,<2.0, new sortedcontainers-stubs, pytest-timeout, myst-parser and sphinx-reports, updated numpy, pydantic, scipy and the dev/doc tools; uv>=0.13.5.

  • Stricter mypy (disallow_untyped_defs, disallow_subclassing_any), 100 % coverage gate, pytest timeout, doctest run in the lint environment.

  • GitLab CI: tag-only workflow rule, shallow fetch, per-Python cache and JUnit reports, serialized and retried step_doc push.

  • Documentation (README, architecture, usage, commands, find period, cubic spline) rewritten for the new architecture.

1.2.0 - Removed

  • sphinx_prompt_css.css and the step_adapter.__main__ API page.

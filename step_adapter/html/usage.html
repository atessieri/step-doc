STEP Adapter Usage Guide

Introduction

The STEP Adapter is a component of the STEP (Safer Transport for Europe Platform) ecosystem that converts ITS messages into position arrays for the Crash Prediction algorithms. This Redis-based microservice reads CAM (Cooperative Awareness Messages) and CPM (Collective Perception Messages) from a Redis input stream, converts them into PositionArrayV1 messages and publishes them to the crash prediction Redis stream.

Core Functionality:

  • CAM Processing: Keeps a short position history per sender, validates every new position against the previous one and fills the gaps with positions interpolated by a Hermite segment at the configured output frequency

  • CPM Processing: Converts every perceived object into one position array, from its measured position and its predicted path resampled at the configured output frequency

  • Real-time Stream Processing: Integrates with Redis Streams for message reception and Crash Prediction data distribution

  • Actor Dataset Management: Removes the senders without recent positions periodically

Key Components:

  • ActorDataset / PointDataset: Per-actor position history with coherence checks; the gaps are filled by GapFiller

  • GapFiller (from step_cloud_schemas): Output period resampling shared by CAM and CPM (Hermite and cubic spline interpolation and decimation)

  • ObjectPerceivedDataset: Conversion of CPM perceived objects, resampled at the output frequency

  • StepAdapterApp: Reconnecting service running the stream receive, cleaner and Redis health check tasks

  • Configuration System: Pydantic-based configuration models with strict validation

See Architecture for the details.

Prerequisites

Before using the STEP Adapter, make sure you have:

  1. Python 3.13 or higher installed

  2. A Redis server for stream processing

  3. The step_adapter package installed in your environment

Installation

You can install the STEP Adapter package using pip:

$pip install --extra-index-url https://gitlab.automotive.vodafone.com/api/v4/projects/1138/packages/pypi/simple step_adapter

Or if you’re using a development version:

pip install -e /path/to/step_adapter

Basic Concepts

STEP Adapter consumes CAM and CPM messages published by step_client on a Redis input stream and publishes the resulting position arrays to the crash prediction Redis stream. Key concepts include:

  • Actor: A CAM sender, identified by its station id (ActorId); each actor has its own history of at most maxActorHistoryPointNumber positions

  • Coherence Checks: A position too close in time to the previous one, or too far from the local time, is discarded; a gap longer than inputMaxPeriod restarts the history of the actor; an implied speed above 120 m/s restarts it against a single position and discards the new position against a confirmed history of at least two positions

  • Interpolation: When the gap from the previous position exceeds the output period plus outputPeriodMaxDeviation, the gap is filled with positions interpolated by a Hermite segment (see Finding the Optimal Interpolation Period), the altitude on a straight line; the received position is always the last point of the array

  • Perceived Objects: Every perceived object of a CPM becomes one position array with its measured position and predicted path, put on the output period grid: a longer CPM period is interpolated, a shorter one decimated (at most 101 points); no history is kept. The path beyond inputMaxCpmSpan is discarded, and an object whose kept points span less than the minimum output period is not forwarded

  • Periodic Cleanup: Every cleanerInterval seconds, the actors whose last position is older than inputOldestAllowedTime are removed

  • Signal Handling: Graceful shutdown on SIGINT/SIGTERM (CTRL_C/CTRL_BREAK on Windows), exit code 3 (ABORTED)

  • Automatic Reconnection: A Redis error ends the current connection cycle and a new one starts after reconnectInterval seconds, with empty actor histories (a message that cannot be converted is only logged and skipped); an error a reconnect cannot fix ends the program with exit code 2 (ERROR)

Environment Variables

The Redis connection settings (database, timeouts, keepalive, SSL, pool) are kept in the JSON configuration file, in the redis.connection section (step_redis RedisConnection), while the Redis host, port and credentials are read from the environment, so that secrets are never written to the configuration file:

Variable

Required

Description

REDIS_URL

yes

Redis server host name or IP address, without protocol or port

REDIS_PORT

yes

Redis server port (1-65535); usually 6380 with TLS (redis.connection.sslEnable true), 6379 without

REDIS_USERNAME

no

ACL username, when the server requires authentication

REDIS_PASSWORD

no

Password, when the server requires authentication

The StepAdapterApp constructor reads them once, through step_redis RedisCredential.from_env, before the first connection cycle. A missing REDIS_URL or REDIS_PORT, a non-integer or out-of-range port, or an empty host raise ValueError: since the credential is read outside the reconnect loop, a misconfiguration stops the program with exit code 2 (ERROR) instead of being retried forever.

How RedisCredential.from_env reads them.

  • It first loads the .env file found in the current working directory or in its nearest parent directory (find_dotenv(usecwd=True)): what counts is the directory step_adapter is launched from, not the directory of the installed package. Without a .env file only the environment is read.

  • A variable already set in the environment wins over the .env file: load_dotenv adds the missing variables and never overrides an existing one.

  • An empty REDIS_USERNAME or REDIS_PASSWORD counts as unset: without a username, authentication uses the default user, and without both no authentication is performed.

  • The host and port are logged at INFO level, together with whether a username is set; the username and the password never are.

Format of the .env file.

  • One KEY=VALUE line per variable, no export needed;

  • # starts a comment;

  • quote a value only if it contains spaces or # (REDIS_PASSWORD="a #b");

  • keep the file out of version control: list .env in .gitignore, only the .env.example template is versioned.

Template. doc/source/env/.env.example is a commented template:

# Template of the ".env" with the Redis host, port and credentials of step_adapter.
# Copy it to ".env" (git-ignored) in the directory the application is launched
# from (doc/examples for the client_demo package), or in one of its parent directories.
# RedisCredential.from_env (step_redis) reads it at start-up; a variable already
# set in the environment (shell, container) takes precedence over the value in
# ".env".

# Host name or IP address of the Redis server. Required.
REDIS_URL=redis.example.com

# TCP port of the Redis server (1-65535). Required. Usually 6380 with TLS
# (redis.connection.sslEnable true), 6379 without.
REDIS_PORT=6380

# ACL username. Optional: unset or empty authenticates as the "default" user
# (or not at all when the password is unset or empty too).
REDIS_USERNAME=my_user

# Password. Optional: unset or empty when the server requires no
# authentication.
REDIS_PASSWORD=my_secret

Download the template: .env.example (save it as .env). For the client_demo, copy it to doc/examples, the directory the demo is launched from:

cp doc/source/env/.env.example doc/examples/.env

Copy-Item doc/source/env/.env.example doc/examples/.env

Alternatives to the file. Variables set in the shell or by a container runtime take precedence over .env:

export REDIS_URL=redis.example.com
export REDIS_PORT=6380

$env:REDIS_URL = "redis.example.com"
$env:REDIS_PORT = "6380"

services:
  step_adapter:
    env_file: .env          # or, one by one:
    environment:
      REDIS_URL: redis.example.com
      REDIS_PORT: "6380"

Note

Credentials that the server rejects, an ACL denial, a missing SSL file or an untrusted certificate are classified by step_redis as StepRedisFatalError: the program ends with exit code 2 (ERROR) instead of reconnecting.

Configuration

STEP Adapter requires configuration for the actor history, the interpolation, the Redis connection and streams, and the logging. The configuration is managed through a JSON file.

Creating a Configuration File

To create a default configuration template:

step_adapter --conf_template ./config

This writes step_adapter_config_v1_schema_template.json into the ./config directory (created if missing), a template that you can customize for your specific needs.

Key Configuration Parameters

  • Base Configuration:

    • templateVersion: Configuration format version, only "1"

    • maxActorHistoryPointNumber: Maximum number of points in the history of an actor (5-30)

    • minActorHistoryAltitudeTrailingPointPercent: Minimum trailing run of points with altitude, as a percentage of the history points (or of the points of a CPM perceived object), needed to interpolate the altitude when some points lack it (0-100, at least 4 points)

    • inputMaxPeriod: Maximum period in milliseconds between two positions of an actor (1000-4000)

    • inputLocalTimeMaxDeviation: Maximum deviation in seconds between the position time and the local time (0-30)

    • inputOldestAllowedTime: Maximum age in seconds of the last position of an actor before it is removed (0-30)

    • inputMaxCpmSpan: Maximum time span in seconds of the path of a CPM perceived object, starting from its measured position; the part of the path beyond it is discarded (1-120)

    • outputNominalSampleFrequency: Output frequency in Hz of the CAM and CPM position arrays: 1, 2, 5 or 10

    • outputPeriodMaxDeviation: Maximum deviation in milliseconds from the output period (0-50)

    • cleanerInterval: Period in seconds of the actor cleanup (1-60)

    • reconnectInterval: Time in seconds between reconnection attempts (1-60)

  • Redis Configuration (redis):

    • connection: Database, timeouts, keepalive, SSL and pool settings; the host, port and credentials are read from the environment (see Environment Variables). socketTimeout must exceed the input waitTimeout by at least 5 seconds.

    • streams.input: Input stream id, consumer group id and receive wait timeout in milliseconds

    • streams.outputs.crashPrediction: Crash prediction output stream id and maximum length

  • Log Configuration (log):

    • globalLevel: Global logging level (e.g., DEBUG, INFO, WARNING, ERROR)

    • handlersConfig: List of log handlers (stream, file, rotating file, null), each with its own level, format and date format

The instance name is not part of the configuration: it is given with -i/--instance and is also used as the Redis stream consumer name.

Running STEP Adapter as a Service

To run the STEP Adapter as a standalone service:

step_adapter --instance adapter_1 --config /path/to/config.json

This will start the adapter, which will:

  1. Read the Redis host, port and credentials from the environment (see Environment Variables)

  2. Connect to Redis and create the input stream

  3. Convert the received CAM and CPM messages into position arrays

  4. Publish the position arrays to the crash prediction stream

  5. Remove the actors without recent positions every cleanerInterval seconds

Command-Line Options

The STEP Adapter supports several command-line options (see Command Line Interface):

  • --version, -v: Show version information

  • --help, -h: Show help information

  • --conf_schema, -s: Write the configuration JSON schema into a directory

  • --conf_template, -t: Write the configuration template into a directory

  • --config, -c: Path to configuration file (requires --instance)

  • --instance, -i: Specify the instance name (requires --config)

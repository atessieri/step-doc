======================
Command Line Interface
======================

Overview
========

The step_adapter command line interface (CLI) provides a way to interact 
with the STEP Adapter.

The CLI allows users to:

* View the program version
* Generate JSON schema documentation for configuration
* Create configuration templates
* Load and run the module with a specific configuration

Basic Usage
===========

.. code-block:: bash

    step_adapter [options]

If no options are provided, the program will display the help message.

Options
=======

The following command line options are available:

``-h, --help``
    Display the help message and exit.

``-v, --version``
    Show the program version and exit.

``-s, --conf_schema <schema directory>``
    Write the configuration JSON schema (``step_adapter_config_v1_schema.json``)
    into the specified directory, created if missing.

``-t, --conf_template <template directory>``
    Write a configuration template (``step_adapter_config_v1_schema_template.json``)
    into the specified directory, created if missing.

``-c, --config <config file>``
    Load the configuration from the specified file and run the module.

``-i, --instance <instance name>``
    Specify the instance name, also used as the Redis stream consumer name.

.. note::
    The ``-c``/``--config`` and ``-i``/``--instance`` options must be given together:
    when only one of them is present, the program logs a single error line (no
    traceback) and exits with code ``1`` (``USAGE``). The Redis host, port and
    credentials are not command line options: they are read from the environment
    (see :ref:`step_adapter_credentials`).

Detailed Command Description
============================

Help Command
------------

To display help information:

.. code-block:: bash

    step_adapter --help

This will output usage instructions and a list of available options.

Version Command
---------------

To display the program version:

.. code-block:: bash

    step_adapter --version

This will output the current version of the step_adapter.

Configuration Schema Generation
-------------------------------

To generate a JSON schema file documenting all configuration options:

.. code-block:: bash

    step_adapter --conf_schema /path/to/schema_dir

This command creates the JSON schema file ``step_adapter_config_v1_schema.json`` in the
specified directory. The file describes
all available configuration options, their types, defaults, and constraints. 
The schema can be used for validation or as a reference for creating custom configurations.

Configuration Template Generation
---------------------------------

To generate a configuration template file with default values:

.. code-block:: bash

    step_adapter --conf_template /path/to/template_dir

This command creates the JSON configuration file ``step_adapter_config_v1_schema_template.json``
with default values for all settings in the specified directory. Users can modify this file as needed to customize their configuration.

Running with Configuration
--------------------------

To run the module with a specific configuration:

.. code-block:: bash

    step_adapter --instance test --config /path/to/config_file.json

This loads the configuration from the specified file, reconfigures the logger from its
``log`` section, logs the program, ``step_cloud_schemas`` and ``step_redis`` versions and
starts the step_adapter. The module connects to the Redis streams specified in the
configuration, with the host, port and credentials read from the ``REDIS_*`` environment
variables or a ``.env`` file (see :ref:`step_adapter_credentials`).

Configuration File Structure
============================

The configuration file is a JSON document that defines the behavior of the step_adapter. 
It includes settings for:

* Module basic settings
* Redis client connection
* Redis streams
* Logging configuration

Exit Codes
==========

The program uses the following exit codes:

* ``0`` (OK): Successful termination, including ``-h``/``--help`` and ``-v``/``--version``
* ``1`` (USAGE): No arguments, an invalid or unknown option, or only one of
  ``-c``/``--config`` and ``-i``/``--instance``
* ``2`` (ERROR): General error during execution: an invalid configuration file, a missing
  ``REDIS_URL``/``REDIS_PORT`` variable, or a Redis error a reconnect cannot fix
  (``StepRedisFatalError``)
* ``3`` (ABORTED): Operation aborted by user or system (``SIGINT``/``SIGTERM``, Ctrl+C)

Examples
========

Generate a configuration schema:

.. code-block:: bash

    step_adapter --conf_schema ./schema

Create a configuration template:

.. code-block:: bash

    step_adapter --conf_template ./template

Run with specific configuration:

.. code-block:: bash

    step_adapter --instance test --config ./my_config.json

Generate both schema and template:

.. code-block:: bash

    step_adapter --conf_schema ./schema --conf_template ./template

Program Operation
=================

When running with a configuration file, the step_adapter
performs the following operations:

   #. Reads the Redis host, port and credentials from the environment (see
      :ref:`step_adapter_credentials`); a missing or invalid variable ends the program
      with exit code ``2``
   #. Runs connection cycles through ``AppRunner``; each cycle creates new, empty actor
      and perceived object datasets, opens a Redis connection pool and starts three
      asynchronous tasks:

      - **Stream Message Reception**: Listens to the Redis input stream for CAM
        (Cooperative Awareness Messages) and CPM (Collective Perception Messages); each CAM
        is added to the history of its sender, possibly with cubic spline interpolated
        positions, and each perceived object of a CPM becomes one position array resampled
        at the output frequency; every position array is published to the crash prediction
        stream
      - **Periodic Dataset Cleanup**: Every ``cleanerInterval`` seconds, removes the actors
        whose last position is older than ``inputOldestAllowedTime``
      - **Redis Health Check**: Periodically checks the Redis connection

   #. When a task fails, the cycle ends and a new one starts after ``reconnectInterval``
      seconds; an error a reconnect cannot fix (rejected credentials, ACL denial, missing
      SSL file, untrusted certificate) ends the program with exit code ``2``
   #. Manages graceful shutdown when interrupted, releasing the Redis connections

It will continue running until manually interrupted (e.g., with Ctrl+C) or until a
system signal is received.

Advanced Usage
==============

Signal Handling
---------------

Signal handling is owned by ``AppRunner`` (from ``step_cloud_schemas``, see
:doc:`architecture`): on ``SIGINT``/``SIGTERM`` (POSIX) or ``CTRL_C``/``CTRL_BREAK`` (Windows)
the running tasks are cancelled, the Redis pool and streams are released and the program
exits with code ``3`` (``ABORTED``).

Logging
-------

The step_adapter includes detailed logging capabilities. Log settings can be configured 
in the configuration file, including:

* Log level (DEBUG, INFO, WARNING, ERROR, CRITICAL)
* Console logging
* File logging with rotation options

At INFO level, the duration of each message handling and of each cleanup is logged.

You can enable debug logging to troubleshoot connection or message handling issues.

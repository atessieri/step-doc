STEP Adapter Config V1 Schema
=============================

The STEP Adapter Config Version 1 Schema defines a comprehensive configuration structure
for the STEP Adapter. This JSON Schema is automatically generated from Pydantic
models and provides strong typing, validation rules, and documentation.

Overview
--------

The STEP Adapter Configuration is organized hierarchically with the main ``StepAdapterConfig``
class containing several nested configuration components for different aspects of the system:

  * **Base Configuration**

      * ``templateVersion``: The version of the template (currently "1")
      * ``maxActorHistoryPointNumber``: The maximum number of points in the actor's history (5-30)
      * ``minActorHistoryAltitudeTrailingPointPercent``: The minimum trailing run of points with
        altitude, as a percentage of the history points (or of the points of a CPM perceived
        object), needed to interpolate the altitude (0-100)
      * ``inputMaxPeriod``: The maximum period between two positions of an actor (1000-4000 milliseconds)
      * ``inputLocalTimeMaxDeviation``: The maximum deviation of the position time from the local
        time (0-30 seconds)
      * ``inputOldestAllowedTime``: The maximum age of the last position of an actor before it is
        removed (0-30 seconds)
      * ``inputMaxCpmSpan``: The maximum time span of the path of a CPM perceived object, starting
        from its measured position; the part of the path beyond it is discarded (1-120 seconds)
      * ``outputNominalSampleFrequency``: The output frequency of the CAM and CPM position arrays
        (1, 2, 5 or 10 Hz)
      * ``outputPeriodMaxDeviation``: The maximum deviation from the output period (0-50 milliseconds)
      * ``cleanerInterval``: The interval for the cleaner task (1-60 seconds)
      * ``reconnectInterval``: Time between reconnection attempts (1-60 seconds)

  * **Redis Client Configuration**

      * Connection parameters (database, timeouts, keepalive, pool); the host, port and
        credentials are read from the environment (see :ref:`step_adapter_credentials`)
      * Security settings (SSL/TLS)
      * Input stream and crash prediction output stream

  * **Logging Configuration**

      * Log handlers
      * Log levels
      * Formatting options

Features and Benefits
---------------------

* **Type Validation**: Strong typing and constraints via Pydantic fields
* **Immutable Design**: Configuration is frozen after loading to prevent runtime errors
* **Comprehensive Documentation**: Detailed field descriptions and examples
* **Default Values**: Sensible defaults provided for all configuration options
* **Strict Validation**: Prevents configuration errors before they cause runtime issues

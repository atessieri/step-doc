step_client.step_client_app module

Workload of the STEP Client program.

Defines the ReconnectingApp subclass handed to AppRunner by step_client.__main__: it reads the MQTT credential (step_lib MqttCredential.from_env) and the Redis credential (step_redis RedisCredential.from_env) from the environment, then each connection cycle (cycle) opens a Redis connection pool and connects to the STEP MQTT broker, and runs three concurrent tasks in a TaskGroup: one forwarding CAM/CPM messages received from the STEP broker to the adapter Redis stream and DENM messages to the producer Redis stream, one forwarding DENM messages read from the input Redis stream to the STEP broker, and one running the Redis health check. Any failure tears the cycle down and the inherited work reconnects after reconnectInterval seconds; an error a reconnect cannot fix ends the run with ExitCode.ERROR, and a shutdown cancellation ends the loop instead. Delivery is at-most-once: a message being forwarded when a transport fails is logged and lost, because both the MQTT subscription and the Redis input stream (read without acknowledgement) have already acknowledged it.

Complexity:

  • - Time – O(n * m), where n is the number of ITS/Redis messages processed over the program’s lifetime and m the size (field count/byte length) of a message; each message is decoded, logged and re-serialized in O(m) time, and each connect/reconnect cycle performs O(t) setup work, t = number of configured MQTT subscription/publish topics.

  • - Space – O(t + m) per reconnect cycle, for the StepBroker topic configuration and the payload of the message being handled; the three concurrent tasks are fixed in number.

Classes:

  • ExitCode: Enumeration of the program exit codes. Complexity: time O(1), space O(1).

  • StepClientApp: Workload run by AppRunner: the reconnecting STEP broker/Redis stream bridge. Complexity: time O(n * m) over the program’s lifetime, space O(t + m).

class step_client.step_client_app.StepClientApp(instance_name: str, config: StepClientConfig, logger: Logger)[source]

Bases: ReconnectingApp[ExitCode]

Workload of the program, run by AppRunner: the reconnecting bridge between the STEP MQTT broker and the Redis streams.

Holds the state shared by every connection cycle: the instance name, the configuration and the MQTT and Redis credentials read once from the environment at construction. Each cycle opens a fresh Redis connection pool and StepBroker, subscribes to the configured topics and runs the STEP receive, Redis stream receive and Redis health check tasks until one of them fails; the inherited work then reconnects after reconnectInterval seconds, and an error that reconnecting cannot fix (_FATAL_ERRORS) ends the run with fatal_result (ExitCode.ERROR).

async cycle() → None[source]

Open the Redis pool and the STEP broker and run the bridge tasks.

Opens a StepRedisPool (at most _REDIS_MAX_CONNECTIONS connections, parameters from StepRedisPoolParams.from_connection) and a StepBroker, subscribes to the configured topics and runs _step_receive_run, _stream_receive_run and _redis_health_check_run in a TaskGroup. The first failure propagates to the inherited work, which reconnects or ends the run.

Returns:

Returns only if every task ends normally, which they never do.

None

Complexity:

  • - Time – O(t) for the StepBroker setup and topic subscription, t = number of configured subscription/publish topics, plus O(n * m) for the n messages of size m processed by the receive tasks.

  • - Space – O(t + m), for the StepBroker topic configuration and the message being handled by each task; the three tasks are fixed in number.

step_client package

STEP Client Package for ITS Message Communication.

This package provides functionality for communicating with the STEP (Safer Transport for Europe Platform) MQTT broker to receive and send ITS (Intelligent Transport Systems) messages. It serves as a client that interfaces between the STEP MQTT broker and Redis streams for message processing.

Goal:

The goal of the step_client project is to provide a reliable, secure bridge between the STEP MQTT broker and the Redis-based ITS message processing pipeline, so that downstream components can consume CAM, CPM, and DENM messages received from the STEP broker and publish DENM messages to it without managing MQTT connectivity, security, or protocol details directly.

The package handles:

  • Subscribing to MQTT topics to receive ITS messages from the STEP broker

  • Publishing DENM messages read from the Redis input stream to the STEP broker

  • Integrating with step_redis’s CloudEvents-format Redis stream conversion

  • Managing message queuing via Redis streams

  • Providing secure communication with SSL/TLS support

  • Configuration management for MQTT/Redis connection parameters (host, port and credentials come from the environment, see step_lib MqttCredential and step_redis RedisCredential)

Main components (all re-exported here):

  • StepBroker: Broker client class for MQTT communication with the STEP broker

  • StepClientApp: AppRunner workload bridging the STEP broker and Redis streams, with the ExitCode enum

  • StepClientConfig and its nested models: Configuration management for the client (the MQTT client and Redis connection models come from step_lib and step_redis)

  • StepClientError and subclasses: Custom exceptions for error handling

Note: the exported configuration model PublishTopicParams shares its name with step_lib.PublishTopicParams (the runtime publish-topic parameters it is converted into by StepBroker); import the one you need explicitly.

Redis stream/pool integration (step_redis), the application runner and logging (step_cloud_schemas.AppRunner/StepLogger) are used by step_client_app and __main__ but provided by those external libraries.

Modules:

  • step_client_config: Pydantic configuration models for the STEP client (MQTT client/protocol, Redis client/streams, logging) plus JSON schema/template generation.

  • step_broker: StepBroker client class for MQTT communication with the STEP broker, including topic subscription and ITS message publishing.

  • step_client_app: StepClientApp workload run by AppRunner, wiring the STEP broker to Redis streams with reconnect handling, plus the ExitCode enum.

  • step_exception: Exception hierarchy for STEP client errors (StepClientError, StepCliError).

  • __main__: CLI entry point: argument parsing, schema/template generation, configuration loading and the AppRunner launch of StepClientApp.

Example:

$step_client -i instance_name -c config.json
Complexity:

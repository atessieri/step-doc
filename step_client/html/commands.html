Command Line Interface

Overview

The step_client command line interface (CLI) provides a way to interact with the STEP (Safer Transport for Europe Platform) broker and ITS ETSI messages. It facilitates the exchange of messages between the STEP broker and Redis streams.

The CLI allows users to:

  • View the program version

  • Generate JSON schema documentation for configuration

  • Create configuration templates

  • Load and run the client with a specific configuration

Basic Usage

step_client [options]

If no options are provided, the program will display the help message.

Options

The following command line options are available:

-h, --help

Display the help message and exit.

-v, --version

Show the program version and exit.

-s, --conf_schema <schema dir>

Write the configuration JSON schema into the specified directory (created if missing).

-t, --conf_template <template dir>

Write a configuration template into the specified directory (created if missing).

-c, --config <config file>

Load the configuration from the specified file and run the client. Must be used together with -i/--instance.

-i, --instance <instance name>

Specify the instance name. Must be used together with -c/--config.

Detailed Command Description

Help Command

To display help information:

step_client --help

This will output usage instructions and a list of available options.

Version Command

To display the program version:

step_client --version

This will output the current version of the step_client.

Configuration Schema Generation

To generate a JSON schema file documenting all configuration options:

step_client --conf_schema /path/to/schema_dir

This command creates the directory if needed and writes step_client_config_v1_schema.json in it. The file describes all available configuration options, their types, examples, and constraints (every field is required). The schema can be used for validation or as a reference for creating custom configurations.

Configuration Template Generation

To generate a configuration template file with default values:

step_client --conf_template /path/to/template_dir

This command creates the directory if needed and writes step_client_config_v1_schema_template.json in it, a JSON configuration file with default values for all settings. Users can modify this file as needed to customize their configuration.

Running with Configuration

To run the client with a specific configuration:

step_client --config /path/to/config_file.json --instance my_instance

This loads the configuration from the specified file and starts the step_client. The client will connect to the STEP broker and Redis streams as specified in the configuration. The -i/--instance option is required whenever -c/--config is used.

Configuration File Structure

The configuration file is a JSON document that defines the behavior of the step_client. It includes settings for:

  • MQTT client connection

  • MQTT protocol options

  • Redis client connection

  • Redis streams

  • Logging configuration

  • Station ID and position (latitude/longitude)

  • Reconnection interval

The instance name is not part of the file; it is given with -i/--instance. The MQTT and Redis addresses and credentials are read from environment variables (MQTT_URL, MQTT_PORT, REDIS_URL, REDIS_PORT, and the optional *_USERNAME/*_PASSWORD), not from the file: see Environment Variables and the .env.example template.

For the STEP Client Configuration Schema with all configuration options, generate a schema file using the --conf_schema option.

Exit Codes

The program uses the following exit codes:

  • 0 (OK): Successful termination, including -h/--help and -v/--version

  • 1 (USAGE): No arguments given, an invalid or unknown option, or only one of -c/--config and -i/--instance

  • 2 (ERROR): General error during execution, including an invalid configuration file, a missing or invalid environment variable (MQTT_URL, MQTT_PORT, REDIS_URL, REDIS_PORT) and an error a reconnect cannot fix (rejected Redis or MQTT credentials, missing SSL file, untrusted certificate)

  • 3 (ABORTED): Operation aborted by user or system

Examples

Generate a configuration schema:

step_client --conf_schema ./schema

Create a configuration template:

step_client --conf_template ./template

Run with specific configuration:

step_client --config ./my_config.json --instance my_instance

Generate both schema and template:

step_client --conf_schema ./schema --conf_template ./template

Program Operation

When running with a configuration file, the step_client performs the following operations:

  1. Reads the MQTT and Redis credentials (MQTT_URL, MQTT_PORT, MQTT_USERNAME, MQTT_PASSWORD, REDIS_URL, REDIS_PORT, REDIS_USERNAME, REDIS_PASSWORD) from the environment (step_lib MqttCredential.from_env and step_redis RedisCredential.from_env), first loading the .env file found in the current working directory (or an ancestor of it), if any

  2. Connects to the Redis server using the provided connection settings

  3. Connects to the STEP broker using MQTT settings

  4. Subscribes to the specified MQTT topics

  5. Starts three asynchronous tasks:

    • One task listens for MQTT ITS ETSI messages from the STEP broker and publishes them to Redis streams

    • Another task listens for DENM messages on the Redis input stream and publishes them to the STEP broker

    • A third task runs a periodic Redis stream health check to keep the connection pool validated

  6. Automatically handles reconnection if connections are lost (using the specified reconnect interval); an error a reconnect cannot fix ends the program with code 2 (ERROR)

  7. Manages graceful shutdown when interrupted: AppRunner (from step_cloud_schemas) watches for a shutdown request (SIGINT/SIGTERM, or SIGINT/SIGBREAK on Windows), cancels the running tasks and exits with code 3 (ABORTED)

The client will continue running until manually interrupted (e.g., with Ctrl+C) or until a system signal is received.

Advanced Usage

Signal Handling

The step_client properly handles system signals for graceful shutdown. When a signal is received, it cleans up resources and terminates with the appropriate exit code.

Logging

The step_client includes detailed logging capabilities. Log settings can be configured in the configuration file, including:

  • Log level (DEBUG, INFO, WARNING, ERROR, CRITICAL)

  • Console logging

  • File logging with rotation options

You can enable debug logging to troubleshoot connection or message handling issues.

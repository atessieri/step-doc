STEP Client Usage Guide
=======================

Introduction
------------

STEP Client is a Python package designed to facilitate communication between 
the STEP (Safer Transport for Europe Platform) MQTT broker and Redis streams for 
ITS (Intelligent Transport Systems) message processing. This guide walks 
through the different ways to use the STEP Client, from basic configuration 
to advanced usage patterns.

Prerequisites
-------------

Before using the STEP Client, make sure you have:

    #. Python 3.13 or higher installed
    #. Access to a STEP MQTT broker
    #. A Redis server for stream processing (required)
    #. The step_client package installed in your environment

Installation
------------

You can install the STEP Client package using pip:

.. code-block:: bash

   $pip install --extra-index-url https://gitlab.automotive.vodafone.com/api/v4/projects/961/packages/pypi/simple step_client

Or if you're using a development version:

.. code-block:: bash

    pip install -e /path/to/step_client

Basic Concepts
--------------

STEP Client operates as a bridge between MQTT messaging and 
Redis streams, specifically designed for ITS message exchange. 
Key concepts include:

    * **StepBroker**: Gateway component that handles MQTT communication with the STEP broker
    * **StepClientConfig**: Configuration management for the client
    * **StepRedisPool/StepClientRedisStream**: Redis integration for message queuing
    * **ITS Messages**: Standard message formats like CAM (Cooperative Awareness Messages),
      DENM (Decentralized Environmental Notification Messages) and CPM (Collective Perception Messages)

Configuration
-------------

STEP Client requires configuration for both MQTT and Redis connections. The
configuration is managed through a JSON file, while the broker and Redis
addresses and credentials are read from environment variables.

Creating a Configuration File
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

To create a default configuration template:

.. code-block:: bash

    step_client --conf_template my_config_template_dir

This creates the directory (if missing) and writes
``step_client_config_v1_schema_template.json`` in it, a template that you can
customize for your specific needs.

Key Configuration Parameters
^^^^^^^^^^^^^^^^^^^^^^^^^^^^

* **MQTT Client Configuration** (config file, ``MqttClientConfig``):

  * sslEnable: Whether to use TLS/SSL encryption
  * sslClientCertFile / sslClientKeyFile / sslClientKeyFilePassword: Client certificate
    settings for mutual TLS
  * sslCaCertsFile: CA certificate bundle used to verify the broker
  * sslVerifyServerCert: Whether to verify the broker's certificate

* **MQTT Broker Connection** (environment variables, not the config file):

  * ``MQTT_URL``: MQTT broker hostname or IP (required)
  * ``MQTT_PORT``: MQTT broker port, e.g. 1883 for non-TLS, 8883 for TLS (required)
  * ``MQTT_USERNAME`` / ``MQTT_PASSWORD``: Authentication credentials (optional)

* **Redis Connection** (environment variables, not the config file):

  * ``REDIS_URL``: Redis server hostname or IP (required)
  * ``REDIS_PORT``: Redis server port (required)
  * ``REDIS_USERNAME`` / ``REDIS_PASSWORD``: Authentication credentials (optional)

* **MQTT Protocol Configuration**:
  
  * keepalive: Keep-alive interval in seconds
  * cleanStart: Whether to start with a clean session
  * subscriptionTopics: List of topics to subscribe to
  * publishTopics: Configuration for topics to publish to
  
* **Redis Configuration** (required):
  
  * connection: Redis server connection details
  * streams: Configuration for Redis streams (inputs and outputs)
  
* **General Configuration**:

  * stationId: Station identification number
  * latitude / longitude: Position of the station in degrees
  * reconnectInterval: Time in seconds between reconnection attempts

  The instance name is not part of the configuration file; it is supplied on the
  command line via ``-i/--instance`` (required together with ``-c/--config``).

Running STEP Client as a Service
--------------------------------

To run the STEP Client as a standalone service:

.. code-block:: bash

    step_client --config /path/to/config.json --instance my_instance

This will start the client, which will:

    #. Connect to the configured MQTT broker
    #. Subscribe to the specified topics
    #. Connect to Redis
    #. Process ITS messages between MQTT and Redis

Command-Line Options
--------------------

The STEP Client supports several command-line options:

    * ``--config``, ``-c``: Path to configuration file
    * ``--instance``, ``-i``: Instance name (required together with ``--config``)
    * ``--conf_schema``, ``-s``: Write the configuration JSON schema into a directory
    * ``--conf_template``, ``-t``: Generate a configuration template into a directory
    * ``--version``, ``-v``: Show version information
    * ``--help``, ``-h``: Show help information
